# ADR-0019: 开源核心、租户与独立商业产品边界

- 状态：已接受
- 日期：2026-09-26
- 适用仓库：两者

## 背景

Edgeweir 保留开源 CDN / WAF / 边缘调度核心，同时需要通过商业运营产品、官方扩展和服务支持持续开发。维护者已选择以下边界：组织、成员和内部协作开源；对外客户门户、套餐计费、财务和分销整体归入独立商业运营产品。

原始 BOOTSTRAP、ROADMAP 和 ADR-0007 把租户门户与计费列入平台 v1，但没有区分开源产品与商业产品。本 ADR 取代这些条目的产品归属；已实现的组织、成员、隔离与控制台能力不迁出、不加锁。BOOTSTRAP 保留为历史需求来源，当前范围以本 ADR 和更新后的 ROADMAP 为准。

本 ADR 补充 ADR-0018 对独立商业产品的适用范围：两个开源仓库的无官方回连、无商业授权校验、安全发布和数据保护原则继续生效。原 ADR 拒绝把开源核心改成联网授权产品的结论保持有效，不再解释为禁止开发独立商业服务。

## 决策

### 1. 许可证与合法用途

- 两个核心仓库保持标准 **AGPL-3.0-only**，许可证正文不改写，不附加“禁止商用”或“仅限个人”的条款；详见 [LICENSING.md](../../LICENSING.md)。
- 企业可以合规地使用开源核心经营服务，社区也可以按适用许可实现自己的门户或计费系统。产品分层不能变成对开源权利的限制。
- 独立原创商业代码另行约定许可；私有仓库不等于自动取得闭源权限。集成 AGPL 代码或第三方组件之前必须核实组合关系与代码权利；本次没有新增链接例外、贡献者授权协议或商业双许可。

### 2. 组织与商业客户是不同的概念

开源核心中的 `organization` 是资源归属和权限隔离单位，不等于收费账户、套餐订阅或分销商。现有 schema、RBAC、组织切换、邀请和后台用户管理继续保留。

未来商业运营产品拥有自己的客户、订阅、账单和结算记录，通过显式映射关联核心组织。一位客户与组织、订阅之间的关系需要单独设计，不能直接假设一一对应。核心表不承载官方购买资格或许可证状态。

| 能力 | 产品归属 |
| --- | --- |
| 组织、成员、邀请、角色、隔离、2FA、passkey、API 访问 | 开源核心 |
| 成员登录后管理自己组织的站点，平台管理员管理组织、用户和基础设施 | 开源核心；保留现有控制台和后台 |
| 节点、集群、缓存、证书、WAF / 规则引擎、调度、统计与审计 | 开源核心；实现进度仍以 ROADMAP 为准 |
| 资源用量采集、技术限额、限速、站点启停及公开管理接口 | 开源核心；商业产品可通过接口编排 |
| 营销落地页、登录页和邀请加入 | 开源核心；现有公开落地页不是商业客户门户 |
| 对外客户门户、自助开户购买、产品目录、套餐、价格、商业配额、流量包 | 独立商业运营产品 |
| 按流量 / 95 带宽计费、余额、充值、订单、支付、退款、对账与财务报表 | 独立商业运营产品 |
| 分销、代理商、佣金、结算、多级价格、白标运营、优惠券和欠费流程 | 独立商业运营产品 |
| 客户实名认证、业务工单、短信 / 微信支付等运营集成、高防 IP 售卖 | 独立商业运营产品；基础防护与调度仍开源 |
| 官方账户、订阅、许可证签发、插件目录与分发、支持服务 | 独立官方商业服务 |

“对外客户门户”指注册、购买、充值、账单、套餐和售后流程，不指现有成员管理站点的控制台。技术配额与商业套餐额度分别属于基础资源控制和销售规则，不把两者混成付费开关。

### 3. 产品与数据隔离

- 两个开源仓库不内置隐藏的商业实现或 `license.valid` 功能开关，不因官方订阅状态限制核心节点、组织、成员或站点数量。
- 独立商业运营产品负责“运营者向自己的客户收费”；官方商业服务负责“Edgeweir 向运营者销售软件、扩展与服务”。两套账户、支付密钥和账本不得混用。
- 商业集成优先通过版本化的公开管理 API 与显式事件接口，不直接读写核心数据库，不复用节点注册 token、节点私钥或内部 CA 身份。专用服务账号、细粒度 API scope 与事件接口仍需后续设计，不能假定当前 AccessKey 已提供全部所需能力。
- 商业产品需要联网激活、下载扩展或使用云服务时，在独立组件中明确说明目的地、发送字段、断网行为和数据权限，由管理员主动启用。核心与边缘节点不因此自动回连官方服务。
- 不把本轮文档变更视为闭源插件与 AGPL 集成的法律结论；独立进程和 API 是架构选择，闭源交付前仍须检查实际组合关系与许可。

### 4. 商业授权不能成为流量故障源

- 官方许可证到期、授权服务不可达或商业产品卸载，不得停用开源核心、清除配置、阻断已有 CDN 流量或基础防护。节点继续采用原有的 last-known-good 行为。
- 商业扩展自身的新功能、下载、更新和云服务可按明示合同处理到期；应提供宽限、续费和迁移路径。许可证校验不进入逐请求转发路径。
- 运营者按自己客户的合同执行欠费停用，是商业运营规则，通过正常管理接口提交可审计的配置；不得把“运营者的 Edgeweir 授权失效”伪装成“终端客户欠费”。
- 官方商业服务不要求上传节点私钥、站点证书私钥、DNS 凭据或 SSH 凭据，也不要求开放任意远程命令执行通道。

## 后果与本次落地

- 修改的是产品边界、许可说明与开发路线图；现有组织、成员、节点、登录和站点行为不变，不做数据库迁移。
- 现有两个仓库的 LICENSE 保留原文。README、SECURITY、CONTRIBUTING、ARCHITECTURE、CLAUDE 与 ROADMAP 引用一致的边界。
- 原 v1 租户门户、套餐计费、财务与分销条目移出开源核心路线图；用量、统计、权限隔离与资源控制继续留在核心。
- 商业运营产品和官方云端服务尚未创建或实现。收费金额、授权引擎、支付渠道、插件执行机制和商业合同均未由本 ADR 确定。

## 备选方案

- 把开源版限定为个人非商业使用：不符合保留真正开源核心的目标。
- 从当前开源核心移走组织、成员或租户隔离：破坏已有架构和使用体验。
- 将完整商业功能放进开源仓库再做本地许可证开关：不能形成可靠的源码保密边界，也与核心的信任原则冲突。
- 在节点数据面做联网授权和到期停机：把商业服务的故障扩散到客户流量。

## 许可依据

- [AGPL-3.0 原文](https://www.gnu.org/licenses/agpl.html)：使用、分发、源码及网络交互义务。
- [OSI 开源定义](https://opensource.org/osd)：开源许可不能排除商业用途。
- [GNU 关于插件与组合作品的说明](https://www.gnu.org/licenses/gpl-faq.html#GPLPlugins)：插件许可取决于实际结合方式，进程或仓库边界不是自动豁免。

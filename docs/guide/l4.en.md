# L4 forwarding

TCP / UDP port forwarding: port pools, L4 apps, port ranges, TLS termination, PROXY protocol, IP lists and limits, DNS, statistics, node requirements.

## Concepts

| Term | Definition |
| --- | --- |
| L4 app | Forwards TCP connections or UDP sessions on one port (or a range of ports) of every node of a cluster to its origins. |
| Port pool | A range of ports the cluster's L4 apps may use, per protocol (TCP, UDP, TCP + UDP). |
| Reserved port | A port of the cluster's HTTP / HTTPS listeners; never part of a port pool or an L4 app. |
| UDP session | The datagrams from one client address and port; one session until the idle timeout. |
| PROXY protocol | A header at the start of a connection that carries the client's address and port; v1 is text, v2 binary. |

## How it works

1. Port ranges are set on the cluster's **Port pools** tab; an L4 app's port must fall inside one.
2. Saving an L4 app publishes the cluster's configuration revision (through the [configuration canary](clusters.en.md#configuration-canary) as for sites; disabling and deleting reach every node at once); every node of the cluster listens on the port and forwards connections to the origins by weight.
3. With DNS steering on for the cluster, every enabled app has the CNAME target `<app's CNAME prefix>.<cluster domain>` (8 random characters for new apps, the UUID for apps from before the upgrade; regenerate or customize it on the app's page, see [CNAME prefixes](domains.en.md#cname-prefixes)), through which clients reach healthy nodes.
4. Nodes report per app and per minute the connections, refusals, peak concurrency, and bytes, shown on the app's **Analytics** tab.

Nodes need the capability `l4-v1`; port ranges, origins on the arriving port, and TLS termination also need `l4-v2`, see [Node requirements](#node-requirements).

## Set up port pools

1. Open **Clusters & nodes**, select the cluster, and switch to the **Port pools** tab.
2. Click **Add port pool**, select the **Protocol** (TCP, UDP, or TCP + UDP), and fill in **First port** and **Last port**. For a single port both are the same. **Remove** at the end of a row deletes it.
3. Click **Save** (available once something changed). The console shows **Saved**.
4. Open these ports per protocol in the node hosts' firewall and the cloud security group; container nodes also publish them, see [Add nodes](../deploy/nodes.en.md#ports-and-firewall).

**Reserved ports** at the top of the card lists the ports no pool may contain; without pools the card shows "No port pools yet". When the cluster has nodes without L4 support, the tab shows the warning from [Node requirements](#node-requirements).

| Item | Behavior |
| --- | --- |
| Ports | 1024–65535; the first port must not be above the last ("The first port must not be above the last", **Save** unavailable) |
| Count | At most 64 port pools per cluster |
| Overlap | Pools of one protocol must not overlap, and TCP + UDP overlaps both TCP and UDP ("Port pools overlap: {pools}"); the conflicting pools are marked |
| Reserved ports | 80, 443, the extra HTTP / HTTPS ports on the cluster's **Settings** tab, and the listener ports of the latest revision. A pool that contains one is refused ("Port {port} is used by the cluster's HTTP listeners") and marked; conversely, an extra listener port inside a pool is refused too ("Port {port} is inside port pools: {pools}") |
| Shrinking | Refused when the pools no longer contain the port or range of an app, disabled apps included ("Ports in use by {apps}") |
| Publishing | Port pools only check app ports: saving publishes no configuration revision, nodes are not affected |
| Unsaved | Leaving the page with unsaved changes asks first |
| Audit | `cluster.port_pools_update`, with the pools before and after as metadata |

## Create an L4 app

1. Open `/l4` (see [Pages and entry points](#pages-and-entry-points)) and click **New L4 app**. Without a cluster the button is unavailable with the hint "Create a cluster first"; without apps the list shows "No L4 apps yet".
2. Fill in **Name** (at most 100 characters); with several clusters, select the **Cluster** (the list's cluster filter by default, else the oldest cluster).
3. Select the **Protocol** (TCP or UDP) and fill in **Listen port**; for a range of ports also **Last port**. The hint "Port pools: {pools}" below lists the pools of that protocol and turns red when the port is outside them; when the cluster has none, the hint reads "The cluster has no TCP port pool" and **Set up port pools** opens the cluster's **Port pools** tab.
4. Under **Origins**, select the **Origin port** (**Fixed** or **Same as the port**), fill in **Origin**, **Port**, and **Weight**, and turn on **Backup** where needed; **Add origin** adds more, see [Origins and health checks](#origins-and-health-checks).
5. Set **PROXY protocol**, **TLS certificate**, **Timeouts**, **Passive health check**, **IP lists**, and **Limits per node** as needed.
6. **Enabled** is on by default. Click **Create**; the console shows "Created, revision #N".
7. Verify: the app appears in the list and **CNAME target** shows `<app's CNAME prefix>.<cluster domain>`; connect to the port on any node:

   ```bash
   nc -vz <node IP> 9000                      # TCP: the connection succeeds
   dig @<node IP> -p 5353 example.com +short  # UDP, here forwarding to a DNS origin
   ```

8. The app's **Analytics** tab starts showing connections (reported every minute, after about 1–2 minutes).

When nodes of the cluster lack `l4-v2`, **Last port**, **Origin port**, and **TLS certificate** are unavailable with the note "Some nodes in the cluster do not support it"; a range, origins on the arriving port, or a certificate the app already uses can still be changed. A refusal from the server shows under the field it concerns (port, origins, PROXY protocol, TLS certificate, IP lists), anything else at the bottom of the form.

## Origins and health checks

| Field | Values | Default | Effect |
| --- | --- | --- | --- |
| Origin (`address`) | Host name or IP, at most 253 characters | — | Follows the [origin address restrictions](origins-and-cache.en.md#origin-address-restrictions): special-purpose addresses only inside the origin allow list; nodes check every address a host name resolves to |
| Port (`port`) | 1–65535 | — | Origin port; may differ from the listen port. Empty with **Same as the port** under **Origin port** |
| Weight (`weight`) | 1–100 | 1 | Random choice by weight |
| Backup (`backup`) | On / off | Off | Used only while every primary origin is down |

An app has 1–32 origins, at least one of them not a backup ("Keep at least one origin that is not a backup"; **Create** / **Save** unavailable).

| Item | Behavior |
| --- | --- |
| Choice | Healthy primary origins at random by weight; when every primary is down, only healthy backups; when all are down, all of them in turn, primaries first |
| Retries | The next origin only after a failed connection to the origin (refused, timed out), at most 3 origins per connection; no switch once connected |
| Host names | Resolved by the resolver nodes use for sites; a failed resolution, or only refused addresses, counts as one failure |
| Saving | The origins are replaced as a whole; an origin with an unchanged address and port keeps its ID, and with it its passive health state on the nodes |

Passive health check and timeouts:

| Field | Values | Default | Effect |
| --- | --- | --- | --- |
| Passive health check · Failures before down (`maxFails`) | 1–100 | 3 | After this many failed connections (for UDP also an unreachable origin, such as ICMP port unreachable) the origin is taken out |
| Passive health check · Retry after (seconds) (`failTimeoutSeconds`) | 1–3600 | 30 | How long the origin stays out before it is tried again; also how long failures count, one success clears them |
| Timeouts · Connect (seconds) (`connectTimeoutMs`, milliseconds) | 0.1–60 seconds (API 100–60000 ms) | 5 seconds | Timeout for connecting to an origin |
| Timeouts · Idle (seconds) (`idleTimeoutSeconds`) | 1–86400 | TCP 600, UDP 30 | How long without data in either direction ends a connection or session. Switching the protocol in the new-app dialog sets the protocol's default (unless edited); an API create without it takes the protocol's default, and changing the protocol later keeps the value |

Health state lives on each node only: it is not reported to the console and not shown in the UI. On the node host, list the origins currently down:

```bash title="Node"
sudo curl -s --unix-socket /run/edgeweir-node/control.sock http://localhost/v1/l4
```

`down` in the response lists `{app_id, origin_id, down_until}`.

## Port ranges and origin ports

| Field | Values | Default | Effect |
| --- | --- | --- | --- |
| Last port (`portEnd`) | Empty, or above the listen port; at most 1000 ports per app | Empty | The app listens on every port from **Listen port** to **Last port**; the whole range must be inside the protocol's port pools (adjacent pools may share it), contain no reserved port, and not overlap another app's port or range |
| Origin port (`originPortMode`) | Fixed (`fixed`) / Same as the port (`same`) | Fixed | Fixed: each origin's own port; same: the origin port is the port the connection arrived on (9005 of range 9000-9010 connects to the origin's 9005), the origins' **Port** stays empty (omitted in the API, stored as 0) |

| Item | Rule |
| --- | --- |
| Cluster limit | A cluster's L4 apps listen on at most 2048 ports together (ranges count each port, disabled apps included; "A cluster's L4 apps use at most 2048 ports") |
| Node resources | A TCP range takes one listening socket per port; UDP one per port and worker, see [Ports and firewall](../deploy/nodes.en.md#ports-and-firewall) |
| Statistics and DNS | Per app, as for a single port |
| Node capability | Ranges, origins on the arriving port, and TLS termination need `l4-v2` |

## TLS termination

A TCP app may choose a **TLS certificate**: the node terminates TLS and connects to the origins over plain TCP.

| Field | Values | Default | Effect |
| --- | --- | --- | --- |
| TLS certificate (`certificateId`) | **No TLS**, or an issued, unexpired certificate nodes can load (the menu lists only these and the app's current certificate) | No TLS | The certificate of the handshake |
| Minimum TLS version (`tlsMinimumVersion`) | TLS 1.2 / TLS 1.3 | TLS 1.2 | Handshakes below it are refused; unavailable with **No TLS** |

| Item | Behavior |
| --- | --- |
| SNI | Must be one of the certificate's names (a wildcard covers one label), else the handshake is aborted; a handshake without SNI gets the certificate |
| Cipher suites | The sites' **Modern** profile, not configurable |
| With the PROXY protocol | Both work together: with **Accept PROXY protocol** the header comes before the handshake; **Send to origins** still sends one |
| IP lists and limits | Checked after the handshake |
| Certificate | A certificate not issued yet or expired is refused ("The certificate is not issued yet or has expired"); so is one nodes cannot load (an EC key with explicit curve parameters), see [HTTPS](https.en.md#troubleshooting). A certificate an app uses cannot be deleted ("The certificate is still used by L4 apps: {apps}"); after a renewal nodes use the new one without a reload |
| UDP | Not supported ("TLS termination is for TCP apps only"); the dialog's certificate choice is unavailable for UDP apps |

Verify:

```bash
echo NAME | openssl s_client -quiet -connect <node IP>:9000 -servername game.example.com
```

## PROXY protocol

TCP apps only; UDP apps show "UDP does not carry PROXY protocol", and switching to UDP clears both settings.

| Field | Values | Default | Effect |
| --- | --- | --- | --- |
| Send to origins (`proxyProtocolVersion`) | None (0) / v1 / v2 | None | Every connection to an origin starts with a PROXY protocol header: the client's address and port, and the node address and port it connected to. v2 headers carry no TLVs |
| Accept PROXY protocol (`acceptProxyProtocol`) | On / off | Off | The listener expects every connection to start with a PROXY protocol header, v1 or v2 detected automatically; for nodes behind a layer-4 load balancer. The client address is the one in the header (the TCP peer for `UNKNOWN`), and IP lists check that address |

| Accept | Send to origins | Forwarding |
| --- | --- | --- |
| Off | Any | Native nginx forwarding |
| On | None | Native nginx forwarding |
| On | v1 / v2 | Lua relay: the header it writes carries the client address from the received header (a header nginx sends natively would carry the load balancer's address). Lower throughput than native forwarding; no half-close, one side closing ends the connection |

With **Accept PROXY protocol** on, connections without a header are closed, and a client that reaches the port directly can claim any address in the header: open the port to the load balancer only. Both settings are structural like the port and protocol: changing them reloads the nodes, see [Reloads and long connections](#reloads-and-long-connections).

## IP lists and connection limits

| Field | Values | Default | Effect |
| --- | --- | --- | --- |
| IP lists · Allow lists (`allowListIds`) | Any IP lists, at most 16 | None | When set, only addresses in these lists are accepted |
| IP lists · Block lists (`blockListIds`) | Any IP lists, at most 16 | None | Addresses in these lists are refused |
| Limits per node · Concurrent connections (`maxConnections`) | 0–10000000 | 0 | Connections (UDP: sessions) a node forwards at once; 0 means no limit |
| Limits per node · New connections per second (`newConnectionsPerSecond`) | 0–1000000 | 0 | New connections (UDP: new sessions) a node accepts per second; 0 means no limit |

**Add list** picks from **IP lists**; a list's **Action** does not matter here. The remove button next to a list ("Remove {name}") takes it out again.

| Item | Behavior |
| --- | --- |
| Order | Allow lists, block lists, new connections per second, concurrent connections; the first one not met refuses |
| Refusal | Nothing is forwarded: TCP connections are closed (data the client sent and nobody read makes the kernel answer RST), UDP datagrams are dropped; counted as **Refused**. A refused UDP client counts once per datagram |
| Counting | Limits count per node; the cluster's total capacity is the number of nodes × the limit |
| List changes | Nodes apply changes to list entries without a reload; a list referenced by an L4 app cannot be deleted ("The IP list is used by {users}", naming the users) |
| Per-client connection limits | The cluster's [connection limits](bans.en.md#connection-limits) limit TCP connections per client address in the kernel and, without named ports, include the ports of the cluster's TCP L4 apps; UDP is not limited |
| Other protection | Global **Block** and **Allow** lists, site bans and HTTP-layer bans, rules, WAF, challenges, and CC protection do not apply to L4 apps. On nodes with `kernel-ban-v1`, global bans drop packets in the kernel with nftables, L4 ports included, see [Kernel bans](bans.en.md#kernel-bans) |

## DNS

L4 apps use the cluster's DNS steering like sites, see [DNS steering](dns.en.md#generated-records).

| Item | Behavior |
| --- | --- |
| Records | One `<app's CNAME prefix>.<cluster domain> CNAME all.<cluster domain>` per enabled app; with **Keep per-site line targets** also `<line name>.<app's CNAME prefix>.<cluster domain>` |
| Line targets | One row per line under **CNAME target** on the app page: `<line name>.<app's CNAME prefix>.<cluster domain>` with **Keep per-site line targets**, else the line's own `<line name>.<cluster domain>` |
| Steering | Resolution lines, backup node groups, health removal, and scheduling rules apply as usual |
| Health | Nodes are removed by node health (heartbeat, data plane, current revision applied, scheduling rules), not by the origin state of a single app |
| Writing | After creating or enabling, the next reconciliation (every minute) writes the record; manual mode lists it among the records to create by hand |
| Disabled | A disabled app has no record; the next reconciliation deletes it (disabled sites keep theirs) |
| CNAME prefix | After a change the old name keeps resolving for 24 hours |
| DNS not managed | **CNAME target** shows "Cluster DNS is off" |

Clients connect to the CNAME target with the app's port, for example on your own domain:

```text
game.example.com.  CNAME  <app's CNAME prefix>.<cluster domain>.
```

Clients connect to `game.example.com:9000`.

## Statistics

The **Analytics** tab of the app page (`/l4/<app ID>?tab=stats`), with the ranges **Last hour**, **Last 6 hours**, **Last 24 hours** (default), and **Last 7 days** (URL parameter `range`: `1h`, `6h`, `7d`). The window ends now and moves on every minute; **Refresh** reads again at once.

| Metric | Meaning |
| --- | --- |
| Connections | TCP connections or UDP sessions accepted |
| Refused | Connections or sessions refused by the IP lists or the limits per node |
| Peak concurrency | Per minute the sum of the nodes' peaks, the highest minute of the range |
| Received | Bytes received from clients |
| Sent | Bytes sent to clients |

One card per metric (the range's total and a trend line); charts **Connections** (connections and refused) and **Traffic** (received and sent); the **Nodes** table lists every reporting node's values over the range, busiest first, or "No traffic" without data.

| Item | Behavior |
| --- | --- |
| Reporting | Nodes report per app and per minute, in the same batch as site statistics; bytes of open connections are sampled every 10 seconds, so long connections count in every minute |
| Resolution | API point width: 60 seconds for ranges up to 1 day, 300 seconds up to 5 days, else 3600 seconds; the charts draw at most 120 points |
| Retention | Minute data for 7 days; deleted with the app |
| Loss | Deleting a cluster's last L4 app, or an nginx restart, loses the last minute or two a node has not reported yet |
| Node metrics | A node's active connections (`metrics-v1`) include layer-4 client connections, upstream connections, and UDP sessions, and so does the **Active connections** condition of scheduling rules |

## Reloads and long connections

| Change | Node behavior |
| --- | --- |
| Port, last port, protocol, whether TLS is terminated, **Accept PROXY protocol**, the version under **Send to origins**; creating, deleting, disabling, enabling | Structural: `nginx.conf` is rendered again and nginx reloads |
| Origins, weights, backups, the origin port mode, passive health check, timeouts, IP lists and their entries, limits per node, the chosen certificate and minimum TLS version | Hot update without a reload; new settings apply to later connections |

| Item | Behavior |
| --- | --- |
| TCP connections | Connections opened before a reload stay with the old worker and keep forwarding until they end or reach the idle timeout; the old worker exits after its last connection |
| UDP sessions | Do not survive a reload: later datagrams start a new session in a new worker (possibly with another origin); the old session ends at the idle timeout |
| New ports | Connections that arrive between the reload and the push of the L4 app table (milliseconds) are closed; the node reports the configuration applied only after the push |
| Old workers | By default they serve their connections until these end, so frequent structural changes leave several sets of old workers. The node option `--stream-shutdown-timeout` makes old workers close the connections they still serve after that long, HTTP keep-alive and WebSocket connections included, see [Add nodes](../deploy/nodes.en.md#ports-and-firewall) |

## UDP

| Item | Behavior |
| --- | --- |
| Sessions | One client address and port is one session until the idle timeout; any number of replies per datagram from the origin is forwarded (DNS, QUIC, game protocols work) |
| Idle timeout | 30 seconds by default. Set a short idle timeout for request-response protocols such as DNS, otherwise every client port holds a concurrent session until it times out |
| PROXY protocol and TLS termination | Not supported |
| Refusal | Refused datagrams are dropped and counted one by one |

## Node requirements

| Item | Behavior |
| --- | --- |
| Capability | `l4-v1` once the configuration has an enabled L4 app; also `l4-v2` once an enabled app uses a port range, origins on the arriving port, or TLS termination |
| Nodes without it | Refuse that configuration, keep their last-known-good configuration, and show **Upgrade required** in **Clusters & nodes**; since they do not apply the current revision, they leave DNS steering after 2 minutes. Without `l4-v1`, the port pools tab, the app list, the app page, and the dialog warn "Nodes {nodes} in {cluster} lack L4 forwarding and skip configurations with L4 apps until upgraded"; without `l4-v2`, the dialog locks the fields concerned with the note "Some nodes in the cluster do not support it" |
| Order | [Upgrade the nodes](node-upgrades.en.md) first, then create L4 apps |
| Ports | Open the port pools in the node hosts' firewall and the cloud security group, and publish them on container nodes, see [Add nodes](../deploy/nodes.en.md#ports-and-firewall) |
| Privileges | Ports are 1024 or higher: the node's systemd unit and image need no extra privileges |

## Rollback

**Roll back** under **Revisions** on the cluster's **Releases** tab ships the L4 app settings of the chosen revision:

| Case | Behavior |
| --- | --- |
| The app is disabled now | Not shipped |
| The app was deleted since, its port is no longer inside a port pool, a referenced IP list was deleted, or the revision's TLS certificate has expired or cannot be loaded by nodes | The rollback is refused ("The rollback references resources that are gone or unavailable") |
| The configuration canary rolls back to the stable revision | These apps are left out, everything else is shipped |

A rollback does not change the apps' saved settings; any later change publishes them again from the saved settings.

| --- | --- |

| Name | 1–100 characters, surrounding spaces removed |
| Port ranges | At most 1000 ports per app; 2048 ports per cluster |
| TLS termination | TCP only; one certificate per app |
| Ports | 1024–65535, inside a port pool of the cluster for the protocol, no reserved port; a port of a protocol belongs to one app of the cluster (disabled apps included) |

| Statistics | Per minute, kept for 7 days; one query covers at most 7 days |
| Protection | Only the app's own IP lists, the limits per node, the cluster's connection limits (TCP), and kernel bans |

## API

Paths are relative to `/api/v1`; request fields and responses are in [API and endpoints](../reference/api/clusters.en.md#port-pools-and-l4-apps). Service accounts cannot call these procedures (403 `SERVICE_ACCOUNT_FORBIDDEN`).

| Procedure | Method and path | Purpose |
| --- | --- | --- |
| `clusters.portPools` | `GET /clusters/{clusterId}/port-pools` | Port pools, reserved ports, and the active nodes without `l4-v1` or `l4-v2` |
| `clusters.setPortPools` | `PUT /clusters/{clusterId}/port-pools` | Replaces the port pools; publishes no revision |
| `l4Apps.list` | `GET /l4-apps` | The apps, by port and protocol; query parameter `clusterId` optional |
| `l4Apps.get` | `GET /l4-apps/{id}` | One app |
| `l4Apps.create` | `POST /l4-apps` | Creates an app (201); returns the app and the revision |
| `l4Apps.update` | `PATCH /l4-apps/{id}` | Changes the fields given, `origins` replaces the list; optional `expectedUpdatedAt` |
| `l4Apps.setEnabled` | `PUT /l4-apps/{id}/enabled` | Disables or enables; optional `expectedUpdatedAt` |
| `l4Apps.delete` | `DELETE /l4-apps/{id}` | Deletes; returns the revision |
| `l4Apps.setCnamePrefix` | `PUT /l4-apps/{id}/cname-prefix` | Sets the CNAME prefix (`prefix`); without it, a new random prefix |
| `l4Apps.stats` | `GET /l4-apps/{id}/stats` | Query parameters `from`, `to` (ISO 8601, at most 7 days); returns counters per point, totals, and per node |

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| "Port {port} is outside the cluster's port pools for this protocol" | The port (or that port of the range) is in no pool of the protocol | Add a port pool on the cluster's **Port pools** tab, or use another port |
| "Port {port} is used by the cluster's HTTP listeners" | A port pool or app port contains a reserved port | Avoid the ports listed under **Reserved ports** |
| "Port {port} is inside port pools: {pools}" | An extra listener port added on the cluster's **Settings** tab lies inside a port pool | Use another listener port, or shrink the pool first |
| "The last port must be above the first, at most 1000 ports" | The last port is not above the listen port, or the range exceeds 1000 ports | Change the last port |
| "A cluster's L4 apps use at most 2048 ports" | The ports of all the cluster's apps exceed 2048 | Shorten ranges, or delete unused apps |
| "Every origin needs a port while the origin port is fixed" | **Origin port** is **Fixed** but an origin has no port | Fill in the port, or select **Same as the port** |
| "Origin address {address} is in the special-purpose range {range}, outside the origin allow list" | The origin is a private or other special-purpose address | Use a public address, or add the range to the [origin allow list](system.en.md#origin-allow-list) |
| "The certificate is not issued yet or has expired" | The chosen certificate is not issued or has expired | Issue or renew the certificate first |
| "TLS termination is for TCP apps only" | The API set `certificateId` on a UDP app | Remove the certificate, or use TCP |
| TLS handshakes fail | The SNI is not one of the certificate's names; the client's highest version is below the minimum TLS version | Connect with a name of the certificate; change the minimum TLS version |
| "The certificate is still used by L4 apps: {apps}" | Deleting a certificate apps still use | Choose another certificate or **No TLS** in the listed apps first |
| "Ports in use by {apps}" | Creating or editing: another app of the cluster (disabled ones included) uses the port and protocol; saving port pools: an app's port would be left outside | Use another port, or change or delete the listed apps first |
| "Port pools overlap: {pools}" | Pools of one protocol overlap; TCP + UDP overlaps TCP and UDP | Change the ranges or protocols |
| "A cluster can have at most 256 L4 apps" | The limit is reached | Delete unused apps |
| "PROXY protocol is for TCP apps only" | The API set PROXY protocol on a UDP app | Remove the PROXY protocol settings |
| "It changed since you loaded it; reload and try again" | The app was changed elsewhere after the dialog opened | Reload the page and edit again |
| "Nodes {nodes} in {cluster} lack L4 forwarding …" | Nodes lack `l4-v1` | [Upgrade the nodes](node-upgrades.en.md) |
| **Last port**, **Origin port**, and **TLS certificate** unavailable with "Some nodes in the cluster do not support it" | Nodes lack `l4-v2` | [Upgrade the nodes](node-upgrades.en.md) |
| Some nodes leave DNS after an app is created | These nodes lack a required capability and do not apply the current revision | Upgrade the nodes, or disable the app first |
| Connections time out | The node firewall or security group does not open the port; a container node does not publish it | Open it as in [Ports and firewall](../deploy/nodes.en.md#ports-and-firewall) |
| Connections are closed at once | Refused by an IP list or a limit (**Refused** rises); **Accept PROXY protocol** is on but the client sends no header; the port was just added | Check the lists and limits; turn on **Accept PROXY protocol** only behind a load balancer |
| The origin drops the connection or reports a protocol error right after connecting | **Send to origins** is set but the origin does not accept PROXY protocol, or expects another version | Enable that version on the origin, or select **None** |
| The origin sees the load balancer as the client | A layer-4 load balancer sits in front of the nodes | Have the load balancer send PROXY protocol, turn on **Accept PROXY protocol**, and choose a version under **Send to origins** |
| Every connection fails and **Refused** does not rise | No origin is reachable | Check `down` of `GET /v1/l4` on a node, the origin addresses, and the origin's firewall |
| High UDP **Peak concurrency**, or the **Concurrent connections** limit reached | Every client port is a session until the idle timeout | Lower **Idle (seconds)** |
| Old nginx workers stay after a reload | They still serve long connections | Expected; set `--stream-shutdown-timeout` to bound it |
| **CNAME target** shows "Cluster DNS is off" | The cluster's DNS mode is **Not managed** | [Bind the cluster](dns.en.md#bind-a-cluster) on its **DNS** tab |
| "The IP list is used by {users}" | Deleting a list the listed apps still reference | Remove it from the app's allow and block lists first |
| "The rollback references resources that are gone or unavailable" | An app, port, IP list, or certificate of the chosen revision is no longer available | Choose a more recent revision, or change the app directly |

# API安全

打开网站侧栏的 **安全 → API安全**（`/sites/<ID>/api-security`），配置端点发现、OpenAPI 请求校验、JWT 与 GraphQL 检查。

## 开启与保存

所有检查默认关闭，端点发现也默认关闭。检查各自选择模式：

| 模式 | 行为 |
| --- | --- |
| 关闭（`off`） | 不运行该检查 |
| 观察（`observe`） | 记录违规，请求继续处理 |
| 执行（`enforce`） | 拦截该检查发现的违规 |

编辑只改变草稿，点击**保存**才发布。将检查从关闭或观察切到执行时，点击**保存并执行**确认。先观察实际请求、修正配置与必要的例外，再开启执行。

节点在访问鉴权之后、缓存查找之前执行API安全。站点集群的活动节点需要真实支持能力 `api-security-v1`；页面显示不支持的节点数。保存的模式不代表所有节点已经执行，先检查[节点升级](node-upgrades.md)与网站配置下发状态。

## 端点发现

开启**采样端点**后，默认采样率为1000/10000（10%），可设1–10000。发现最多保留500个候选，保留7天。

| 字段 | 含义 |
| --- | --- |
| 方法与路径模板 | HTTP方法与发现的模板；支持命名参数，如 `/users/{id}` |
| 来源 | 采样流量、OpenAPI或人工确认 |
| 首次/最后发现 | 发现记录的时间范围 |
| 采样请求数 | 被采样并记录的请求数 |
| 采样违规数 | 采样记录中带API检查违规的数量 |
| 确认/修正 | 确认候选或更正其路径模板，仅修改发现记录 |

数字是采样计数，不是全量流量、唯一访客数或业务成功率。自动候选与人工确认都不会生成、启用或放宽安全策略；需要校验的端点由明确保存的Schema配置决定。

## OpenAPI与Schema校验

1. 点击**导入OpenAPI JSON**，粘贴JSON或选择JSON文件。
2. 点击**预览**，核对端点、请求参数与请求体概况，以及问题代码和问题位置。
3. 点击**使用预览**替换Schema草稿中的端点和导入问题；此时尚未保存。
4. 选择观察模式并保存。修正原文档后重新导入，直到问题列表为空，才能选择执行。

导入仅接受OpenAPI 3.0或3.1的JSON，文档不超过512 KiB，最多200个端点。不接受YAML。预览不会更改站点策略。

支持按方法和路径模板匹配端点，校验路径、查询串、请求头参数与JSON请求体；不提供响应Schema校验。支持的Schema关键字：

| 关键字 | 范围 |
| --- | --- |
| `type` | `string`、`number`、`integer`、`boolean`、`object`、`array`、`null` |
| `properties`、`required` | 对象属性与必填属性 |
| `additionalProperties` | 仅布尔值 |
| `items` | 数组元素Schema |
| `enum` | 字符串、数字、布尔值或 `null` |
| `minLength`、`maxLength` | 字符串长度 |
| `minItems`、`maxItems` | 数组长度 |
| `minimum`、`maximum` | 数值上下限 |
| `nullable` | 可空值 |

数值约束必须能以控制台JSON数字无损往返；不接受导入时发生舍入或下溢的数值。数值字面量最多128字节，十进制指数范围为−308到308；超出范围会报告约束位置。

带API检查元数据的访问日志使用脱敏模板作为路径，并清除查询串、请求头、User-Agent与Referer；站点原有的日志选项不能为这些记录保留请求值。

仅检查带Content-Length且不超过128 KiB的完整请求体；分块编码、HTTP/2或HTTP/3未提供长度时按无法完整检查处理，执行模式拒绝、观察模式记录并继续。需要读取请求体的检查也要求空请求明确提供长度；无效UTF-8与未配对的Unicode代理码转义拒绝。

文档内部 `$ref` 展开后最多8层、2000个Schema节点。远程引用、循环引用、`pattern`/正则、`format`、`allOf`/`anyOf`/`oneOf`等组合约束不受支持，不能作为已执行的约束。导入问题带文档中的 `location`；存在任何问题时，禁止保存Schema执行模式。JSON请求体的处理上限为128 KiB。

**未知端点**决定文档未定义的方法与路径如何处理：允许，或按模式记录/拦截。后者在观察模式仅记录，在执行模式拦截；关闭Schema时不执行未知端点检查。

方法与路径区分大小写，按节点规范化后的完整路径匹配；参数占一个非空路径段，尾斜杠区分。静态段更多的模板优先，同等优先级的重叠模板拒绝。编码斜杠、点路径、分号参数等歧义路径不能授予例外，也不继承访问控制的编码路径例外。选择放行未知端点时，Schema不会保护其他拼写、方法或路径；源站若忽略路径大小写，需要配置对应端点或拦截未知端点。

## JWT

JWT检查使用静态公钥，校验签名、签发者（`iss`）、受众（`aud`）、过期时间（`exp`）与生效时间（`nbf`）等声明。开启观察或执行时，签发者、至少一个受众和公钥均必填。

| 字段 | 范围 |
| --- | --- |
| 签发者 | 与令牌声明匹配，最多512字符 |
| 受众 | 每行一个，最多16个 |
| 签名算法 | `RS256`、`ES256`、`EdDSA`，至少选择一个 |
| 公钥JWKS | `{"keys":[...]}`，最多8把，`kid`不可重复 |
| 时钟容差 | 0–120秒，默认30秒 |
| 检查范围 | 与[访问鉴权](access-control.md#范围与选择)相同的域名、路径前缀、扩展名与排除路径 |

每把公钥需要 `kid`、`alg`、`kty`。RSA使用公开的 `n`、`e`；ES256使用 `crv: "P-256"`、`x`、`y`；EdDSA使用 `crv: "Ed25519"`、`x`。编辑器与接口只接受这些公钥字段。不要粘贴私钥；`d`、`p`、`q`、`dp`、`dq`、`qi`、`oth`与对称密钥 `k`均拒绝，不会通过删除私密字段自动转成公钥。

没有远程JWKS地址或定期获取公钥，也不支持HMAC等对称签名算法。轮换时先加入新公钥，再切换签发端，最后删除旧公钥并保存。JWT开启时，匹配其检查范围的请求绕过缓存，避免不同身份共用缓存结果；观察模式也如此。

## GraphQL

检查配置路径上的HTTP GET/POST GraphQL请求，解析AST，限制深度、展开片段后的字段数、别名、批量请求数与文档字节数。不提供GraphQL业务Schema或Resolver级授权校验。

| 设置 | 范围 | 默认值 |
| --- | --- | --- |
| 路径前缀 | 1–16个，每行一个 | `/graphql` |
| 最大深度 | 1–30 | 10 |
| 最大展开字段数 | 1–1000 | 200 |
| 最大别名数 | 0–200 | 30 |
| 最大批量数 | 1–20 | 5 |
| 最大文档字节数 | 256–65536 | 65536 |
| 允许内省 | 开/关 | 关 |

仅含APQ/持久化查询标识、没有查询正文的请求记为违规，节点不会根据哈希从远程获取查询。观察模式只记录上述违规，执行模式才拦截。

按operationName选择操作；多个操作未指定名称、未知操作、未知或循环片段均拒绝。variables仅接受对象或省略/null。字段数与别名按片段每次展开累计，条件指令保守计数，不估算Resolver成本。GET不接受mutation；关闭内省时拦截 `__schema`与 `__type`，仍允许 `__typename`。

## 检查例外与结果

每个例外指定一个检查项（Schema、JWT或GraphQL）、方法（或所有方法）、路径模板、原因和启用状态，最多100条。新增、编辑、启停与删除都在保存后发布；原因不能为空，最多256字符。例外仅跳过选定的API检查，其他API检查、访问鉴权、WAF与其他安全策略继续执行。

路径填写完整模板：`/users/{id}`可匹配 `/users/42`等参数值，`/users`只匹配该路径，不表示所有以它开头的路径。发现表中的人工确认只改发现元数据，不能代替配置例外或Schema策略。

歧义或异常编码路径在执行模式拒绝，在观察模式记录；不要用编码路径规避模板匹配或检查范围。

**观察结果**显示时间、请求ID、方法、路径模板、检查项、代码与模式，并显示HTTP状态和命中的例外数。用请求ID关联[访问日志](access-logs.md)。观察模式出现违规不表示该请求已被拦截；执行模式的违规才触发API检查拦截。

发现候选实际保留7天，之后删除。观察结果仅查询最近最多7天，且受普通访问日志保留期影响；日志保留更短时，结果也更少。访问日志内的API检查元数据没有独立的7天删除规则，其存储保留遵循访问日志设置。

## 接口与审计

接口使用与控制台相同的[API凭据](../reference/api.md)，路径以 `/api/v1` 开头：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /sites/{id}/api-security` | 返回 `settings`、`updatedAt`、`unsupportedNodes` |
| `PUT /sites/{id}/api-security` | 提交完整 `settings` 与 `expectedUpdatedAt` |
| `POST /sites/{id}/api-security/import` | 用字符串 `document` 预览导入，返回版本、端点和问题 |
| `GET /sites/{id}/api-security/results` | 获取发现、观察结果、采样率、保留天数与不支持节点数 |
| `PUT /sites/{id}/api-security/endpoints/{endpointId}` | 提交 `path`，只确认或修正发现记录 |

遇到版本冲突时重新获取并核对修改，不覆盖他人保存。设置变更记录审计 `site.api_security_update`；发现确认记录 `site.api_endpoint_confirm`。无效配置返回 `API_SECURITY_INVALID`，无效导入返回 `API_SECURITY_IMPORT_INVALID`，已不存在的发现返回 `API_ENDPOINT_NOT_FOUND`。

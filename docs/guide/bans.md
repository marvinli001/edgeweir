# 封禁

按 IP 地址或 CIDR 临时拦截或限制客户端：手动、自动与规则封禁，灰名单，内核封禁与连接数限制。

## 概念

| 术语 | 定义 |
| --- | --- |
| 封禁 | 一个 IP 地址或 CIDR，到期前对应请求被拦截（403）。经节点通道直接下发，数秒内生效，不产生配置版本。 |
| 范围 | 「网站」：只作用于一个网站。「全局」：作用于所有集群的全部网站，并由节点在内核丢包（见[内核封禁](#内核封禁)）。API 中分别为 `site` 与 `platform`。 |
| 来源 | 「手动」：在 **封禁** 页签或经 API 创建。「自动」：节点按触发条件自行产生并上报。「规则」：节点执行规则的「封禁」动作或限速的「超额后封禁」时产生并上报。 |
| 灰名单 | 到期前对应请求被挑战或限速而不被拦截，见[灰名单](#灰名单)。 |
| 到期 | 1 分钟到 7 天。长期拦截用 [IP 名单](rules.md#ip-名单)。 |

页面：侧边栏 **访问控制 → IP 名单与封禁**，页面顶部的「IP 名单 | 封禁 | 灰名单」切换 `/ip-lists`、`/bans` 与 `/greylist`。设置在 **访问控制 → 防护设置**（`/protection`）的「封禁」与「连接限制」卡片。

## 封禁地址

1. 打开 **IP 名单与封禁 → 封禁**，点击「新建封禁」。
2. 选择「范围」：「网站」（默认）或「全局」。
3. 范围为「网站」时，在「网站」中选择网站；网站较多时先在「搜索网站」中输入名称或域名。
4. 填写「IP 或 CIDR」，例如 `203.0.113.7` 或 `198.51.100.0/24`。
5. 选择「原因」（默认「滥用」）与「时长」（1 小时、6 小时、1 天（默认）、3 天、7 天），点击「封禁」。
6. 验证：从被封禁的地址请求该网站：

   ```bash
   curl -sI -H 'Host: www.example.com' http://<节点 IP>/
   ```

   返回 403，响应头含 `X-Edgeweir-Error: ip-banned`。网站封禁不影响同一地址访问其他网站。

封禁后提示中的「查看封禁」打开列表。解封：点击该行的「解封」并确认，节点在数秒内移除该封禁；手动、自动与规则封禁都可解封。

列表只显示有效的封禁（未到期、未解封），按创建时间倒序，每页 50 条，每 30 秒刷新；可按范围、网站与来源筛选：

| 列 | 内容 |
| --- | --- |
| 地址 | 规范化的 CIDR；在线节点未能保存该封禁时显示「N 个节点未生效」 |
| 网站 | 网站名称；全局封禁显示「全局」 |
| 原因 | 封禁原因 |
| 来源 | 「手动」及操作者；「自动」及来源节点与触发条件（指标、观测值 / 阈值、窗口秒数）；「规则」及规则名称（全局规则标「（全局）」，规则已删除时显示「已删除的规则」，悬停显示规则 ID）与来源节点，限速的封禁另有触发条件；未下发到其他节点的自动与规则封禁另标「未共享」 |
| 到期 | 状态灯与剩余时间；悬停显示到期时间。列表刷新前已到期的封禁显示「已到期」 |

任一集群的[访客 IP](../deploy/nodes.md#访客-ip) 不是「直连」时，列表上方显示「集群 {clusters} 的访客 IP 来自代理：内核封禁只匹配 TCP 对端」，见[节点前的负载均衡](#节点前的负载均衡)。

### 从其他页面封禁

| 入口 | 结果 |
| --- | --- |
| 网站「日志」页签，行末「⋯」→「封禁 IP」 | 封禁对话框，预填网站与地址 |
| 统计的「热门 IP（估算）」，行末「⋯」→「封禁 IP」 | 网站「统计」页签预填网站与地址；**概览** 预填「全局」与地址 |
| 网站「攻击」页签「近期 Top IP 与路径」，IP 行「⋯」→「封禁 IP」 | 预填网站与地址 |
| 网站「攻击」页签「事件」，自动封禁行「⋯」→「在所有网站封禁」 | 预填「全局」与地址 |
| 网站「攻击」页签「事件」，自动封禁行「⋯」→「解封」 | 确认后解除本网站对该地址的封禁（只解除 CIDR 与该地址完全相同的封禁，覆盖它的网段封禁保留）；没有时提示「该地址没有生效中的封禁」 |
| ⌘K / Ctrl+K →「封禁 IP…」 | 封禁对话框；在网站页面时预填该网站 |
| `/bans?site=<网站 ID>&ip=<地址>` | 预填网站与地址的对话框；列表只显示该网站中与该地址重叠的封禁，地址旁的 × 清除地址筛选 |

对话框中「范围」都可以改。

## 规则

| 项目 | 行为 |
| --- | --- |
| 地址 | IPv4 / IPv6 地址或 CIDR，最长 64 字符；单个地址视为 `/32` 或 `/128`；清除主机位，IPv6 小写并压缩；`::ffff:a.b.c.d` 按对应的 IPv4 处理；拒绝前导零写法和 zone ID |
| 前缀下限 | IPv4 `/16`，IPv6 `/48` |
| 到期 | 60–604800 秒（界面提供 1 小时到 7 天的选项）；节点按到期时间自动失效，控制台每 10 分钟删除到期超过一小时的记录 |
| 原因 | 手动：「滥用」「攻击」「扫描」「垃圾请求」「其他」；自动：「单 IP 请求过快」「扫描未知域名」「挑战失败过多」；规则：「规则封禁」「超过限速」 |
| 再次封禁 | 同一地址的全局封禁、或同一网站与地址的网站封禁，只有一条有效的手动封禁；再次封禁更新原因与到期时间，不增加数量。手动全局封禁的 CIDR 与一条有效的自动或规则全局封禁相同时，手动封禁接替它，按新建封禁计数、审计并发给全部节点；那条全局封禁未共享时随之解除（各节点删除自己的那条），手动封禁另建一条 |
| 受保护地址 | 网站封禁不能包含该网站所在集群的节点地址，全局封禁不能包含任何节点地址；封禁也不能包含回环地址（`127.0.0.0/8`、`::1`）与未指定地址（`0.0.0.0/8`、`::`），不能与全局放行名单重叠 |
| 执行位置 | 边缘层确定网站之后、规则之前：先查全局封禁，再查网站封禁。全局放行名单中的地址与集群的可信代理不受封禁；网站的[本站放行名单](access-control.md#本站名单)中的地址不受该网站的封禁（含 CC 单 IP 自动封禁），全局封禁照常 |
| 下发 | 不产生配置版本、不经配置金丝雀、节点不重载 |
| 审计 | `ban.create`、`ban.update`（再次封禁）、`ban.delete`；自动与规则封禁的产生不写审计 |

## 数量上限

| 上限 | 计数 | 设置 |
| --- | --- | --- |
| 手动封禁上限 | 有效的手动封禁与灰名单条目，全局与网站范围合计 | **防护设置 → 封禁 → 手动封禁上限**；默认 10000，范围 100–100000 |
| 自动封禁 | 每个集群的有效网站范围自动与规则封禁；全局范围的自动与规则封禁另计 | 各固定 10000 条；超出时最早的失效 |

自动与规则封禁不计入手动封禁上限。达到上限时新建封禁或灰名单条目返回 409 `BAN_PLATFORM_LIMIT`（「手动封禁已达上限（N 条）」）；再次封禁仍有效的手动封禁、再次添加仍有效的灰名单条目不受上限限制。修改设置写审计 `system.bans_update`。

## 自动封禁

节点按触发条件自行封禁：

| 触发 | 范围 | 原因 | 说明 |
| --- | --- | --- | --- |
| CC 防护的「单 IP QPS」 | 网站 | 「单 IP 请求过快」 | 见[挑战与 CC 防护](challenges.md#cc-防护) |
| 集群的扫描防护 | 全局 | 「扫描未知域名」 | 见[扫描防护](domains.md#扫描防护)；需要 `unknown-host-v1` |
| 挑战失败封禁 | 网站 | 「挑战失败过多」 | 同一地址 10 分钟内答错挑战达到网站设置的次数，见[挑战失败封禁](challenges.md#挑战失败封禁)；需要 `challenge-v2` |

IPv4 封单个地址，IPv6 封所在的 `/64`；回环地址从不封禁。封禁立即在该节点生效，每 5 秒批量上报控制台。

| 项目 | 行为 |
| --- | --- |
| 共享 | **防护设置 → 封禁 → 集群内共享自动封禁**，默认开启：开启时网站范围的封禁下发到同集群的全部节点，全局范围的下发到全部节点；关闭时只保存供查看，列表标记「未共享」。修改只影响之后新增的封禁 |
| 合并 | 网站范围：同一节点、网站、地址与来源只保存一条；全局范围：同一地址只保存一条（已有有效的手动全局封禁时不新增，也不改动它）；再次上报只延长到期时间 |
| 校验 | 网站范围的封禁须属于该节点所在集群的网站；全局范围的只来自扫描防护与全局规则的「封禁」动作；IPv4 只接受单个地址，IPv6 只接受 `/64`（旧版节点为 `/128`）；到期最长为创建后 7 天；网站范围的覆盖受保护地址（本集群节点的地址、全局放行名单）时不保存 |
| 全局范围的受保护地址 | 覆盖其他集群节点的地址或任一集群的可信代理时保存但不共享，列表标记「未共享」，可以解封；覆盖上报节点所在集群的节点地址或全局放行名单时保存为已解封，不列出，该集群的节点在数秒内删除自己的封禁，其他集群节点对同一地址的封禁不受影响 |
| 解封 | 与手动封禁相同，点击该行的「解封」；未共享的封禁由持有它的节点在数秒内删除（不支持的旧版节点要到期才失效）。全局范围的扫描封禁发给全部支持扫描防护的节点（几个节点都可能封禁了这个地址），每个节点删除自己到期不晚于解封时间加上本集群设置过的最长扫描封禁时长的封禁；节点收到解封之后再次自行封禁同一地址不受影响。网站范围的封禁解封后，各节点重新为该客户端计数，它再次超过阈值时会被再次封禁 |

## 规则封禁

规则的「封禁」动作与限速的「超额后封禁」由节点经自动封禁的同一通道写入并上报，列表的来源为「规则」，带规则名称。见[WAF 动作](rules.md#waf-动作)。需要节点能力 `waf-v2`。

| 项目 | 行为 |
| --- | --- |
| 范围 | 「封禁」动作：网站规则为网站范围；全局规则可选网站或全局范围。「超额后封禁」：网站范围 |
| 前缀 | 「封禁」动作：IPv4 /16–/32（默认 /32）、IPv6 /48–/64（默认 /64）；「超额后封禁」：IPv4 /32、IPv6 /64 |
| 时长 | 「封禁」动作 60–604800 秒（默认 3600）；「超额后封禁」60–86400 秒，0 为关闭 |
| 不重复写入 | 该网段已有有效封禁（任何来源）时节点不再写入；被封禁的请求在规则之前已被拒绝 |
| 不写入 | 全局放行名单中的地址、集群的可信代理与节点自己的预热请求；网站范围的封禁不写给本站放行名单中的地址 |
| 合并 | 网站范围：同一节点、网站与网段只保存一条规则封禁（与同一地址的自动封禁分别保存）；全局范围：同一网段只保存一条；再次上报只延长到期时间 |
| 校验 | 规则必须存在：全局范围的封禁来自全局规则，网站范围的来自该网站的规则或全局规则；规则在上报前被删除时不保存（节点上的封禁照常到期） |
| 共享与解封 | 与自动封禁相同；计入自动封禁的 10000 条上限，不计入手动封禁上限；不写审计 |

## 灰名单

灰名单中的地址不被拦截，而是被挑战或限速，到期自动失效。与封禁共用节点通道，数秒内生效，不产生配置版本（挑战密钥除外，见下表）。

1. 打开 **IP 名单与封禁 → 灰名单**，点击「添加灰名单」。
2. 选择「范围」（「网站」或「全局」）；范围为「网站」时选择网站。
3. 填写「IP 或 CIDR」。
4. 选择「动作」：
   - 「挑战」（默认）：选择「挑战方式」（「Cookie 跳转」「JS 计算」（默认）「工作量证明」「图片验证码」）。没有该级别通行凭证的请求先收到挑战。
   - 「限速」：填写「请求数」（默认 60）与「窗口（秒）」（默认 60）。每个客户端（IPv4 地址，IPv6 所在的 `/64`）在每个节点上每窗口最多这么多请求，超出返回 429，响应头含 `Retry-After` 与 `X-Edgeweir-Error: ip-greylisted`。
5. 选择「原因」与「时长」，点击「添加」。

列表列为「地址」「网站」「动作」「原因」「到期」，可按范围与网站筛选。移出：点击该行的「移出」并确认。链接 `/greylist?ip=<地址>` 只列出与该地址重叠的条目。

| 项目 | 行为 |
| --- | --- |
| 地址、到期、原因 | 与手动封禁相同：前缀下限 IPv4 `/16`、IPv6 `/48`，1 分钟到 7 天，手动封禁的原因，受保护地址相同 |
| 限速范围 | 请求数 1–100000，窗口 1–3600 秒 |
| 再次添加 | 同一范围、网站与地址只有一条有效条目；再次添加更新动作、原因与到期时间 |
| 与封禁 | 同一地址可同时有封禁与灰名单条目，两者都有效时封禁优先；移出灰名单不影响封禁 |
| 执行顺序 | 封禁之后查找灰名单；限速在规则之后执行，规则自己的结果优先；挑战与 Under Attack、CC、规则的挑战合并，取最高级别。已验证的爬虫跳过 Under Attack 与 CC 挑战，不跳过灰名单挑战 |
| 免除 | 全局放行名单与集群可信代理中的地址不受任何条目约束；HTTP-01 验证请求不受约束。规则的「放行」免除挑战与限速；跳过挑战免除挑战；跳过限速免除同一范围条目的限速。网站的本站放行名单中的地址不受该网站的网站范围条目约束，也免除全局条目的挑战，不免除全局条目的限速 |
| 内核 | 灰名单从不写入 nftables |
| 挑战密钥 | 挑战需要集群的挑战密钥：集群配置还没有密钥时，添加「挑战」条目会为相关集群（全局条目为全部集群）发布一个配置版本，原因「为灰名单挑战下发密钥」；版本应用前节点对这些请求返回 503（`X-Edgeweir-Error: challenge-unavailable`） |
| 上限 | 计入 **防护设置 → 封禁 → 手动封禁上限** |
| 节点 | 需要 `greylist-v1`；旧版节点忽略灰名单，列表上方显示「N 个节点版本过低，不执行灰名单」。节点未能保存的条目显示「N 个节点未生效」 |
| 审计 | `greylist.create`、`greylist.update`（再次添加）、`greylist.delete` |

## 节点

| 项目 | 行为 |
| --- | --- |
| 节点能力 | 执行封禁需要 `bans-v1`；规则封禁另需 `waf-v2`，挑战失败封禁另需 `challenge-v2`，扫描防护另需 `unknown-host-v1`，灰名单需要 `greylist-v1`；未上报该能力的旧版节点照常服务，不执行对应功能 |
| 同步 | 节点只取得本集群的封禁与已共享的全局封禁。节点保存已应用的序号，只拉取之后的变化；首次连接或控制台数据库恢复后取得完整快照。节点把封禁落盘，重启后先装入再连接控制台 |
| 容量 | 节点参数 `--ban-capacity`（默认 100000 条，最大 10000000）与 `--ban-dict-mb`（默认 32 MiB）。空间不足时先淘汰最早的自动封禁 |
| 未生效 | 手动封禁写不下时不会静默丢弃：节点上报未生效的封禁，列表显示「N 个节点未生效」（只计在线节点），节点每分钟重试 |
| 状态 | 节点每次心跳上报封禁状态：已应用序号、条目数、容量、未生效的封禁、内核条目数与淘汰的自动封禁数。经 `GET /api/v1/nodes/{id}` 的 `banStatus` 读取（`appliedSequence`、`entries`、`capacity`、`unapplied`、`unappliedIds`、`kernelEntries`、`autoEvicted`） |

## 内核封禁

全局封禁同时由节点 agent 写入 nftables，在内核丢弃被封地址的入站数据包，被封客户端连 TCP 与 TLS 握手都无法完成。网站封禁只在 HTTP 层执行。[L4 应用](l4.md#ip-名单与连接上限) 只受内核封禁约束：网站封禁与 HTTP 层的封禁不作用于四层流量。

| 项目 | 行为 |
| --- | --- |
| 条件 | agent 具备 `CAP_NET_ADMIN`，主机有 `nft`，节点参数 `--kernel-bans` 为 `auto`（默认；`off` 关闭）。agent 启动时建表，成功才上报能力 `kernel-ban-v1`；失败时只做 HTTP 层封禁并记录日志 |
| 表 | agent 只管理自己的表 `inet edgeweir`（集合 `ban4`、`ban6`、`allow4`、`allow6`，input 链），启动时清掉残留，退出时删除；每次变更是一个 `nft -f -` 事务 |
| 永不封禁 | 控制台地址、节点自身地址、回环地址、全局放行名单 |
| 出站连接 | 被封地址的入站包全部丢弃，节点也无法与该地址建立连接（例如该地址恰好是源站） |

默认的 systemd 单元与节点镜像不授予 `CAP_NET_ADMIN`，需要时按下列步骤启用。

### systemd 节点

1. 安装 nftables：

   ```bash title="节点"
   sudo apt-get install -y nftables    # Debian、Ubuntu
   sudo dnf install -y nftables        # RHEL 系
   ```

2. 创建 drop-in，在已有的 `CAP_NET_BIND_SERVICE` 之外增加 `CAP_NET_ADMIN`：

   ```ini title="/etc/systemd/system/edgeweir-node.service.d/kernel-ban.conf"
   [Service]
   AmbientCapabilities=CAP_NET_BIND_SERVICE CAP_NET_ADMIN
   CapabilityBoundingSet=CAP_NET_BIND_SERVICE CAP_NET_ADMIN
   ```

3. 重新加载并重启：

   ```bash title="节点"
   sudo systemctl daemon-reload
   sudo systemctl restart edgeweir-node
   ```

4. 验证：`sudo nft list table inet edgeweir` 列出集合 `ban4` 与 `ban6`；`GET /api/v1/nodes/{id}` 的 `supportedFeatures` 含 `kernel-ban-v1`。

> [!NOTE]
> 环境能力同样被 agent 启动的 OpenResty 进程继承。

### 容器节点

1. 以构建参数 `NFT_CAPABILITY=true` 构建节点镜像。镜像为 `nft` 设置文件能力 `cap_net_admin+ep`，agent 仍以非 root 用户运行：

   ```bash title="edgeweir-node 源码目录"
   docker build --build-arg NFT_CAPABILITY=true -t edgeweir-node:nft .
   ```

2. 运行容器时加 `--cap-add NET_ADMIN`（Compose：`cap_add: [NET_ADMIN]`）。
3. 验证：`docker exec <容器> nft list table inet edgeweir` 列出集合 `ban4` 与 `ban6`；`GET /api/v1/nodes/{id}` 的 `supportedFeatures` 含 `kernel-ban-v1`。

### 节点前的负载均衡

集群的[访客 IP](../deploy/nodes.md#访客-ip) 设置决定 HTTP / HTTPS 监听的访客地址（`ip.src`）：

| 访客 IP | HTTP 层封禁、CC、规则、日志 | 内核封禁与连接数限制 |
| --- | --- | --- |
| 直连（默认） | TCP 对端；节点前有负载均衡时为负载均衡器的地址，自动封禁会把它整个封掉 | TCP 对端 |
| PROXY protocol | PROXY 头中的访客地址 | 仍只匹配 TCP 对端（负载均衡器），对访客地址的封禁不在内核生效 |
| 可信代理报头 | 可信代理报头中的访客地址；可信 CIDR 内的地址永不封禁，也不计入 CC 单 IP 计数 | 同上，只匹配 TCP 对端 |

后两种模式下，「封禁」页签上方显示「集群 {clusters} 的访客 IP 来自代理：内核封禁只匹配 TCP 对端」。直连模式下节点前仍有负载均衡时，把负载均衡器的地址加入全局放行名单：它们不会被封禁，也不会在内核被丢包。

[L4 应用](l4.md)在自己的监听上接受 PROXY 协议，与 HTTP / HTTPS 监听的访客 IP 设置无关。

## 连接数限制

在内核按客户端限制 TCP 连接，挡住单个地址的连接洪泛与慢速连接。在 **防护设置 → 连接限制** 按集群设置（有多个集群时先在「集群」中选择），随配置版本下发（可回滚，节点重启后按最近的配置恢复）。

| 设置 | 默认 | 行为 |
| --- | --- | --- |
| 启用 | 关 | 关闭时保留填写的值 |
| 每 IP 并发连接 | 256 | 一个客户端同时保持的连接数，超出的新连接被丢弃；0–100000，0 为不限 |
| 每 IP 每秒新建连接 | 50 | 一个客户端每秒新建的连接数，超出的被丢弃；0–100000，0 为不限。启用时两项不能都为 0（「至少设置一项限制」） |
| 突发 | 100 | 超过速率前可一次新建的连接数；0–1000000，0 等于每秒新建连接；不能小于每秒新建连接（「突发不能小于每秒新建连接」），每秒新建连接为 0 时只能为 0 |
| 端口 | 集群监听端口 | 「集群监听端口」：集群的 HTTP / HTTPS 监听与 TCP [L4 应用](l4.md)端口，随它们变化，「生效端口」显示节点实际限制的端口；「指定端口」：在「端口列表」中填写逗号分隔的端口或端口段（如 `80, 443, 10000-10999`），1–64 段，不能重叠 |

| 项目 | 行为 |
| --- | --- |
| 客户端 | IPv4 按地址，IPv6 按所在的 `/64` |
| 顺序 | 在 `inet edgeweir` 表中放行集合与封禁集合之后：全局放行名单、控制台与节点自身地址、回环地址不受限制 |
| 协议 | 只限 TCP，不限 UDP |
| 条件 | 与[内核封禁](#内核封禁)相同（`CAP_NET_ADMIN` 与 nftables），节点能力 `conn-limit-v1`。不满足时节点照常应用配置，卡片显示「{node} 未生效：{error}」；nftables 拒绝限制规则时（例如内核没有 `nft_connlimit`）封禁照常写入 |
| 状态 | 启用时卡片显示「N / M 个节点已生效」，旧版节点显示「节点版本过低：{nodes}」；`GET /api/v1/nodes/{id}` 的 `banStatus.connectionLimitsActive`、`connectionLimitsError` |
| 负载均衡 | 只匹配 TCP 对端：节点前有负载均衡时把它的地址加入全局放行名单，否则所有访客共用它的配额 |
| 审计 | `cluster.connection_limits_update`；配置版本原因「修改连接限制」 |

## API

路径位于 `/api/v1` 下。

| 过程 | 端点 | 说明 |
| --- | --- | --- |
| `bans.list` | `GET /bans` | 有效的封禁；查询参数 `scope`（`site` / `platform`）、`siteId`、`source`（`manual` / `auto` / `rule`）、`address`（IP 或 CIDR：覆盖它或在它之内的封禁）、`page`、`pageSize`（默认 50，最大 100） |
| `bans.create` | `POST /bans` | `scope` 为 `site` 时必须带 `siteId`，为 `platform` 时不能带；另需 `cidr`、`reason`（`abuse` / `attack` / `scanner` / `spam` / `other`）、`durationSeconds` |
| `bans.delete` | `DELETE /bans/{id}` | 解封手动、自动或规则封禁 |
| `greylist.list` | `GET /greylist` | 有效的灰名单条目与 `unsupportedNodes`；查询参数 `scope`、`siteId`、`address`、`page`、`pageSize` |
| `greylist.create` | `POST /greylist` | 同 `bans.create`，另需 `action`：`{"kind":"challenge","challenge":"js"}`（`cookie302` / `js` / `pow` / `captcha`）或 `{"kind":"rate_limit","requests":60,"windowSeconds":60}` |
| `greylist.delete` | `DELETE /greylist/{id}` | 移出灰名单 |
| `settings.bans`、`settings.setBans` | `GET`、`PUT /settings/bans` | `maxTotal`、`shareAutoBans` |
| `clusters.connectionLimits` | `GET /clusters/{clusterId}/connection-limits` | 集群的连接数限制、生效端口与节点状态 |
| `clusters.setConnectionLimits` | `PUT /clusters/{clusterId}/connection-limits` | `settings`：`enabled`、`perIp`、`newPerSecond`、`burst`、`ports`（`[{"start":80,"end":80}]`；`null` 为集群监听端口） |

只读 AccessKey 与演示账号只能调用 `GET` 接口，其余返回 403 `ACCESS_KEY_READ_ONLY` / `DEMO_READ_ONLY`；服务账号不能调用这些接口（403 `SERVICE_ACCOUNT_FORBIDDEN`）。字段与示例见 [API 与端点](../reference/api/security.md#封禁)。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「IP 地址或 CIDR 无效」 | 不是 IP 地址或 CIDR，或含前导零、zone ID | 改为标准写法 |
| 「前缀过短，最短为 /16」（或 `/48`） | 前缀短于下限 | 拆成更长的前缀，或改用 IP 名单 |
| 「封禁时长须在 1 分钟到 7 天之间」 | 到期时间超出范围 | 长期拦截改用 IP 名单 |
| 「封禁范围包含受保护的地址 …」 | 封禁包含节点地址、回环或未指定地址，或与全局放行名单重叠 | 缩小范围 |
| 「手动封禁已达上限（N 条）」 | 有效的手动封禁与灰名单条目达到上限 | 解封不再需要的地址，或调大 **防护设置 → 封禁 → 手动封禁上限** |
| 「请选择网站」 | 范围为「网站」但未选择网站 | 选择网站，或把范围改为「全局」 |
| 「封禁不存在或已失效」 | 封禁已到期或已解封 | 刷新列表 |
| 列表显示「N 个节点未生效」 | 节点封禁容量或内存不足 | 调大节点的 `--ban-capacity`、`--ban-dict-mb`，或减少封禁 |
| 封禁后仍能访问 | 节点缺少 `bans-v1`；地址在全局放行名单或集群可信代理中；网站封禁的地址在该网站的本站放行名单中 | 升级节点；用 [IP 检查](access-control.md#ip-检查) 查看该地址命中的名单与有效封禁 |
| 全局封禁没有在内核生效 | 节点缺少 `kernel-ban-v1`；访客 IP 不是「直连」 | 按[内核封禁](#内核封禁)授予 `CAP_NET_ADMIN` 并安装 nftables；见[节点前的负载均衡](#节点前的负载均衡) |
| 灰名单地址没有被挑战或限速 | 节点缺少 `greylist-v1`；地址在放行名单中；同一地址另有封禁（封禁优先）；规则放行或跳过了该动作 | 升级节点；检查放行名单与规则 |
| 灰名单挑战返回 503 | 挑战密钥的配置版本还未应用 | 等待版本应用，查看集群的版本状态 |
| 连接限制「未生效」 | 节点没有 `CAP_NET_ADMIN` 或 nftables，或内核拒绝规则（原因见提示） | 按[内核封禁](#内核封禁)启用；检查节点日志 |

# 统计与访问日志

流量统计与统计维度，访问日志的采样、查询、导出、保留期与存储，节点上的实时查看，以及调用接口的 AccessKey。

## 概念

| 术语 | 定义 |
| --- | --- |
| 统计 | 节点按分钟汇总的全量计数：请求数、流量、缓存命中、状态码，以及估算的热门 URL 和 IP。 |
| 访问日志 | 按采样率记录的单个请求。有上限的诊断数据，不是零丢失的审计记录。 |
| 采样率 | 被记录的请求比例；界面为百分比，API 为万分比整数（0–10000）。 |
| 拦截原因 | 节点拒绝或挑战请求的原因，如 `rule`、`ip_banned`、`region`，见[拦截原因](#拦截原因)。 |
| 统计维度 | 节点按分钟统计的有界分类：国家、运营商（ASN）、来源域名、浏览器 / 操作系统 / 设备、HTTP 与 TLS 版本、拦截原因、挑战。 |
| 统计模式 | 环境变量 `EDGEWEIR_ANALYTICS` 的取值：`lite`（PostgreSQL，默认）或 `clickhouse`；决定访问日志存在哪里。 |
| AccessKey | 以控制台账户的身份调用 `/api/v1` 的密钥（`ewk_` 前缀），见 [AccessKey](#accesskey)。 |

## 查看统计

| 位置 | 范围 |
| --- | --- |
| **概览**（`/overview`） | 全部网站与节点，含「请求最多的网站」「请求最多的节点」，见[概览](overview.md) |
| **网站** → 选择网站 →「统计」页签（`/sites/<网站 ID>?tab=analytics`） | 单个网站 |

1. 打开上表中的页面，选择时间范围：「过去 1 小时」「过去 6 小时」「过去 24 小时」「过去 7 天」「过去 30 天」。网站「统计」页签的范围写入地址参数 `range`（`1h`、`6h`、`24h`、`7d`、`30d`）。
2. 查看「请求总数」「数据传输」「缓存命中率」「带宽峰值」「4xx 占比」「5xx 占比」「状态码」「热门 URL（估算）」「热门 IP（估算）」；点击指标打开详情。网站「统计」页签另有「地区」「运营商（估算）」「来源（估算）」「终端」「协议」卡片，概览另有「流量最高的国家」（按数据传输），见[统计维度](#统计维度)。
3. 点击「刷新」重新读取。
4. 点击「自定义卡片」选择显示哪些卡片；网站「统计」页签的选择对所有网站生效，与概览分开保存，见[自定义卡片](overview.md#自定义卡片)。
5. 需要处理某一项时，点击该行右侧的「⋯」：热门 IP 可「封禁 IP」（网站「统计」页签中预填该网站，概览中预填「全局」范围）；网站「统计」页签的热门 URL 可「刷新 URL」，路径展开到网站的每个非泛域名，确认列出的 URL 后提交刷新任务。

时间窗固定、不选范围的读数：

| 位置 | 内容 |
| --- | --- |
| **概览** 的「此刻」 | 全部网站最近一个完整分钟的请求速率与出口带宽、过去 1 小时的缓存命中率，见[此刻](overview.md#此刻) |
| **网站** 列表的「24 小时请求」 | 每个网站过去 24 小时的请求数与趋势；只在网站不超过 20 个、列表未搜索或筛选时显示 |
| **网站** →「概览」页签的「实时请求」 | 已启用网站过去 1 小时每分钟的每秒请求数（正在统计的这一分钟不画），每分钟刷新；悬停读取某一分钟 |

### 统计数据

| 项目 | 行为 |
| --- | --- |
| 保留 | 分钟明细 7 天，小时汇总 90 天，天汇总 365 天；统计模式为 `clickhouse` 时，控制台图表和告警仍使用 PostgreSQL 中的汇总 |
| 迟到数据 | 迟到的分钟数据触发对应小时和天的重算；早于 7 天的数据被丢弃 |
| 汇总 | 后台任务每分钟增量汇总；UTC 边界固定；长期图表读取已完成的小时汇总和尚未汇总的明细 |
| 热门 URL / IP | 节点端有界的 Space-Saving 近似计数，界面标明「估算」：每个 worker 每分钟最多跟踪 128 个网站桶，每桶最多 32 个候选；每桶保留前 50 项；可能遗漏低频项，不用于计费 |
| URL 内容 | 不含查询字符串和请求头；超过 512 字节、含 `?` 或控制字符的路径不计入；路径本身仍可能包含业务标识 |
| 计数上限 | 单个节点、网站、时间桶的累计计数上限为 9,007,199,254,740,991（`Number.MAX_SAFE_INTEGER`），达到后保持该值 |
| 删除 | 删除节点保留网站的历史统计与日志；删除网站删除其统计和 PostgreSQL 中的日志 |

### 统计维度

| 位置 | 卡片 | 内容 |
| --- | --- | --- |
| 网站「统计」页签 | 「地区」 | 客户端国家的请求数与数据传输；GeoIP 查不到的地址记为「未知」 |
| | 「运营商（估算）」 | 客户端网络（AS 号与名称）的请求数，估算，至多 50 个 |
| | 「来源（估算）」 | `Referer` 的主机名（不含端口；与请求的 Host 相同时不计）的请求数，估算，至多 50 个 |
| | 「终端」 | 「浏览器」「操作系统」「设备」（按节点的 User-Agent 分类表） |
| | 「协议」 | 「HTTP 版本」（1.0、1.1、2、3）与「TLS 版本」（1.2、1.3、明文） |
| 网站「安全」页签 | 「拦截原因」 | 各[拦截原因](#拦截原因)的请求数 |
| | 「挑战通过率」 | 下发的挑战（挑战页与 cookie302 跳转）、验证通过后签发的通行凭证与两者之比 |
| 概览 | 「流量最高的国家」 | 全部网站按数据传输排列的国家 |

| 项目 | 行为 |
| --- | --- |
| 分类表 | 浏览器：Chrome、Edge、Firefox、Safari、Opera、三星浏览器、UC、QQ 浏览器、微信、Yandex、IE、爬虫、命令行工具、其他；操作系统：Windows、macOS、iOS、Android、Linux、ChromeOS、HarmonyOS、其他；设备：桌面、手机、平板、爬虫、其他。节点不使用大型 UA 解析库，分类按关键字判断，可能与浏览器的实际品牌不同 |
| 上限 | 每个网站每分钟：国家至多 250 个；运营商与来源域名各保留前 50（每个 worker 跟踪 64 个候选，近似计数）；其他维度的键固定 |
| 汇总与保留 | 与其他统计相同：分钟明细 7 天，小时汇总 90 天，天汇总 365 天 |
| 计入的请求 | 确定网站之后被拒绝的请求都计入统计（含客户端证书、封禁与维护模式的拒绝）；SNI 与 Host 不一致、PURGE 方法与未知域名不计入 |
| 节点 | 需要节点能力 `stats-dims-v1`（只用于统计，不阻止发布）；集群有活动节点缺少时卡片提示「集群中有节点不上报这些统计」 |
| 近似 | 节点按 worker 汇总、每分钟写一次；每个 worker 每分钟至多跟踪 128 个网站，worker 异常退出时丢失当前分钟的维度 |

### 上报与去重

| 项目 | 行为 |
| --- | --- |
| 批次 | 节点把统计批次和单调序号写入状态目录的 `traffic-spool.json`（0600），再经节点通道（mTLS）上报 |
| 去重 | 回执丢失、节点重启或本地回执写入失败时重发同一序号；控制台在一个事务内更新统计和该节点的游标，重复序号不重复计数；本地序号文件丢失时节点从控制台游标重新同步 |
| 离线队列 | 最多 10000 个桶、32 MiB；溢出时丢弃并记录日志 |
| 内存计数 | 未转存的计数 2 小时后过期；进程在首次持久化之前崩溃会丢失内存中的计数 |
| 语义 | 可重试批次的去重，不是计费级的逐请求 exactly-once |
| 旧节点 | 不带序号的旧版上报被拒绝；这类节点在 **集群与节点** 中显示「需要升级」 |

## 启用访问日志

页面：**网站** → 选择网站 →「日志」页签（`/sites/<网站 ID>?tab=logs`）。上方卡片是日志设置，下方是查询。

1. 在「访问日志采样率」中选择「关闭」「1%」「10%」或「100%」。选择后立即保存，发布网站所在集群的新配置版本（原因「修改网站 {site}」），提示「已保存」。
2. 按需打开「始终记录被拦截、挑战与鉴权失败的请求」「记录查询字符串」「记录直连对端地址」，在「记录请求头」中填写请求头名称，点击「保存」。只提交改动的项，同样发布新的配置版本。
3. 验证：产生请求后，在查询表单点击「查询」，列表出现记录。

| 字段 | 取值 | 默认值 | 作用 |
| --- | --- | --- | --- |
| 访问日志采样率 | 「关闭」/「1%」/「10%」/「100%」 | 「关闭」 | 记录请求的比例；API 的 `sampleRate` 接受 0–10000 的万分比整数 |
| 始终记录被拦截、挑战与鉴权失败的请求 | 开 / 关 | 关 | 有[拦截原因](#拦截原因)的请求不论采样率都写一条，采样率记为 100% |
| 记录查询字符串 | 开 / 关 | 关 | 日志带请求的查询字符串（不含 `?`，至多 2048 字节） |
| 记录请求头 | 至多 8 个请求头名称，以逗号或空格分隔；每个 1–64 个字符，只含字母、数字与 `-`，保存时转小写并去重 | 空 | 日志带这些请求头的值（每个至多 512 字节，多个值以 `, ` 连接）；不能选 `Authorization`、`Cookie`、`Proxy-Authorization` |
| 记录直连对端地址 | 开 / 关 | 关 | 访客 IP 来自 PROXY protocol 或可信报头（[访客 IP](../deploy/nodes.md#访客-ip) 的非直连模式）时，日志另带连接的对端地址；与客户端 IP 相同时不记录 |

| 项目 | 行为 |
| --- | --- |
| 生效 | 节点热更新网站表，不重载 nginx |
| 审计 | `site.logs_configure`（「修改访问日志采样率」），只记录改动的项 |
| 请求头错误 | 「不能记录 {name}」（禁止的请求头）、「请求头名称无效：{name}」、「最多 8 个请求头」，「保存」不提交 |
| 节点能力 | 后四项需要 `access-logs-v2`：集群有活动节点缺少时这些选项只能关闭，卡片提示「集群中有节点不支持」 |
| 隐私提示 | 卡片底部显示「日志保留 {days} 天，可能包含个人数据」，天数为当前统计模式的[保留期](#保留期) |

| 记录的字段 | 不记录 |
| --- | --- |
| 时间、客户端 IP、方法、Host、路径、状态码、发送字节、耗时（毫秒）、缓存状态、采样率、节点 ID、请求 ID；User-Agent（至多 512 字节）、Referer（不含查询字符串与片段，至多 1024 字节）、HTTP 版本、协议（http / https）、TLS 版本、国家、运营商（AS 号与名称）、请求字节、响应的 `Content-Type`（媒体类型）、回源地址、回源状态码与回源耗时（缓存命中与节点直接应答时为空）、拦截原因与触发它的规则 | Cookie、`Authorization`、请求和响应正文；查询字符串、其他请求头与直连对端地址只在网站开启对应选项时记录 |

客户端 IP、User-Agent、Referer、查询字符串与请求头可能属于个人数据：按需开启，保留期按需缩短（见[保留期](#保留期)）。

回源字段由节点的回源层给出：回源地址是应答的源站地址（重试时为最后一个；缓存重新验证（`REVALIDATED`）时不记录地址），回源状态码与耗时是节点到回源层的整个应答（包含重试）。查询字符串与请求头取客户端原样（去掉签名 URL 的签名之后、规则修改之前）；在此之前就被拒绝的请求（封禁、客户端证书）不记录查询字符串；网站有签名在路径中的 URL 鉴权（B、C 类）时，这类请求也不记录路径（日志为空，不计入热门 URL）。

国家与运营商由节点查询 GeoIP：每个 worker 缓存最近的地址，每秒至多 200 次未命中的查询，超出或 agent 无应答时记为未知。

强制记录与「写入访问日志」的记录规则共用每个节点每个网站每秒 100 条的额度，超出的只按采样率记录。网站采样率为「关闭」时，只要开启了强制记录，控制台照样保存这些日志（只保存带拦截原因的行）。

网站在「安全」页签的「挑战设置」卡片打开「访问日志记录 JA4」后，日志另记录 JA4 TLS 客户端指纹（明文 HTTP 为空），列表在请求下方显示「JA4」与指纹，CSV 有 `ja4` 列。关闭后控制台不再保存该字段。JA4 的格式见 [JA4](challenges.md#ja4)。

网站开启 [OWASP CRS](waf.md) 后，命中规则的请求另记录命中的规则 ID（每个请求最多 16 个，升序）与是否被拦截：列表在请求下方显示「CRS」（规则 ID 与「已拦截」标记），CSV 有 `wafRuleIds`（空格分隔）与 `wafBlocked` 列。

配置阶段的规则可用「日志采样率（%）」为匹配的请求设置采样率；网站采样率为「关闭」时，这些请求的日志同样保存，见[覆盖设置](rules.md#覆盖设置)。

自定义 WAF 阶段的「记录」规则打开「写入访问日志」后，匹配的请求不论采样率都写一条日志（每个节点每个网站每秒至多 100 条），日志带这些规则的 ID（至多 8 个）：列表在请求下方显示「规则」与规则名称（全局规则显示为「{name}（全局）」，已删除的规则显示 ID），CSV 有 `ruleIds` 列（空格分隔）。网站采样率为「关闭」时这些日志同样保存；因规则才写下的日志采样率记为 100%。见[WAF 动作](rules.md#waf-动作)。

启用访问日志需要节点能力 `access-logs-v1`，记录 JA4 另需 `ja4-v1`，强制记录与可选字段另需 `access-logs-v2`。配置回滚保留当前采样率与 JA4，日志选项只保留回滚目标与当前都开启的部分，不会重新启用已关闭的日志或字段。

### 拦截原因

| 原因 | 列表中的名称 | 何时 |
| --- | --- | --- |
| `ip_banned` | IP 封禁 | 封禁列表（控制台、自动与规则封禁）命中 |
| `ip_blocked` | 封锁名单 | 全局或网站的封锁名单 |
| `rule` | 自定义规则 | 自定义 WAF 规则的拦截、封禁、断开连接与 4xx / 5xx 自定义响应（带规则） |
| `rate_limit` | 限速 | 限速超额（带规则）、灰名单限速 |
| `crs` | OWASP CRS | CRS 拦截 |
| `cc` | CC 防护 | CC 防护的单 IP 封禁 |
| `challenge` | 挑战 | 下发挑战（Under Attack、CC 或规则；规则挑战带规则） |
| `auth` | 访问鉴权 | 访问鉴权拒绝（带鉴权规则） |
| `referer` | 防盗链 | 防盗链拒绝或跳转 |
| `user_agent` | UA 名单 | UA 名单拒绝 |
| `region` | 地区限制 | 地区限制 |
| `cors` | CORS 来源 | 跨域来源不允许 |
| `websocket_origin` | WebSocket 来源 | WebSocket 来源不允许 |
| `client_cert` | 客户端证书 | 网站要求客户端证书 |
| `maintenance` | 维护模式 | 维护模式 |
| `extension` | 扩展 | 节点扩展的裁决（规则 `ext:<id>`），或失败拒绝的扩展无法运行时的 503（[扩展](extensions.md)） |

原因由节点在拒绝处记录，与错误页的 `X-Edgeweir-Error` 对应（`ip-banned`、`ip-blocked`、`policy-denied`、`ip-greylisted`、`waf-blocked`、`geo-denied`、`hotlink-denied`、`ua-denied`、`cors-origin-denied`、`websocket-origin-denied`、`client-cert-required`、`maintenance`、`auth-*`，见[错误页](error-pages.md#设置网站错误页)）。强制 HTTPS 而没有证书的 503、WebSocket 关闭、请求体过大与未知域名不算拦截。

## 查询与导出日志

1. 在「日志」页签填写「开始时间」「结束时间」，按需填写「状态码」「客户端 IP」「路径前缀」「请求 ID」；其余条件在「更多筛选」中（有生效的条件时按钮显示「更多筛选（{count}）」）。
2. 点击「查询」。
3. 需要文件时点击「导出 CSV」。
4. 需要处理某条请求时，点击该行右侧的「⋯」，操作在当前页完成：

   | 操作 | 行为 |
   | --- | --- |
   | 封禁 IP | 打开封禁对话框，已填好本网站与客户端 IP；「范围」可改为「全局」，见[封禁](bans.md) |
   | 刷新 URL | 只在日志有 Host 时出现；确认后为该请求的 Host 与路径创建 URL 刷新任务，见[刷新与预热](origins-and-cache.md#刷新与预热) |
   | 排除 CRS 规则 N | 只在命中 CRS 规则的行出现，每条命中的规则一项；确认后把规则 ID 加入网站的整站排除，见[OWASP CRS](waf.md#排除)。初始化、拦截判定与关联类规则（901xxx、949xxx、959xxx、980xxx）不提供，排除它们等于关闭拦截 |
   | 按路径排除 | 同上，对话框已填好命中的规则 ID 与该请求的路径，可改为前缀或精确路径；确认后追加一个排除条目，见[按路径覆盖与排除](waf.md#按路径覆盖与排除) |

   完成后的提示带有链接，打开封禁列表、刷新任务或 CRS 设置。

列表列为「时间」「客户端 IP」「请求」「状态码」「字节」「耗时（毫秒）」「缓存」。有拦截原因的行在请求下方显示原因标记（挑战为灰色，其余为红色）与规则名称（已删除的规则显示 ID）；请求下方还显示「请求 ID」、「JA4」、「CRS」与「规则」（有值时）。点击行的任意位置（或请求前的箭头）展开「详情」：User-Agent、Referer、协议、国家/地区、运营商、回源（「地址 · 状态码 · 毫秒」）、请求字节、内容类型、查询字符串、请求头、直连对端以及节点扩展的日志字段与裁决，空字段不显示。

| 筛选 | 取值 | 匹配 |
| --- | --- | --- |
| 开始时间、结束时间 | 本地时间；默认开始为 1 小时前，结束为当前时间后 1 分钟；未修改「结束时间」时每次查询重新取当前时间后 1 分钟 | 开始 ≤ 时间 < 结束；结束须晚于开始，否则提示「结束时间必须晚于开始时间」 |
| 状态码 | 100–599 | 精确 |
| 客户端 IP | 至多 64 字符 | 精确 |
| 路径前缀 | 至多 2048 字符 | 前缀 |
| 请求 ID | 至多 128 字符 | 精确 |
| 「更多筛选」→「域名」 | 至多 253 字符 | Host 精确，不区分大小写 |
| 「方法」 | 「全部」、GET、HEAD、POST、PUT、PATCH、DELETE、OPTIONS | 精确 |
| 「状态码类别」 | 「全部」、1xx–5xx | 与「状态码」同时填写时两者都要满足 |
| 「缓存状态」 | 「全部」、HIT、MISS、BYPASS、EXPIRED、STALE、UPDATING、REVALIDATED | 精确 |
| 「拦截原因」 | 「全部」、「任何原因」或[拦截原因](#拦截原因)之一 | 「任何原因」匹配所有带拦截原因的日志 |
| 「国家/地区代码」 | 两位字母（ISO 3166-1） | 精确；不合法时提示「请输入两位国家/地区代码」 |
| 「ASN」 | 1–4294967295 | 精确；不合法时提示「须为 1 到 4294967295 之间的整数」 |
| 「User-Agent 包含」「Referer 包含」 | 各至多 256 字符 | 包含，不区分大小写 |
| 「最短耗时（毫秒）」 | 0–86400000 | 耗时不小于该值；不合法时提示「须为 0 到 86400000 之间的整数」 |
| 「客户端网段」 | CIDR 或单个地址，如 `203.0.113.0/24`，主机位清零 | 客户端 IP 在网段内；不合法时提示「网段格式无效」 |

| 项目 | 行为 |
| --- | --- |
| 条件 | 同时满足 |
| 时间范围 | 早于保留期第一天 UTC 零点（默认 6 天前）的部分与晚于当前时间后 5 分钟的部分不查询 |
| 请求 ID | 每条日志显示节点给出的请求 ID（与响应头 `X-Request-Id` 和[错误页](error-pages.md#请求-id)上的相同），CSV 的 `requestId` 列；更早的节点上报的日志为空 |
| 条数 | 界面最多显示 100 条，超出时提示「仅显示前 100 条，请缩小查询范围」；CSV 最多 1000 条，超出时提示「仅导出前 1000 条，请缩小时间范围」；按时间倒序 |
| CSV 文件 | `edgeweir-logs-<网站 ID>.csv`，UTF-8（带 BOM），CRLF 换行；使用最近一次「查询」的条件 |
| CSV 内容 | 每个单元格加双引号并转义引号；去掉前导空白后以 `=`、`+`、`-`、`@` 开头的值前加 `'`，避免被电子表格当作公式；数组以空格连接。列依次为 `time`、`clientIp`、`method`、`host`、`path`、`status`、`bytesSent`、`durationMs`、`cacheStatus`、`sampleRate`、`nodeId`、`requestId`、`ja4`、`wafRuleIds`、`wafBlocked`、`ruleIds`、`userAgent`、`referer`、`httpVersion`、`scheme`、`country`、`asn`、`asName`、`upstreamAddr`、`upstreamStatus`、`upstreamMs`、`requestBytes`、`contentType`、`tlsVersion`、`blockReason`、`blockRuleId`、`query`、`headers`（`名称: 值`，以 `; ` 连接）、`peerIp` |
| 演示账号 | 客户端 IP 与直连对端地址被缩减，不返回请求头 |

### 跳转参数

其他页面打开「日志」页签时把条件写在地址中，例如「攻击」页签的「查看日志」：

```text
/sites/<网站 ID>?tab=logs&blockReason=any&ip=203.0.113.7&from=2026-10-30T08:00:00.000Z&to=2026-10-30T09:01:00.000Z
```

| 参数 | 取值 | 填入 |
| --- | --- | --- |
| `blockReason` | [拦截原因](#拦截原因)之一或 `any` | 「拦截原因」 |
| `ip` | 至多 64 字符 | 「客户端 IP」 |
| `cidr` | 至多 64 字符 | 「客户端网段」 |
| `path` | 至多 2048 字符 | 「路径前缀」 |
| `from`、`to` | ISO 8601 时间 | 「开始时间」「结束时间」；省略 `to` 时结束为当前时间后 1 分钟并随查询更新 |

带「更多筛选」中的条件时该区域自动展开。页面打开后立即按这些条件查询。

## 日志的采集与存储

| 项目 | 行为 |
| --- | --- |
| 采集 | 节点通过 mTLS 按批次上报，每批最多 1000 条；控制台用每个节点的持久游标防止重试重复写入 |
| 入库过滤 | 网站采样率为「关闭」且没有采样或「写入访问日志」的规则时，只保存带拦截原因的行（开启强制记录时）或不保存；JA4、查询字符串、请求头与直连对端地址只在网站当前开启对应选项时保存；早于保留期或晚于当前时间 5 分钟的行丢弃 |
| 节点内存队列 | 约 2000 条（8 MiB）；满时新日志被丢弃 |
| 节点磁盘队列 | 状态目录的 `logs-spool.json`（0600），最多 10000 条、32 MiB；满时丢弃最旧的未发送批次并记录警告 |
| 丢失 | 请求结束到批次落盘之间，进程或主机崩溃会丢失日志 |
| `lite` 存储 | PostgreSQL 表 `access_log` 按 UTC 日期分区，保留今天及之前「保留天数 − 1」天；后台任务每分钟按设置建立与删除分区 |
| `clickhouse` 存储 | 表 `access_log`，按天分区的 ReplacingMergeTree，TTL 为保留天数，查询时用 `FINAL` 去重；ClickHouse 写入失败时不确认批次，节点重试，不改写入 PostgreSQL |

### 保留期

页面：**系统设置** →「通用」页签 →「访问日志」卡片。字段「保留天数」只显示当前统计模式的天数，另一种模式的天数保存时不变。

| 字段 | 取值 | 默认值 | 作用 |
| --- | --- | --- | --- |
| 保留天数（统计模式 `lite`） | 1–30 | 7 | PostgreSQL 保留今天及之前若干天 |
| 保留天数（统计模式 `clickhouse`） | 1–90 | 7 | ClickHouse `access_log` 的 TTL |

| 项目 | 行为 |
| --- | --- |
| 生效 | PostgreSQL：下一次每分钟维护删除更早的分区，写入与查询同时按新的天数；ClickHouse：保存时与控制台启动后的第一次维护执行 `ALTER TABLE access_log MODIFY TTL`，已有数据按新的 TTL 清理 |
| 不发布 | 修改保留期不发布配置版本 |
| 审计 | `system.log_retention_update`（「修改访问日志保留期」） |
| 统计 | 不受影响（分钟 7 天、小时 90 天、天 365 天） |

## 在节点上实时查看

在节点主机（或容器内）运行：

```bash
edgeweir-node accesslog --site <网站 ID> --json
```

| 选项 | 作用 |
| --- | --- |
| `--site <ID>` | 只看这个网站（1–128 个字母、数字、`_`、`-`）；省略时看全部请求（含未知域名，网站 ID 为空） |
| `--json` | 每行一个 JSON 对象（JSON Lines）；省略时为文本：时间（UTC）、客户端 IP、方法、Host、路径、状态码、发送字节、耗时、缓存状态，有拦截原因时追加 `blocked=<原因>` |
| `--control-socket <路径>`（简写 `--socket`） | 控制套接字，默认 `/run/edgeweir-node/control.sock` |

| 项目 | 行为 |
| --- | --- |
| 采集 | 只在有人查看时采集（命令每 250 毫秒续期一次，退出 5 秒后停止），不受采样率影响，不进入控制台的访问日志 |
| 上限 | 每个节点每秒至多 2000 条，记录保留 10 秒；读取不及时或超出上限时，标准错误输出提示漏掉的条数 |
| 内容 | [记录的字段](#启用访问日志)中除查询字符串、请求头与直连对端地址之外的字段 |
| 权限 | 需要能访问控制套接字（与 `edgeweir-node bans`、`security` 相同） |

按 Ctrl-C 退出。命令说明见 [CLI 参考](../reference/cli.md)。

## 使用 ClickHouse 存储

1. 在控制台的 `.env` 中启用 `analytics` profile，设置统计模式和 ClickHouse 密码：

   ```bash title=".env"
   COMPOSE_PROFILES=analytics
   EDGEWEIR_ANALYTICS=clickhouse
   EDGEWEIR_CLICKHOUSE_PASSWORD=<密码>
   ```

2. 启动 Compose 部署；`COMPOSE_PROFILES` 让此后的每条 `docker compose` 命令都包含 ClickHouse：

   ```bash
   docker compose up -d
   ```

3. 验证：**系统设置** 的「系统信息」中「统计模式」显示 `clickhouse`。

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `EDGEWEIR_ANALYTICS` | `lite` | `lite` 或 `clickhouse` |
| `EDGEWEIR_CLICKHOUSE_URL` | `http://clickhouse:8123` | `http` / `https`，不含账号、查询与片段 |
| `EDGEWEIR_CLICKHOUSE_DATABASE` | `edgeweir` | 字母或 `_` 开头，至多 64 个字母、数字或 `_` |
| `EDGEWEIR_CLICKHOUSE_USER` | `edgeweir` | |
| `EDGEWEIR_CLICKHOUSE_PASSWORD` | 空（`compose.yml` 中为 `edgeweir`） | 也可用 `EDGEWEIR_CLICKHOUSE_PASSWORD_FILE` 从文件读取 |

外部 ClickHouse 的配置见[环境变量](../reference/environment.md)。

| 项目 | 行为 |
| --- | --- |
| 切换 | 只影响新写入；不迁移历史日志和统计 |
| 分钟统计 | 同步写入 ClickHouse 的 `minute_stats` 表（ReplacingMergeTree，以节点批次序号为版本，TTL 7 天），直接分析时使用 `FINAL` |
| 图表与告警 | 仍使用 PostgreSQL 的精确分钟、小时、天汇总，两种模式计数口径一致；采样日志不用于统计全量流量 |
| 删除网站 | 控制台立即停止对该网站日志的查询授权；ClickHouse 中的原始数据按 `access_log` 的 TTL（保留天数）清除 |

## AccessKey

AccessKey（`ewk_` 开头）以控制台账户的身份调用 `/api/v1`，放在请求头 `x-api-key` 中。在用户菜单的 **个人设置** →「AccessKey」卡片中创建、编辑与吊销，见[个人设置](account.md#个人设置)；权限范围、每分钟请求数与错误码见 [API 参考](../reference/api.md#accesskey)。

```bash
curl -s -H 'x-api-key: <密钥>' \
  'https://console.example.com/api/v1/sites/<网站 ID>/logs?from=2026-10-30T00:00:00Z&to=2026-10-30T01:00:00Z&blockReason=any'
```

只读 AccessKey 可以读取日志设置、查询、导出与读取统计；修改采样率、日志选项与保留期需要读写 AccessKey。

## 接口

| 操作 | 过程 | 方法与路径（`/api/v1`） |
| --- | --- | --- |
| 读取网站的日志设置 | `logs.settings` | `GET /sites/{siteId}/logs/settings` |
| 修改采样率与日志选项 | `logs.configure` | `PUT /sites/{siteId}/logs/settings` |
| 查询日志 | `logs.query` | `GET /sites/{siteId}/logs` |
| 导出 CSV | `logs.export` | `GET /sites/{siteId}/logs/export` |
| 读取保留期 | `settings.logRetention` | `GET /settings/log-retention` |
| 修改保留期 | `settings.setLogRetention` | `PUT /settings/log-retention` |
| 流量曲线 | `analytics.traffic` | `GET /analytics/traffic` |
| 热门 URL / IP | `analytics.topRequests` | `GET /analytics/top-requests` |
| 请求最多的网站 / 节点 | `analytics.topSites`、`analytics.topNodes` | `GET /analytics/top-sites`、`GET /analytics/top-nodes` |
| 按网站、节点、状态码或拦截原因的趋势 | `analytics.breakdown` | `GET /analytics/breakdown` |
| 统计维度 | `analytics.dimensions` | `GET /analytics/dimensions` |

| 请求 / 响应 | 字段 |
| --- | --- |
| `GET /sites/{siteId}/logs/settings` | 响应 `sampleRate`、`storage`（`lite` / `clickhouse`）、`retentionDays`（当前模式的保留天数）、`logBlocked`、`logQuery`、`logHeaders`、`logPeer` |
| `PUT /sites/{siteId}/logs/settings` | 各字段都可省略，省略时保持原值：`sampleRate`（0–10000）、`logBlocked`、`logQuery`、`logPeer`、`logHeaders`；响应 `{ ok: true }` |
| `GET /sites/{siteId}/logs`、`/logs/export` | 必填 `from`、`to`（ISO 8601）；可选 `status`、`ip`、`path`、`requestId`、`host`、`method`、`statusClass`、`cacheStatus`、`blockReason`、`country`、`asn`、`ua`、`referer`、`minDuration`、`cidr`；`limit`（1–1000，默认 100）。查询响应 `{ entries, truncated }`，导出响应 `{ csv, truncated }` |
| `PUT /settings/log-retention` | `postgresDays`（1–30）、`clickhouseDays`（1–90），都必填；响应另带 `storage` |
| `analytics.*` | `range`（`1h`、`6h`、`24h`、`7d`、`30d`，默认 `24h`）；单个网站加 `siteId`（`analytics.topSites`、`analytics.topNodes` 除外） |

只读 AccessKey 只能调用 `GET`；服务账号不能调用这些过程（403 `SERVICE_ACCOUNT_FORBIDDEN`）。日志字段见 [API 参考](../reference/api/monitoring.md#访问日志)。

## 限制

| 项目 | 说明 |
| --- | --- |
| 采样率 | 界面只提供关闭、1%、10%、100%；其他比例通过 API 设置 |
| 日志保留 | PostgreSQL 至多 30 天、ClickHouse 至多 90 天；保留 30 天且采样率高时 PostgreSQL 占用较大，建议使用 ClickHouse |
| 完整性 | 访问日志有队列上限且可能丢失，不能作为审计账本；统计不是计费级精确计数 |
| 热门 URL / IP | 近似值，可能遗漏低频项 |
| 历史迁移 | 切换统计模式不迁移历史数据 |
| 统计维度 | 运营商与来源为近似值；终端分类按关键字判断 |
| 节点本地文件 | 节点不把访问日志写入本地文件；需要时用 `edgeweir-node accesslog` 实时查看 |

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「没有匹配的日志」 | 采样率为关闭或过低；时间范围早于保留期；节点未应用启用日志的版本或缺少 `access-logs-v1`；「更多筛选」的条件过窄 | 检查采样率、时间范围、筛选条件和节点「已应用版本」 |
| 被拦截的请求没有日志 | 没有开启「始终记录被拦截、挑战与鉴权失败的请求」，或超过每秒 100 条 | 开启该选项；超出部分只按采样率记录 |
| 日志选项不可用，提示「集群中有节点不支持」 | 集群有活动节点缺少 `access-logs-v2` | 升级节点，见[节点升级](node-upgrades.md) |
| 统计卡片提示「集群中有节点不上报这些统计」 | 集群有活动节点缺少 `stats-dims-v1` | 升级节点 |
| 国家、运营商为空或「未知」 | 节点没有 GeoIP 数据库，或客户端地址是内网地址 | 见[系统设置](system.md#geoip-数据库) |
| 「结束时间必须晚于开始时间」 | 时间范围无效 | 调整时间 |
| 「请输入两位国家/地区代码」「网段格式无效」等，「更多筛选」自动展开 | 筛选条件格式不对 | 修正标红的条件 |
| 「不能记录 {name}」「请求头名称无效：{name}」「最多 8 个请求头」 | 记录请求头的名称被禁止、格式不对或超过 8 个 | 修正请求头列表 |
| 「仅显示前 100 条，请缩小查询范围」 | 匹配超过 100 条 | 缩小时间范围或增加过滤条件，或导出 CSV |
| 「仅导出前 1000 条，请缩小时间范围」 | 匹配超过 1000 条 | 分段导出 |
| 统计图表为空 | 网站没有流量，或节点未上报 | 检查节点心跳和网站域名是否已发布 |
| 节点显示「需要升级」 | 节点不支持带序号的统计上报或当前配置要求的能力 | 升级节点，见[节点升级](node-upgrades.md) |
| 「网站不存在」（`SITE_NOT_FOUND`，404） | `siteId` 错误或网站已删除 | 检查网站 ID |
| 「输入有误」（`BAD_REQUEST`，400） | API 参数不合法：`from` / `to` 不是 ISO 8601 时间、`limit` 超过 1000、`sampleRate` 超出 0–10000、请求头名称不合法 | 按[接口](#接口)修正请求 |
| 「此密钥只有只读权限」（`ACCESS_KEY_READ_ONLY`，403） | 只读 AccessKey 调用了修改接口 | 使用读写 AccessKey |
| 「服务账号不能调用此接口」（`SERVICE_ACCOUNT_FORBIDDEN`，403） | 用服务账号 key 调用了日志或统计接口 | 改用 AccessKey |

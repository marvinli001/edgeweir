# 访问控制

网站的访问鉴权（Basic 认证、转发鉴权、URL 鉴权 A–D）与访问控制（本站名单、地区、CORS、防盗链、UA 名单、WebSocket 来源、安全响应头），以及 IP 检查。它们都在规则与缓存之前执行，缓存命中同样生效。

## 概念

| 术语 | 定义 |
| --- | --- |
| 鉴权规则 | 网站的一条访问鉴权设置：类型、范围与该类型的设置。每个网站最多 16 条，按顺序匹配。 |
| 范围 | 规则检查哪些请求：域名、路径前缀、扩展名与排除路径前缀，全部留空表示所有请求。 |
| Basic 认证 | 浏览器弹出登录框，按用户名与密码校验（RFC 7617）。 |
| 转发鉴权 | 节点把请求的部分请求头发给鉴权服务，按它的应答放行或拒绝。 |
| URL 鉴权 | 链接里带时间戳与签名，节点用密钥校验签名与有效期；常用于付费或限时的下载与视频。 |
| 签名 | `md5` 十六进制摘要（32 位小写），由路径、时间戳与密钥计算。 |
| 本站名单 | 网站选用的 IP 名单：本站拦截名单中的地址访问本网站返回 403；本站放行名单中的地址跳过本网站的部分检查。 |
| 访问控制 | 本页「本站名单」到「安全响应头」各节的设置，每项单独开关与保存。 |

## 添加规则

1. 打开 **网站 →（网站）→ 访问控制**。
2. 点击「添加规则」，选择「类型」，按下文填写范围与该类型的设置，点击「完成」。
3. 用上移、下移调整顺序，用开关启用或停用规则。
4. 点击「保存」。控制台发布新的配置版本（原因「修改网站 {site} 的访问鉴权」），节点热更新，不重载 nginx。

所在集群有活动节点不支持（缺少能力 `access-auth-v1`）时，页签显示「所在集群有节点不支持，暂时无法开启」，不能添加规则；已保存的规则仍可修改或删除。

## 范围与选择

| 字段 | 取值 | 匹配 |
| --- | --- | --- |
| 域名 | 网站的域名中勾选若干个；不选为全部 | 按该域名自己的写法匹配请求的 Host：`a.com` 整串相等，`*.a.com` 最左一级，`.a.com` 任意层级子域名，`~正则` 整串匹配 |
| 路径前缀 | 每行一个，以 `/` 开头，最多 32 个，每个 ≤ 1024 字节 | 路径以其中之一开头；留空不限 |
| 扩展名 | 逗号或空格分隔，最多 64 个，1–16 个小写字母或数字，不带点 | 路径最后一段的扩展名（与规则字段 `http.request.uri.path.extension` 相同，小写）；留空不限 |
| 排除路径前缀 | 同路径前缀 | 路径以其中之一开头时不检查 |

- 路径是 nginx 规范化后的路径（百分号已解码，与规则的 `http.request.uri.path` 相同）。URL 鉴权 B、C 按去掉两段签名之后的路径判断。
- **第一条命中范围的启用规则生效**，后面的规则不再看；停用的规则不下发到节点。
- 从网站移除的域名不再出现在范围里；范围的域名因此全部被移除时，规则作用于网站的所有域名（更多请求需要鉴权，而不是更少）。

## 执行顺序

| 顺序 | 步骤 |
| --- | --- |
| 1 | 探针健康端点、CDN-Loop、节点证书的 HTTP-01、按 Host 找网站、SNI 校验、客户端证书、动态封禁（全局封禁总是检查；网站封禁不检查本站放行名单中的地址）、PURGE 方法 |
| 2 | 选出鉴权规则；URL 鉴权解析并**去掉签名**（之后的维护模式、CC、规则、缓存键、刷新与回源都只看到去掉签名后的 URI） |
| 3 | 维护模式、CC 计数、`/.edgeweir/` 保留路径 |
| 4 | 全局放行与拦截名单 |
| 5 | [本站拦截名单](#本站名单) |
| 6 | [地区访问控制](#地区访问控制) |
| 7 | [CORS](#cors) 预检应答（预检先于鉴权：浏览器的预检不带凭据） |
| 8 | [防盗链](#防盗链) |
| 9 | [UA 名单](#ua-名单) |
| 10 | **鉴权**：明文 HTTP 请求且网站「强制 HTTPS」会跳转时先跳转（保留原 URL 与签名），凭据不经明文发送；然后按类型校验 |
| 11 | 规则阶段、CC 单 IP 封禁、Under Attack 与 CC 挑战、[WebSocket 来源](#websocket-来源与空闲超时)、缓存查找与回源 |
| 12 | 响应：[CORS](#cors) 响应头、[安全响应头](#安全响应头)，然后响应变换与压缩阶段的规则（规则可以改写或删除这两类头） |

ACME HTTP-01 验证请求、`/.edgeweir/` 保留路径与节点本地的预热请求不鉴权（预热签名 URL 时同样去掉签名，与正常请求落到同一个缓存对象），也不执行第 5–9 步与 WebSocket 来源检查；预热的响应同样添加响应头。配置规则对「强制 HTTPS」的覆盖在鉴权之后才运行，对选中鉴权规则的请求不起作用。

## Basic 认证

| 字段 | 取值 | 默认值 |
| --- | --- | --- |
| 认证域（realm） | 1–64 个字符，不含 `"`、`\` 与控制字符；随 `WWW-Authenticate` 发送 | 网站名 |
| 用户 | 1–100 个。用户名 1–64 个可打印 ASCII，不含 `:`；密码 8–128 个字符 | 一个 |
| 回源保留 Authorization | 开 / 关 | 关（删除） |
| 回源附加 X-Auth-User | 开 / 关；开启时总是覆盖访客自带的同名头 | 关 |

| 项目 | 行为 |
| --- | --- |
| 密码 | 只存加盐哈希：PBKDF2-HMAC-SHA256、16 字节随机盐、10000 次迭代，信封加密后入库，经节点通道下发；界面与 API 只返回用户名，密码栏显示「已保存，留空不修改」 |
| 修改 | 已有用户的密码留空保持不变；新用户和改了名的用户必须填写密码 |
| 失败 | 401、`WWW-Authenticate: Basic realm="…", charset="UTF-8"`、`X-Edgeweir-Error: auth-required`，正文是网站的 401 页面（没有时用「其他 4xx」页面，再没有时用内置页面）。401 页面设为跳转或改写状态码时，对 Basic 不生效（浏览器只在 401 时弹出登录框） |
| 通过后 | 默认从回源请求中删除 `Authorization`，请求照常缓存；保留时沿用原规则：带 `Authorization` 的请求只有缓存规则允许时才缓存 |
| 节点的缓存 | 校验结果在每个 worker 内缓存：成功 60 秒，失败 10 秒，按 `Authorization` 值的哈希与密钥版本区分；修改密码或删除用户后旧结果立即失效 |
| 失败限速 | 同一网站、同一客户端网络（IPv4 地址或 IPv6 /64）10 秒内第 11 次及以后的失败校验直接返回 429（`auth-rate-limited`，带 `Retry-After`），不计算哈希 |

验证：

```bash
curl -sI -H 'Host: www.example.com' http://<节点 IP>/admin/
curl -sI -u alice:<密码> -H 'Host: www.example.com' http://<节点 IP>/admin/
```

第一条返回 401 与 `WWW-Authenticate`，第二条返回 200。

## 转发鉴权

| 字段 | 取值 | 默认值 |
| --- | --- | --- |
| 鉴权地址 | `http://` 或 `https://` URL，≤ 2048 字符，主机为域名或 IP，不含账号与片段 | — |
| 方法 | GET / HEAD | GET |
| 超时（秒） | 0.1–10 | 5 |
| 转发的请求头 | 访客的请求头名称，逗号分隔，最多 16 个；不能是 `Host`、逐跳头与节点自己设置的五个头 | `authorization, cookie` |
| 复制到回源的响应头 | 鉴权应答的头名称，最多 8 个；不能是受保护头（同规则的请求头） | 空 |
| 结果缓存（秒） | 0（不缓存）–300 | 0 |
| 原样返回 3xx | 开 / 关 | 关 |
| 服务不可用时放行 | 开 / 关 | 关 |

节点发给鉴权服务的请求：

| 项目 | 内容 |
| --- | --- |
| 路径 | 经节点的回源层发出：与源站相同的地址策略（特殊用途地址不在[源站地址允许清单](system.md#源站地址允许清单)内一律拒绝）、DNS 解析与 TLS 证书校验 |
| 请求头 | 转发列表中的访客请求头，以及 `X-Original-URI`（访客的原始请求 URI，含签名与查询串）、`X-Original-Method`、`X-Original-Host`、`X-Real-IP`（访客 IP，同规则的 `ip.src`）、`X-Forwarded-For`（与回源相同）；其他请求头一律不发送 |
| 请求体 | 不发送 |

| 鉴权应答 | 节点的处理 |
| --- | --- |
| 2xx | 放行；「复制到回源的响应头」中鉴权应答带的头写入回源请求，没有带的头从回源请求中删除（访客不能自带） |
| 401、403 | 原样返回状态码、`WWW-Authenticate`、`Content-Type` 与正文（正文超过 64 KiB 时改用网站的错误页），`Cache-Control: no-store`、`X-Edgeweir-Error: auth-denied` |
| 3xx | 开启「原样返回 3xx」时返回状态码与 `Location`（登录跳转），否则按拒绝处理 |
| 其他 4xx | 403（错误页，`auth-denied`） |
| 5xx、连接失败、超时、地址被拒 | 服务不可用：503（错误页，`auth-unavailable`）；开启「服务不可用时放行」时请求不经鉴权继续处理。节点每条规则每 60 秒最多写一条 NOTICE 级 nginx 错误日志（网站 ID、规则 ID 与状态码） |

> [!WARNING]
> 结果缓存的键只有转发的请求头（名称与值），不含路径与访客 IP。鉴权服务按路径或 IP 决定时不要开启结果缓存。只缓存 2xx 与 401 / 403。

## URL 鉴权 A–D

| 类型 | URL 形式 | 签名 |
| --- | --- | --- |
| A | `路径?sign=时间戳-随机串-签名` | `md5(路径@时间戳@随机串@密钥)` |
| B | `/时间戳/签名/路径` | `md5(路径@时间戳@密钥)` |
| C | `/签名/时间戳/路径` | `md5(路径@时间戳@密钥)` |
| D | `路径?sign=签名&t=时间戳` | `md5(路径@时间戳@密钥)` |

| 字段 | 取值 | 默认值 |
| --- | --- | --- |
| 主密钥 | 16–128 个可打印 ASCII（不含空格）；「生成」在浏览器中生成 32 个字母数字 | — |
| 备用密钥 | 同主密钥；轮换期间两把都接受 | 无 |
| 有效期（秒） | 1–31536000 | 1800 |
| 允许时钟偏差（秒） | 0–600 | 300 |
| 签名参数名（A、D） | 1–32 个字母、数字、`_` 或 `-` | `sign` |
| 时间参数名（D） | 同上，不能与签名参数名相同 | `t` |

| 项目 | 行为 |
| --- | --- |
| 路径 | 访客请求的原始路径：请求行中 `?` 之前的部分，百分号编码保持原样；B、C 为去掉两段之后的部分（必须以 `/` 开头） |
| 时间戳 | 十进制 Unix 秒（1–12 位）；在 `时间戳 − 偏差` 到 `时间戳 + 有效期 + 偏差` 之间有效 |
| 签名、随机串 | 签名 32 位小写十六进制；随机串（A）1–64 个字母或数字 |
| 参数 | 同名参数出现多次时取第一个，去签名时全部删除；参数值不解码 |
| 比较 | 主、备两把密钥都计算，与签名做常数时间比较 |
| 去签名 | A、D 从查询串中删除签名参数，其他参数保持顺序；B、C 去掉两段路径。缓存键、刷新匹配、规则与回源只看到去掉签名后的 URI，所以同一对象的不同签名命中同一份缓存 |
| B、C 的规范化 | nginx 规范化后的路径也必须以这两段开头（例如 `/1661824870/<签名>/a/../b` 规范化为 `/1661824870/<签名>/b`，去掉后为 `/b`）；否则视为没有签名 |
| 失败 | 403 与网站的错误页：签名缺失、格式错误或不符为 `auth-denied`，过期或时间戳超前为 `auth-expired` |
| 密钥 | 信封加密后入库，经节点通道下发，界面与 API 只告诉你是否已设置；生成的密钥只在对话框中显示一次，保存前请复制 |

示例：密钥 `123456`、时间戳 `1661824870`、随机串 `c6d1a57067b21f7b`、路径 `/images/test.jpg`：

```text
A  /images/test.jpg?sign=1661824870-c6d1a57067b21f7b-0baac47b6c2ad519bb1bfe7babff37a3
B  /1661824870/64bf8671521f2a61a3b64691fde82729/images/test.jpg
C  /64bf8671521f2a61a3b64691fde82729/1661824870/images/test.jpg
D  /images/test.jpg?sign=64bf8671521f2a61a3b64691fde82729&t=1661824870
```

在自己的应用中生成（D）：

```bash
ts=$(date +%s); path=/images/test.jpg
sign=$(printf '%s@%s@%s' "$path" "$ts" "$KEY" | openssl md5 | awk '{print $NF}')
echo "https://www.example.com${path}?sign=${sign}&t=${ts}"
```

### 在控制台生成签名 URL

1. 在规则列表中点击 URL 鉴权规则右侧的链接图标「生成签名 URL」（有未保存的修改时先保存）。
2. 填写路径（以 `/` 开头）或网站域名的 `http(s)` 网址，以及有效期（1 秒至规则的有效期，默认规则的有效期）。
3. 点击「生成」。控制台用规则的主密钥计算并显示签名 URL 与过期时间；不保存、不下发。要让链接恰好在 P 秒后过期，控制台把时间戳设为 `现在 − (规则有效期 − P)`。

每次生成写审计 `site.auth_sign_url`（规则、路径与过期时间，不含签名）。

## 本站名单

1. 先在 **IP 名单** 创建名单（任何动作都可以，见 [IP 名单](rules.md#ip-名单)）。
2. 打开 **网站 →（网站）→ 访问控制**，在「本站名单」卡片选择「拦截名单」与「放行名单」（各最多 16 份），点击「保存」。

| 项目 | 行为 |
| --- | --- |
| 本站拦截名单 | 访客地址（`ip.src`）在其中任一份名单中时返回 403（`X-Edgeweir-Error: ip-blocked`），只作用于本网站；全局放行名单与本站放行名单中的地址除外 |
| 本站放行名单 | 跳过本站拦截名单、本网站的封禁（含 CC 单 IP 自动封禁）、地区、防盗链、UA 名单，以及 Under Attack 与 CC 挑战 |
| 不豁免 | 全局拦截名单、全局封禁、CORS、WebSocket 来源、鉴权、规则与维护模式 |
| 同一名单 | 不能同时作为本站拦截名单与放行名单（「同一名单不能同时作为本站拦截与放行名单：…」） |
| 名单修改 | 名单的条目修改后，所有选用它的网站一起生效 |
| 删除名单 | 被网站选为本站名单的名单不能删除，提示「IP 名单正在被使用：…」并列出网站名 |

## 地区访问控制

在「地区访问控制」卡片打开开关，选择模式并填写列表，点击「保存」。

| 字段 | 取值 | 默认值 |
| --- | --- | --- |
| 模式 | 仅拒绝：命中列表的访客返回 403；仅允许：不命中列表的访客返回 403 | 仅拒绝 |
| 国家 / 地区 | ISO 3166-1 二位代码，每行一个，最多 256 个 | 空 |
| 一级行政区 | `国家-行政区`，行政区为 `ip.geoip.subdivision` 的取值（City MMDB 的代码，没有代码时为英文名称），例如 `US-CA`；比较时 ASCII 不区分大小写；最多 256 个 | 空 |
| ASN | 1–4294967295，最多 256 个 | 空 |
| 生效路径前缀 | 每行一个，最多 32 个；留空为全部路径 | 空 |
| 例外路径前缀 | 以其中之一开头的路径不检查，最多 32 个 | 空 |

| 项目 | 行为 |
| --- | --- |
| 命中 | 国家在列表中、`国家-行政区` 在列表中，或 ASN 在列表中，任一即命中 |
| 没有记录 | GeoIP 没有该地址的记录时（国家为空、ASN 为 0）不命中任何条目：「仅允许」时返回 403 |
| 拒绝 | 403，网站的 403 错误页，`X-Edgeweir-Error: geo-denied` |
| GeoIP 不可用 | 与规则相同返回 503（`X-Edgeweir-Error: policy-unavailable`）；只有生效范围内的请求查询 GeoIP |
| 数据 | 节点本地的 MMDB，见[配置 GeoIP 数据库](rules.md#配置-geoip-数据库)；一级行政区需要 City MMDB |

## CORS

在「CORS」卡片打开开关，填写允许的来源等，点击「保存」。

| 字段 | 取值 | 默认值 |
| --- | --- | --- |
| 允许的来源 | `https://a.com`、`https://a.com:8443`、`https://*.a.com`（下一级子域名）或单独的 `*`，每行一个，最多 100 个；保存时 scheme 与主机名转为小写，去掉默认端口 | 空（开启时至少一个） |
| 允许凭据 | 开启后响应带 `Access-Control-Allow-Credentials: true`，`Access-Control-Allow-Origin` 一律回显请求的 `Origin`；来源不能用 `*` | 关 |
| 允许的方法 | 最多 16 个，按填写顺序输出 | GET、HEAD、POST、PUT、PATCH、DELETE、OPTIONS |
| 允许的请求头 | 列表（最多 64 个），或「回显预检请求的头」 | 空 |
| 暴露的头 | 最多 64 个 | 空 |
| Max-Age（秒） | 0–86400 | 600 |
| 预检交给源站 | 开启后预检照常回源，不在边缘应答；来源允许时源站的应答同样带上完整的预检头（方法、请求头、Max-Age 与 `Vary`），开启「保留源站的 CORS 头」且源站已给出 `Access-Control-Allow-Origin` 时除外 | 关 |
| 保留源站的 CORS 头 | 开启后源站响应已有 `Access-Control-Allow-Origin` 时不改动任何 `Access-Control-*` 头 | 关 |
| 生效路径前缀 | 最多 32 个；留空为全部路径 | 空 |

| 项目 | 行为 |
| --- | --- |
| 来源匹配 | 请求的 `Origin` 规范化（小写、去掉默认端口）后与列表比较；`*.a.com` 只匹配下一级子域名；`null` 与无法解析的 `Origin` 不匹配（`*` 除外） |
| 预检 | `OPTIONS` 且带 `Origin` 与 `Access-Control-Request-Method`：来源允许时节点直接返回 204，带 `Access-Control-Allow-Origin`（及凭据头）、`Access-Control-Allow-Methods`、`Access-Control-Allow-Headers`、`Access-Control-Max-Age`、`Vary: Origin, Access-Control-Request-Method, Access-Control-Request-Headers` 与 `Cache-Control: no-store`，不回源；来源不允许时返回 403（`X-Edgeweir-Error: cors-origin-denied`） |
| 其他响应 | 缓存命中、回源响应与节点生成的响应（错误页、跳转）：默认删除源站的 `Access-Control-*` 头；请求带有允许的 `Origin` 时添加 `Access-Control-Allow-Origin`（及凭据头）与 `Access-Control-Expose-Headers` |
| `Vary` | 生效范围内的响应一律在 `Vary` 中加入 `Origin`（已有 `Origin` 或 `*` 时不加），即使请求不带 `Origin`；缓存中的对象不按 `Origin` 区分 |
| 与规则 | 响应头规则在 CORS 之后执行，可以改写这些头 |

## 防盗链

在「防盗链」卡片打开开关，按需修改来源与范围，点击「保存」。

| 字段 | 取值 | 默认值 |
| --- | --- | --- |
| 允许空来源 | 请求没有 `Referer`（开启「同时检查 Origin」时也没有 `Origin`）时放行 | 开 |
| 允许本站域名 | `Referer` 的主机由本网站服务（精确、泛、后缀与正则域名都算）时放行 | 开 |
| 允许的来源 | `a.com`（精确）、`*.a.com`（下一级）、`.a.com`（任意层级子域名，不含 `a.com`）或单独的 `*`（任意），每行一个，最多 200 个 | 空 |
| 禁止的来源 | 同样写法，最多 200 个；命中即拒绝，优先于允许的来源与本站域名 | 空 |
| 同时检查 Origin | 请求带 `Origin` 时同样检查它 | 关 |
| 生效扩展名 | 最多 64 个 | 常见图片、音视频与下载类型（jpg、png、webp、mp4、m3u8、zip、apk、pdf 等 49 个） |
| 生效路径前缀 | 最多 32 个 | 空 |
| 排除路径前缀 | 最多 32 个 | 空 |
| 动作 | 403（错误页）或 302 跳转到指定地址（本站路径或 `http(s)` URL，最长 2048 字符） | 403 |

| 项目 | 行为 |
| --- | --- |
| 生效范围 | 扩展名与路径前缀都为空时为全部请求；否则扩展名在列表中或路径以某个前缀开头；再去掉排除前缀下的请求 |
| 解析 | 只接受 `http://` 或 `https://` URL：取主机名（小写，去掉账号、端口与末尾的 `.`）；无法解析的 `Referer`（如 `android-app://…`、`Origin: null`）视为不允许，即使开启了「允许空来源」 |
| 判定 | 取到的每个值都必须允许：先看禁止的来源，再看本站域名与允许的来源 |
| 拒绝 | 403，`X-Edgeweir-Error: hotlink-denied`；或 302，带 `Cache-Control: no-store` 与同样的 `X-Edgeweir-Error` |
| 跳转目标 | 目标是本站路径时，请求该路径本身不检查；目标是本网站的完整 URL 且落在生效范围内时会循环跳转，放进排除路径前缀 |
| 局限 | 访客或浏览器可以去掉 `Referer`（例如 `Referrer-Policy: no-referrer`）；需要阻止这类请求时关闭「允许空来源」 |

## UA 名单

在「UA 名单」卡片添加条目（模式与「允许」或「拒绝」），点击「保存」。没有条目时不检查。

| 字段 | 取值 |
| --- | --- |
| 模式 | 与规则的 `wildcard` 运算符相同：整串匹配，`*` 匹配零个或多个字节（至多 8 个），`\*`、`\\` 表示字面量；ASCII 不区分大小写；最长 512 个可打印 ASCII 字符；空模式匹配空 UA 与没有 UA |
| 条目数 | 最多 200 条，保持填写顺序 |
| 生效路径前缀、排除路径前缀 | 各最多 32 个 |

| 项目 | 行为 |
| --- | --- |
| 判定 | 命中任一「允许」条目即放行，不再检查「拒绝」条目；否则命中任一「拒绝」条目返回 403（`X-Edgeweir-Error: ua-denied`） |
| 子串 | 包含某个词写作 `*关键词*`，例如 `*curl*` |
| 只允许名单中的 UA | 再加一条「拒绝」`*` |
| 多个 User-Agent 头 | 以 `, ` 连接后匹配，与 `http.user_agent` 相同 |

## WebSocket 来源与空闲超时

在「WebSocket」卡片选择「允许所有来源」或填写来源列表，按需修改空闲超时，点击「保存」。网站的 WebSocket 开关在「源站」页签，见 [WebSocket](origins-and-cache.md#websocket)。

| 字段 | 取值 | 默认值 |
| --- | --- | --- |
| 来源 | 允许所有来源，或来源列表（写法同 CORS，不能用单独的 `*`，最多 100 个） | 允许所有来源 |
| 空闲超时（秒） | 60–86400 | 3600 |

| 项目 | 行为 |
| --- | --- |
| 拒绝 | 升级请求没有 `Origin`、`Origin` 无法解析或不在列表中时返回 403（`X-Edgeweir-Error: websocket-origin-denied`）；本站放行名单不豁免 |
| 空闲超时 | 升级后的连接空闲这么久后关闭；配置规则的「回源发送超时」「回源读取超时」覆盖仍然优先 |

## 安全响应头

在「安全响应头」卡片打开需要的项，点击「保存」。

| 字段 | 响应头 |
| --- | --- |
| 禁止 MIME 嗅探 | `X-Content-Type-Options: nosniff` |
| X-Frame-Options | 不设置 / `DENY` / `SAMEORIGIN` |
| Referrer-Policy | 不设置，或 `no-referrer`、`no-referrer-when-downgrade`、`origin`、`origin-when-cross-origin`、`same-origin`、`strict-origin`、`strict-origin-when-cross-origin`、`unsafe-url` |
| Permissions-Policy | 填写值（最长 1024 个可打印 ASCII 字符），留空不设置 |
| 隐藏 Server | 删除 `Server` 响应头 |
| 删除 X-Powered-By | 删除源站的 `X-Powered-By` |

设置的头替换源站响应中的同名头，作用于缓存命中、回源响应与节点生成的响应。响应变换阶段的规则在它之后执行：规则设置或删除同名头时以规则为准。

## IP 检查

**网站 →（网站）→ 访问控制 → IP 检查**（固定为本网站），或 **IP 名单 → IP 检查**（可选网站）：输入 IP 地址，点击「检查」。

| 结果 | 内容 |
| --- | --- |
| 结论（选了网站时） | 按执行顺序第一个起作用的步骤：全局封禁、网站封禁、全局拦截名单、本站拦截名单，或被全局 / 本站放行名单豁免，或「没有命中」（继续地区、防盗链等检查） |
| 名单 | 含有该地址的每份 IP 名单、命中的条目、名单动作，以及是否为本网站的本站拦截或放行名单 |
| 封禁 | 覆盖该地址的有效封禁（选了网站时只列全局封禁与本网站的封禁） |
| 访客 IP | 每个集群（选了网站时为其集群）的访客 IP 方式，该地址是否为可信代理（可信代理报头模式）或节点地址 |

IPv4 映射的 IPv6 地址（`::ffff:a.b.c.d`）按 IPv4 地址检查，与节点相同。控制台没有 GeoIP 数据库，IP 检查不判断地区访问控制。

## 失败统计与错误码

被鉴权拒绝的请求（401、403、429、503，包括浏览器第一次不带凭据的 401）按网站与分钟计数，网站「安全」页签的「鉴权失败」卡片显示所选时间范围内的次数（`GET /sites/{id}/auth-rules/failures`）。放行的请求（包括服务不可用时放行）不计。

| `X-Edgeweir-Error` | 状态码 | 原因 |
| --- | --- | --- |
| `auth-required` | 401 | Basic：没有凭据或凭据错误 |
| `auth-denied` | 403（转发鉴权也可能是 401 或 3xx） | URL 鉴权签名缺失或不符；转发鉴权拒绝 |
| `auth-expired` | 403 | URL 鉴权签名过期或时间戳超前 |
| `auth-rate-limited` | 429 | Basic 失败限速 |
| `auth-unavailable` | 503 | 鉴权服务不可用 |

访问控制的拒绝不计入「鉴权失败」：

| `X-Edgeweir-Error` | 状态码 | 原因 |
| --- | --- | --- |
| `ip-blocked` | 403 | 本站拦截名单 |
| `geo-denied` | 403 | 地区访问控制 |
| `cors-origin-denied` | 403 | CORS 预检的来源不允许 |
| `hotlink-denied` | 403 | 防盗链 |
| `ua-denied` | 403 | UA 名单 |
| `websocket-origin-denied` | 403 | WebSocket 来源 |

## 安全与审计

| 项目 | 行为 |
| --- | --- |
| 存储 | 密码哈希与签名密钥用 `EDGEWEIR_MASTER_KEY` 信封加密（绑定规则）；主密钥轮换时一起重新加密 |
| 下发 | 只下发给网站所在集群的节点，经 mTLS 节点通道；节点存在状态目录（`credentials.json`，0600），配置版本里只有引用 |
| 不出现的地方 | 配置版本、快照、审计、日志与 API 响应 |
| 审计 | `site.auth_update`：每条规则的类型、启用、用户数或密钥数、是否更换（不含用户名以外的凭据）；`site.auth_sign_url`；`site.access_control_update`：修改了哪些项及其开关与条目数（不含来源、模式等列表内容）；配置版本原因「修改网站 {site} 的访问控制」 |

## 节点要求

| 项目 | 要求 |
| --- | --- |
| 鉴权规则 | 节点能力 `access-auth-v1`；集群有活动节点不支持时界面不能开启，服务账号与后台任务的发布返回 `NODE_CAPABILITY_REQUIRED`，缺少能力的节点保留 last-known-good 配置 |
| 热更新 | 规则、用户与密钥热更新；节点升级到支持的版本时 nginx 配置新增一个共享字典与一个内部 location（一次结构性重载，不中断已有连接） |
| 访问控制 | 节点能力 `access-control-v1`（任一项开启或选了本站名单时）；地区访问控制有国家或行政区时另需 `geoip-city-v1`，有行政区时控制台另外检查 `geoip-subdivision-v1`，有 ASN 时另需 `geoip-asn-v1`。集群有活动节点不支持时卡片显示「所在集群有节点不支持，暂时无法开启」，服务账号与后台任务的发布返回 `NODE_CAPABILITY_REQUIRED`。没有任何访问控制设置的网站配置与之前逐字节相同 |
| 访问控制热更新 | 全部设置热更新，不重载 nginx；节点升级到支持的版本时，边缘层到回源层一跳的超时改为 86400 秒以容纳更长的 WebSocket 空闲超时（一次结构性重载，不中断已有连接） |

## API

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/sites/{id}/auth-rules` | 规则（不含密码哈希与密钥） |
| PUT | `/sites/{id}/auth-rules` | 整体替换；带 `id` 的规则沿用其密码与密钥，见 [API](../reference/api.md) |
| POST | `/sites/{id}/auth-rules/{ruleId}/sign` | 生成签名 URL |
| GET | `/sites/{id}/auth-rules/failures` | 被拒绝的请求数 |
| GET | `/sites/{id}/access-control` | 访问控制的全部设置 |
| PATCH | `/sites/{id}/access-control` | 只修改请求中出现的项（`siteLists`、`hotlink`、`userAgents`、`cors`、`geo`、`websocket`、`securityHeaders`），见 [API](../reference/api.md) |
| GET | `/ip-check?ip=…&siteId=…` | IP 检查 |

只读 AccessKey 只能调用 `GET`；服务账号不能调用这些接口（`SERVICE_ACCOUNT_FORBIDDEN`）。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 所有请求都是 401 / 403 | 规则的密钥没有下发到节点（节点日志 `access authentication rule … unavailable; its requests are refused`）或范围过大 | 确认节点在线且版本支持；缩小范围或调整规则顺序 |
| 签名正确仍 403 `auth-expired` | 节点与签名方时钟不一致，或时间戳用了毫秒 | 校准时钟，时间戳用秒；适当调大允许时钟偏差 |
| 签名正确仍 403 `auth-denied` | 签名用的路径与访客实际请求的路径不同（例如中文路径未编码或编码大小写不同）；参数名不对 | 用访客实际发送的、已百分号编码的路径计算；核对参数名 |
| 浏览器不弹登录框 | 网站的 401 页面是跳转 | Basic 已忽略跳转；检查是否被其他鉴权规则先命中 |
| 转发鉴权总是 503 | 鉴权地址是内网地址而不在源站允许清单、DNS 解析失败或超时 | 在系统设置的源站允许清单中加入该网段；检查地址与超时 |
| 登录后仍被要求登录 | 结果缓存缓存了 401 | 调小或关闭结果缓存 |
| 「同一名单不能同时作为本站拦截与放行名单：…」 | 同一份名单选在了两边 | 从其中一边移除 |
| 「允许凭据时来源不能用 *」 | CORS 开启了允许凭据而来源有 `*` | 列出具体来源，或关闭允许凭据 |
| 浏览器报 CORS 错误，响应没有 `Access-Control-Allow-Origin` | 请求的 `Origin` 不在允许的来源中（`*.a.com` 不匹配 `a.com` 与多级子域名），或路径不在生效范围 | 补充来源或调整生效路径前缀 |
| 图片在自己的页面上也 403 `hotlink-denied` | 页面的主机不由本网站服务且不在允许的来源中，或页面设置了 `Referrer-Policy: no-referrer` 而「允许空来源」关闭 | 把页面域名加入允许的来源；开启允许空来源 |
| 所有请求 503 `policy-unavailable` | 地区访问控制开启时节点的 GeoIP 服务不可用 | 检查节点 GeoIP 配置，见[配置 GeoIP 数据库](rules.md#配置-geoip-数据库) |
| WebSocket 连接 403 `websocket-origin-denied` | 来源不在列表中，或客户端没有发送 `Origin` | 补充来源；非浏览器客户端发送一个允许的 `Origin` |
| 设置的安全头没有出现或值不同 | 响应变换阶段的规则改写或删除了它 | 检查网站规则与全局规则 |

# 管理多个网站

用标签给网站分组，在网站列表里一次处理多个网站，把一个网站的设置复制到其他网站，或以一个网站为模板克隆出新网站。复制与克隆都是一次性的：之后修改源网站，不会改动复制或克隆出来的网站。

## 概念

| 术语 | 定义 |
| --- | --- |
| 标签 | 网站的分组名称，1–32 个字符，不区分大小写（`Prod` 与 `prod` 是同一个标签，显示第一次写下的写法）。每个网站最多 10 个。标签只在控制台使用，不下发到节点，修改标签不产生配置版本。 |
| 批量操作 | 在网站列表选中若干网站后执行的启用、停用、清除缓存、添加标签、移除标签、复制设置与删除，一次最多 100 个网站。 |
| 复制设置 | 把源网站选中部分的设置写到目标网站，替换目标的这些设置。 |
| 部分 | 复制设置的单位，见「可以复制的部分」。 |
| 克隆 | 以源网站的全部设置和源站新建一个网站，填写新的名称与域名。 |

## 标签

- **添加或修改**：打开 **网站 →（网站）→ 概览**，在「标签」一行点击编辑按钮，输入名称后按回车（或逗号），点击「保存」。输入时会提示已有的标签。新建网站与克隆网站时也可以填写标签。
- **筛选**：在 **网站** 列表点击筛选栏的「标签」，勾选一个或多个标签，选择「含任一标签」或「含全部标签」。点击网站名下方的标签，只看带这个标签的网站。搜索框也按标签名搜索。
- **在命令面板中**：按 ⌘K（Windows / Linux 为 Ctrl+K）输入标签名，选择「标签：…」打开按该标签筛选的列表。
- **改名与删除**：点击筛选栏的「管理标签」。改名为另一个已有标签的名称（不区分大小写）时，两个标签合并为一个。删除标签会从所有网站上移除它。没有网站使用的标签会保留在这里，直到删除。

## 批量操作

1. 在 **网站** 列表勾选网站（表头的选择框选择本页全部）。换页后选择仍然保留；改变搜索或筛选条件会清空选择。
2. 在页面底部的操作栏选择操作：

| 操作 | 效果 |
| --- | --- |
| 启用 / 停用 | 每个改变了状态的网站写一条审计记录（与单个网站的启用、停用相同）；每个集群只发布一个新的配置版本，原因「启用 N 个网站」「停用 N 个网站」（集群里只有一个网站变化时为该网站的原因）。已经是该状态的网站不变。 |
| 清除缓存 | 为所选网站创建一个全站刷新任务，在 **刷新预热** 查看各节点的结果。 |
| 添加标签 / 移除标签 | 给所选网站加上或去掉若干标签。任一网站加上后超过 10 个标签时整个操作失败，提示是哪个网站。 |
| 复制设置 | 选择源网站和要复制的部分，把它们复制到所选网站，见下节。 |
| 删除 | 输入所选网站的数量后才能删除。每个网站写一条审计记录，每个集群只发布一次。 |

批量操作要么全部完成，要么一个都不改（例如所选网站中有一个已被删除）。

## 复制设置

1. 在网站的 **概览** 点击「复制设置」，选择目标网站；或在网站列表选中目标网站，在操作栏点击「复制设置」，选择源网站。
2. 勾选要复制的部分，点击「预览」。
3. 预览列出每个目标网站各部分的变化（列表类的部分显示「原条数 → 新条数」，其他部分显示变化的设置数），以及会失败的网站和原因。预览不保存任何内容。
4. 点击「复制到 N 个网站」。结果列出每个网站复制了哪些部分，或失败的原因。

- 每个目标网站单独保存：一个网站失败时，它的设置保持不变，其他网站照常复制。
- 每个复制成功的网站发布所在集群的新配置版本（原因「把 {source} 的设置复制到 {site}」，内容没有变化时不产生新版本），并写审计记录「复制网站设置」，记录源网站、复制的部分和实际变化的部分。
- 复制的部分会整体替换目标网站的该部分，例如目标原有的网站规则全部被源网站的规则取代。

### 可以复制的部分

| 部分 | 复制的内容 | 不复制 |
| --- | --- | --- |
| 缓存规则 | 全部缓存规则 | |
| 缓存键与分片 | 缓存键（查询参数、请求头、Cookie、设备类型、Host）与 Range 分片 | |
| Cache-Tag | 是否把源站的 Cache-Tag 响应头发给访客 | |
| 压缩 | gzip、Brotli、Zstandard 的开关、级别、最小长度、类型与最大压缩长度 | |
| HTTPS 选项 | 强制 HTTPS、HSTS、最低 TLS 版本、密码套件、HTTP/2、HTTP/3、OCSP 装订、跳转状态码与端口、客户端证书 | 证书、不跳转的域名 |
| 网站规则 | 网站的全部规则（各阶段）与规则读取请求体的上限 | |
| 批量重定向 | 整个重定向表 | |
| 错误页 | 各状态的错误页与「也替换源站的错误响应」 | 维护模式 |
| OWASP CRS | 模式、偏执级别、异常阈值、请求体检查上限与排除项 | |
| CC 与挑战 | Under Attack、挑战方式、通行有效期、工作量证明难度、CC 策略、放行已验证的爬虫、挑战页文案、挑战失败封禁 | |
| 访问控制 | 本站名单、防盗链、UA 名单、CORS、地区访问、WebSocket 来源、安全响应头 | |
| 访问鉴权 | 全部鉴权规则；密码哈希与签名密钥为目标网站重新加密 | |
| 源站池设置 | 负载均衡、超时、长连接、回源协议、gRPC、主动健康检查、会话保持、重试、WebSocket | 源站列表 |
| 日志设置 | 访问日志采样率、记录拦截请求、查询串、请求头、对端地址与 JA4 | |

域名、源站、证书、端口、X-Cache、PURGE 方法与密钥、字符编码、请求体上限与维护模式不属于任何部分，不会被复制。

### 复制失败的原因

目标网站缺少设置里用到的对象时，该网站复制失败：

| 提示 | 说明 |
| --- | --- |
| 规则「…」选择的源站组 … 在该网站不存在 | 先在目标网站的「源站」页签添加同名的源站组。 |
| HTTPS 跳转、HSTS 和客户端证书需要网站有证书 | 目标网站没有证书；先为它配置证书，或不复制「HTTPS 选项」。 |
| 网站没有这些域名：… / 网站没有域名 … | 批量重定向的来源（`域名/路径`）或访问鉴权规则的域名范围写着目标网站没有的域名。 |
| 跳转端口 … 不是网站的 HTTPS 端口 | 先给目标网站加上该端口，或在源网站改用 443。 |
| IP 名单不存在 | 设置引用的 IP 名单在复制时被删除了。 |

## 克隆网站

1. 在网站的 **概览** 点击「克隆」。
2. 填写名称（留空为第一个域名）和域名，按需修改标签（默认为源网站的标签），点击「克隆」。

新网站与源网站在同一个集群，带有源网站的源站（S3 凭据为新网站重新加密）、全部可复制的部分、X-Cache、PURGE 方法与密钥（重新加密）、字符编码、请求体上限与维护模式。证书只覆盖源网站的域名，不会复制；因此新网站的强制 HTTPS、HSTS 与客户端证书为关闭，HTTPS 端口只保留 443（源网站没有 HTTP 端口时使用 80）。源网站的访问鉴权域名范围或批量重定向来源写着源网站的域名时，克隆失败并提示原因。克隆写审计记录「克隆网站」。

## 接口

| 操作 | 接口 |
| --- | --- |
| 设置网站标签 | `PUT /api/v1/sites/{id}/tags` |
| 标签列表、改名、删除 | `GET /api/v1/site-tags`、`PATCH /api/v1/site-tags/{id}`、`DELETE /api/v1/site-tags/{id}` |
| 按标签列出网站 | `GET /api/v1/sites?tagIds[]=<id>&tagIds[]=<id>&tagMatch=all` |
| 批量启停、标签、删除 | `POST /api/v1/sites/batch/enabled`、`/batch/tags`、`/batch/delete` |
| 预览与复制 | `GET`、`POST /api/v1/sites/{id}/copy-settings` |
| 克隆 | `POST /api/v1/sites/{id}/clone` |

字段与错误码见 [API 参考](../reference/api.md)。只读 AccessKey 可以列出标签和预览复制，不能修改；服务账号不能调用这些接口。

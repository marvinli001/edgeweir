# 域名、DNS 与告警

域名归属校验、平台 DNS 调度记录，以及告警渠道、规则与订阅。

## 概念

| 术语 | 定义 |
| --- | --- |
| 可注册域 | 公共后缀表（含 private 段）之下的一级域，例如 `example.com`、`example.co.uk`、`alice.github.io`。域名归属按可注册域校验。 |
| 域名归属 | 组织对一个可注册域的路由授权。未验证的域名保存在控制台，不发布到节点。 |
| CNAME 域 | 平台 DNS 生成调度记录所用的父域，必须位于所选 DNS 服务商的区域内。 |
| 线路 | 平台 DNS 中与一个节点组对应的一组 A/AAAA 记录。 |
| DNS 版本 | 平台 DNS 策略及其记录的快照，独立于节点配置版本（revision）。 |
| 告警渠道 | 平台管理员配置的通知目标：邮件、Webhook、钉钉、企业微信或 Telegram。 |

## 验证域名归属

1. 打开 **控制台 → 网站**，选择网站，进入「域名」页签。
2. 在「域名归属」卡片中，对状态为「待验证」的域名点击「生成校验记录」。
3. 复制「TXT 名称」和「TXT 值」，在该可注册域的权威 DNS 中添加 TXT 记录：

   ```text
   _edgeweir-verification.example.com.  TXT  "edgeweir=<token>"
   ```

4. 确认记录已生效：

   ```bash
   dig +short TXT _edgeweir-verification.example.com
   ```

   输出包含 `"edgeweir=<token>"`。
5. 点击「校验 TXT 记录」。
6. 验证：状态变为「已验证」，控制台发布新的配置版本，该可注册域下的域名进入节点配置。

### 归属规则

| 项目 | 行为 |
| --- | --- |
| 校验范围 | 一条 TXT 记录验证整个可注册域；该组织所有网站中属于此可注册域的主机名和泛域名一并生效。 |
| 唯一性 | 同一平台内，一个可注册域只属于一个组织。多个组织可同时持有待验证申请；一方验证成功后，其他组织不能再使用该根域、子域名或泛域名（`DOMAIN_IN_USE`）。 |
| 平台管理员 | 平台管理员新建网站或保存网站域名时，未验证的可注册域直接记为「管理员已确认」。已存在的待验证域名可由平台管理员点击「免验证并发布」。两种方式都写入审计 `domain.bypass`。 |
| 撤销 | 「撤销验证」停用该组织在此可注册域下全部网站的路由。配置回滚不能恢复未验证的域名。 |
| 释放 | 删除该可注册域的最后一个网站引用后，归属记录随之删除。 |
| 迁移 | 域名转移到另一组织：由平台管理员撤销原组织的验证，新组织再完成 TXT 校验。 |
| 证书 | 已上传的证书不替代域名归属。ACME 申请要求每个证书域名已验证，见 [HTTPS 与证书](https.md)。 |
| 旧部署 | 控制台首次启用域名归属时，撤下没有归属证明的既有路由；需逐个完成 TXT 校验或由平台管理员批准。 |

### TXT 查询

| 项目 | 值 |
| --- | --- |
| 递归服务器 | **后台 → 系统设置 → 所有权校验 DNS** 中保存的服务器；未保存时依次使用 `EDGEWEIR_DNS_RESOLVERS` 和系统解析器，见[平台管理](admin.md) |
| 单次查询 | 超时 2.5 秒，最多 2 次尝试 |
| 并发 | 每个控制台进程同时最多 16 个校验查询 |
| 频率 | 同一可注册域两次校验至少间隔 5 秒（`DOMAIN_VERIFY_BUSY`） |
| 选择解析器 | 租户和校验请求不能指定解析器 |

## 配置平台 DNS

平台 DNS 为每个网站生成 CNAME 目标，把访问流量调度到健康节点。仅平台管理员可用。

1. 打开 **后台 → 平台 DNS**，点击「添加 DNS 服务商」。
2. 填写「名称」「DNS 区域」，选择「DNS 服务商」，填写凭据字段（见下表），点击「创建」。
3. 在「DNS 配置」卡片中打开「启用」，选择「DNS 服务商」，填写「CNAME 域」和「TTL（秒）」。
4. 点击「添加线路」，填写「线路名称」并选择「节点组」。节点位于 NAT 或内网之后时，在该节点的「节点名：目标地址」字段中填写对外地址；留空则自动使用上报的公开 IP。
5. 点击「保存」。控制台提示「已生成 DNS 版本 N」。
6. 验证：「DNS 版本」表中该版本状态为「已发布」，网站「域名」页签显示「CNAME 目标」。

   ```bash
   dig +short CNAME <网站 UUID>.<CNAME 域>
   ```

   输出为 `all.<网站 UUID>.<CNAME 域>.`。
7. 在各网站域名的 DNS 中，把域名 CNAME 到「CNAME 目标」。

### 服务商凭据

凭据使用主密钥信封加密后保存，只写不读。给 API 凭据授予目标区域的最小 DNS 编辑权限。

| 服务商 | 字段 |
| --- | --- |
| Cloudflare | API Token |
| 阿里云 | AccessKey ID、AccessKey Secret |
| 华为云 | AccessKey ID、AccessKey Secret、区域 |
| DNSPod | API Token（DNSPod 传统 API 的 `ID,Token`） |

「编辑」重新填写凭据以轮换密钥；「DNS 区域」和「DNS 服务商」创建后不可修改。

### DNS 配置字段

| 字段 | 取值 | 默认值 | 作用 |
| --- | --- | --- | --- |
| 启用 | 开 / 关 | 关 | 关闭后清理系统管理的全部记录 |
| DNS 服务商 | 已添加的服务商 | 无 | 写入记录的账户与区域 |
| CNAME 域 | 服务商区域内的域名，最长 180 字符 | 无 | 生成记录的父域 |
| TTL（秒） | 30–3600 | 600 | 全部记录的 TTL；服务商或套餐可能要求更高的最低值 |
| 线路名称 | 小写字母、数字、`-`，1–32 字符，不能为 `all` | `line-N` | 线路主机名的第一段 |
| 节点组 | 每个节点组最多一条线路 | 第一个未使用的节点组 | 线路包含的节点 |
| 目标地址 | 每个节点最多 8 个 IP，逗号分隔 | 空（使用上报的公开 IP） | 替代上报地址；可为私网地址，不能为回环、链路本地、组播等特殊用途地址 |

一次配置最多 128 条线路、10000 条系统管理记录。

### 生成的记录

每个启用且至少有一个已验证域名的网站生成以下记录：

| 名称 | 类型 | 内容 |
| --- | --- | --- |
| `<网站 UUID>.<CNAME 域>` | CNAME | `all.<网站 UUID>.<CNAME 域>` |
| `all.<网站 UUID>.<CNAME 域>` | A / AAAA | 该网站所在集群全部线路的健康节点地址 |
| `<线路名称>.<网站 UUID>.<CNAME 域>` | A / AAAA | 该线路节点组内的健康节点地址 |

线路是明确的节点组主机名，不调用服务商专属的运营商或地理解析功能。

### 健康摘除与修复

| 项目 | 行为 |
| --- | --- |
| 进入地址集合 | 节点已启用、45 秒内有心跳、数据面健康，并已应用所在集群的当前配置版本 |
| 检查周期 | 后台任务每分钟重新计算；离线、停用或配置落后的节点被摘除，恢复后加回 |
| 生效时间 | 受 TTL 和递归缓存影响，不是即时切流 |
| 漂移修复 | 系统管理的名称被外部删除或修改后，下一次检查恢复；「修复记录」立即执行一次 |
| 接管范围 | 只增删已登记为系统管理的名称；新名称上已有非系统记录时拒绝接管（`DNS_RECORD_CONFLICT`） |
| 写入顺序 | 先登记管理名称，再删除多余记录、添加缺失记录，最后读回确认；失败时保留登记并在下一周期重试 |

### DNS 版本与回滚

DNS 版本不增加节点配置 revision。「回滚 DNS」恢复所选版本的 DNS 策略，地址仍按当前网站授权与节点健康计算，不恢复已离线的节点。

删除服务商前，先在「DNS 配置」中取消选择该服务商或关闭「启用」并保存，等待清理完成（服务商不再持有系统管理的记录），否则返回 `DNS_PROVIDER_IN_USE`。

## 配置告警渠道

仅平台管理员可用。

1. 打开 **后台 → 告警渠道**，点击「添加渠道」。
2. 填写「名称」，选择「渠道类型」，填写该类型的字段（见下表）。
3. 选择「通知语言」。
4. 按需打开「接收所有网站的告警」和「允许租户订阅」。
5. 点击「创建」。
6. 验证：点击「发送测试」，目标收到测试通知；渠道行不显示「通知发送失败」。

邮件渠道使用 **后台 → 系统设置 → SMTP** 中的服务器，见[平台管理](admin.md)。

### 渠道字段

| 渠道类型 | 字段 | 约束 |
| --- | --- | --- |
| Webhook | Webhook 地址、Bearer 令牌（可选） | HTTP POST JSON；公网目标必须 HTTPS |
| 邮件 | 收件地址 | 1–20 个地址，逗号或空格分隔 |
| 钉钉 | Webhook 地址、签名密钥（可选） | 主机必须为 `oapi.dingtalk.com`；填写签名密钥时附加 timestamp 与 HMAC-SHA256 签名 |
| 企业微信 | Webhook 地址 | 主机必须为 `qyapi.weixin.qq.com` |
| Telegram | 机器人令牌、会话 ID | 调用 Bot API `sendMessage`，关闭链接预览 |

| 开关 | 默认值 | 作用 |
| --- | --- | --- |
| 接收所有网站的告警 | 关 | 渠道接收全平台所有网站的告警，无需订阅 |
| 允许租户订阅 | 关 | 租户可在「告警」页面订阅该渠道 |

平台最多 32 个渠道。编辑渠道时，打开「更新渠道凭据」重新填写类型与字段；不打开则保留原凭据。

### Webhook 载荷

请求体为 JSON，包含 `id`（事件 ID）、`siteId`、`siteName`、`kind`、`status`（`firing` / `resolved`）、`occurredAt`、`text` 和 `url`（控制台中该网站的链接）。配置了 Bearer 令牌时附带 `Authorization: Bearer <令牌>`。接收方返回 2xx 视为成功。

## 设置告警规则

1. 打开 **后台 → 告警渠道**，在「告警规则」卡片中修改阈值。
2. 点击「保存」。

| 字段 | 取值 | 默认值 | 告警种类 | 触发条件 |
| --- | --- | --- | --- | --- |
| 离线阈值（秒） | 45–3600 | 90 | 节点离线 | 网站所在集群的已启用节点超过阈值未上报，或上报数据面不健康 |
| 证书到期预警（小时） | 1–720 | 72 | 证书即将到期 | 网站当前证书在阈值内到期 |
| 最低请求数 | 1–1000000 | 100 | 服务端错误率过高 | 统计窗口内请求数达到该值 |
| 统计窗口（分钟） | 1–60 | 5 | 服务端错误率过高 | 计算 5xx 比例的时间窗口 |
| 5xx 阈值（%） | 1–100 | 20 | 服务端错误率过高 | 窗口内 5xx 比例达到该值 |

「源站不可用」没有单独阈值：某个节点上报网站全部源站在离线阈值内均处于不健康状态时触发。源站状态来自被动健康检查，见[源站与缓存](origins-and-cache.md#被动健康检查)。

告警只针对已启用且至少有一个已验证域名的网站。

## 订阅告警

1. 打开 **控制台 → 告警**，点击「订阅告警」。
2. 在「搜索网站」中查找并选择网站，选择「通知渠道」，勾选告警种类。
3. 点击「保存」。
4. 验证：订阅出现在列表中；「近期告警」显示该网站的事件。

租户只能订阅自己可见的网站和「允许租户订阅」的渠道。

## 投递行为

| 项目 | 行为 |
| --- | --- |
| 事件 | 同一条件只在进入告警和恢复时各产生一个事件，事件 ID 固定 |
| 重试 | 失败后按 2、4、8、16 分钟退避重试，每个渠道共尝试 5 次 |
| 重复 | 网络回执丢失时接收方可能收到重复通知；Webhook 接收方按事件 ID 去重 |
| 投递前检查 | 每次投递重新检查订阅者的组织成员关系、账号停用状态、组织两步验证要求和渠道可见性 |
| 出站策略 | 解析并固定目标 IP；拒绝特殊用途地址；Webhook 类目标不跟随重定向；内部 Webhook 或 SMTP 需在 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` 中放行对应网段 |
| 超时与大小 | 单次投递 10 秒；请求体最大 32 KiB，响应体最大 64 KiB |
| 保留 | 告警事件保留 90 天 |
| 敏感字段 | 渠道接口和失败记录不返回密码、机器人令牌、Webhook 密钥或服务商原始错误 |

## 限制

| 项目 | 说明 |
| --- | --- |
| 后台任务 | 平台 DNS 同步、告警检查与投递由后台任务每分钟执行，需要至少一个 `ROLE=worker` 或 `ROLE=all` 的控制台进程，见[部署概览](../deploy/README.md) |
| 智能解析 | 不使用服务商的运营商线路或地理解析；线路即节点组 |
| 主动探测 | 不做主动可达性探测；源站状态只来自真实流量 |
| 本地模拟服务 | 「本地模拟服务」只在设置 `EDGEWEIR_DNS_TEST_ENDPOINT` 时出现，仅用于测试 |
| 验证范围 | DNS 服务商和钉钉、企业微信、Telegram、外部 SMTP 的真实账户送达需运营者自行验收 |

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「尚未找到 TXT 校验记录」 | 记录未生效，或所用递归服务器缓存了旧结果 | 用 `dig` 查询确认；检查 **后台 → 系统设置 → 所有权校验 DNS** |
| 「请稍后重试校验」 | 5 秒内重复校验，或并发查询已满 | 等待后重试 |
| 「请输入可注册域名下的主机名」 | 域名不在公共后缀之下，例如直接使用公共后缀 | 使用可注册域或其子域名 |
| 「域名已被使用」 | 该可注册域已由其他组织验证 | 由平台管理员撤销原组织的验证 |
| 「CNAME 域不属于该 DNS 区域」 | CNAME 域不在服务商区域内 | 改用区域本身或其子域名 |
| 「该 DNS 名称已有非系统管理的记录」 | 目标名称上已有手工记录 | 删除手工记录后「修复记录」 |
| 「DNS 服务商仍在使用中」 | 服务商仍被选中或仍持有记录 | 关闭或改选服务商，等待清理完成后删除 |
| 「CNAME 目标」显示「无健康节点」 | 线路内没有满足条件的节点 | 检查节点心跳、数据面状态和已应用版本 |
| 渠道显示「通知发送失败」 | 目标拒绝、超时，或地址被出站策略拒绝 | 「发送测试」复现；内网目标加入 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` |
| 「通知渠道数量已达上限」 | 已有 32 个渠道 | 删除不用的渠道 |

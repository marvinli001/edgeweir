# DNS 调度与告警

DNS 调度记录，以及告警渠道、订阅与规则。

## 概念

| 术语 | 定义 |
| --- | --- |
| CNAME 域 | DNS 调度生成记录所用的父域，必须位于所选 DNS 服务商的区域内。 |
| 线路 | DNS 调度中与一个节点组对应的一组 A/AAAA 记录。 |
| DNS 版本 | DNS 调度策略及其记录的快照，独立于节点配置版本（revision）。 |
| 告警渠道 | 通知目标：邮件、Webhook、钉钉、企业微信或 Telegram。 |
| 告警订阅 | 把一个网站的若干告警种类发送到一个渠道。 |

## 配置 DNS 调度

DNS 调度为每个网站生成 CNAME 目标，把访问流量调度到健康节点。

1. 打开 **DNS 调度**，点击「添加 DNS 服务商」。
2. 填写「名称」「DNS 区域」，选择「DNS 服务商」，填写凭据字段（见下表），点击「创建」。
3. 在「DNS 配置」卡片中打开「启用」，选择「DNS 服务商」，填写「CNAME 域」和「TTL（秒）」。
4. 点击「添加线路」，填写「线路名称」并选择「节点组」。节点位于 NAT 或内网之后时，在该节点的「节点名：目标地址」字段中填写对外地址；留空则自动使用上报的公开 IP。
5. 点击「保存」。控制台提示「已生成 DNS 版本 N」。
6. 验证：「DNS 版本」表中该版本状态为「已发布」，网站「域名」页签显示「CNAME 目标」。

   ```bash
   dig +short CNAME <网站 UUID>.<CNAME 域>
   ```

   输出为 `all.<网站 UUID>.<CNAME 域>.`。
7. 在各网站域名的 DNS 中，把域名 CNAME 到「CNAME 目标」。

### 服务商凭据

凭据使用主密钥信封加密后保存，只写不读。给 API 凭据授予目标区域的最小 DNS 编辑权限。DNS 调度的服务商与 ACME DNS-01 使用的 DNS 凭据相互独立，后者见 [HTTPS 与证书](https.md)。

| 服务商 | 字段 |
| --- | --- |
| Cloudflare | API Token |
| 阿里云 | AccessKey ID、AccessKey Secret |
| 华为云 | AccessKey ID、AccessKey Secret、区域 |
| DNSPod | API Token（DNSPod 传统 API 的 `ID,Token`） |

「编辑」重新填写凭据以轮换密钥；「DNS 区域」和「DNS 服务商」创建后不可修改。

### DNS 配置字段

| 字段 | 取值 | 默认值 | 作用 |
| --- | --- | --- | --- |
| 启用 | 开 / 关 | 关 | 关闭后清理系统管理的全部记录 |
| DNS 服务商 | 已添加的服务商 | 无 | 写入记录的账户与区域 |
| CNAME 域 | 服务商区域内的域名，最长 180 字符 | 无 | 生成记录的父域 |
| TTL（秒） | 30–3600 | 600 | 全部记录的 TTL；服务商或套餐可能要求更高的最低值 |
| 线路名称 | 小写字母、数字、`-`，1–32 字符，不能为 `all` | `line-N` | 线路主机名的第一段 |
| 节点组 | 每个节点组最多一条线路 | 第一个未使用的节点组 | 线路包含的节点 |
| 目标地址 | 每个节点最多 8 个 IP，逗号分隔 | 空（使用上报的公开 IP） | 替代上报地址；可为私网地址，不能为回环、链路本地、组播等特殊用途地址 |

一次配置最多 128 条线路、10000 条系统管理记录。

### 生成的记录

每个至少有一个域名的网站生成以下记录（停用的网站同样保留）：

| 名称 | 类型 | 内容 |
| --- | --- | --- |
| `<网站 UUID>.<CNAME 域>` | CNAME | `all.<网站 UUID>.<CNAME 域>` |
| `all.<网站 UUID>.<CNAME 域>` | A / AAAA | 该网站所在集群全部线路的健康节点地址 |
| `<线路名称>.<网站 UUID>.<CNAME 域>` | A / AAAA | 该线路节点组内的健康节点地址 |

线路是明确的节点组主机名，不调用服务商专属的运营商或地理解析功能。

### 健康摘除与修复

| 项目 | 行为 |
| --- | --- |
| 进入地址集合 | 节点已启用、45 秒内有心跳、数据面健康，并已应用所在集群的当前配置版本 |
| 检查周期 | 后台任务每分钟重新计算；离线、停用或配置落后的节点被摘除，恢复后加回 |
| 生效时间 | 受 TTL 和递归缓存影响，不是即时切流 |
| 漂移修复 | 系统管理的名称被外部删除或修改后，下一次检查恢复；「修复记录」立即执行一次 |
| 接管范围 | 只增删已登记为系统管理的名称；新名称上已有非系统记录时拒绝接管（`DNS_RECORD_CONFLICT`） |
| 写入顺序 | 先登记管理名称，再删除多余记录、添加缺失记录，最后读回确认；失败时保留登记并在下一周期重试 |
| 配置金丝雀 | 节点按自己的目标版本判断：金丝雀窗口期间，非金丝雀节点运行稳定版本，不被摘除，见 [配置金丝雀](system.md#配置金丝雀) |

### 大面积摘除保护

一次发布会把原来非空的 `all.` 或线路记录集清空，或摘除的地址记录超过阈值时，保留上一版记录，不写入服务商。控制台与节点通道断开、所有节点都被判定离线时，同样按此处理。

| 项目 | 行为 |
| --- | --- |
| 阈值 | 单次摘除的地址记录占上一版地址记录的比例，默认 50%，**DNS 调度 → 大面积摘除保护** 可调（5%–100%） |
| 不计入 | 不再管理的名称（网站删除、线路移除）；服务商或 CNAME 域变化；关闭 DNS |
| 阻止时 | DNS 调度页面顶部显示被阻止的变更（将删除的地址记录数），DNS 版本列表中状态为「已阻止」；发出告警「DNS 大面积摘除已阻止」 |
| 恢复 | 之后的发布不再触发保护时自动结束阻止，告警恢复 |
| 强制发布 | 在 DNS 调度页面点击「强制发布」并确认，按当前状态发布；写审计 `dns.force_publish` |

### DNS 版本与回滚

DNS 版本不增加节点配置 revision。「回滚 DNS」恢复所选版本的 DNS 策略，地址仍按当前的网站与节点健康状态计算，不恢复已离线的节点。

删除服务商前，先在「DNS 配置」中取消选择该服务商或关闭「启用」并保存，等待清理完成（服务商不再持有系统管理的记录），否则返回 `DNS_PROVIDER_IN_USE`。

## 告警页面

告警在 **告警** 页面配置，页面有四张卡片：

| 卡片 | 内容 |
| --- | --- |
| 告警渠道 | 通知目标，可添加、编辑、发送测试、启用或停用、删除 |
| 告警订阅 | 网站的告警种类与接收它们的渠道 |
| 近期告警 | 最近 100 条告警事件，含集群与 DNS 告警 |
| 告警规则 | 触发告警的阈值 |

## 配置告警渠道

1. 打开 **告警**，在「告警渠道」卡片中点击「添加渠道」。
2. 填写「名称」，选择「渠道类型」，填写该类型的字段（见下表）。
3. 选择「通知语言」。
4. 按需打开「接收所有告警」。
5. 点击「创建」。
6. 验证：点击「发送测试」，目标收到测试通知；渠道行不显示「通知发送失败」。

邮件渠道使用 **系统设置 → SMTP** 中的服务器，见 [SMTP](system.md#smtp)。

### 渠道字段

| 渠道类型 | 字段 | 约束 |
| --- | --- | --- |
| Webhook | Webhook 地址、Bearer 令牌（可选） | HTTP POST JSON；公网目标必须 HTTPS |
| 邮件 | 收件地址 | 1–20 个地址，逗号或空格分隔 |
| 钉钉 | Webhook 地址、签名密钥（可选） | 主机必须为 `oapi.dingtalk.com`；填写签名密钥时附加 timestamp 与 HMAC-SHA256 签名 |
| 企业微信 | Webhook 地址 | 主机必须为 `qyapi.weixin.qq.com` |
| Telegram | 机器人令牌、会话 ID | 调用 Bot API `sendMessage`，关闭链接预览 |

| 开关 | 默认值 | 作用 |
| --- | --- | --- |
| 接收所有告警 | 关 | 渠道接收全部告警，无需订阅：所有网站的告警，以及集群与 DNS 告警 |

未打开该开关的渠道只接收订阅到它的网站告警，见[订阅告警](#订阅告警)。

最多 32 个渠道。编辑渠道时，打开「更新渠道凭据」重新填写类型与字段；不打开则保留原凭据。停用的渠道不发送通知，也不能被新的订阅选择。

### Webhook 载荷

请求体为 JSON，包含 `id`（事件 ID）、`siteId`、`siteName`、`kind`、`status`（`firing` / `resolved`）、`occurredAt`、`resourceId`（告警对象，例如节点或证书的 ID）、`text` 和 `url`（控制台链接）。集群与 DNS 告警的 `siteId` 为 `null`，`siteName` 为集群名称或 `DNS`，`url` 指向 **集群与节点** 或 **DNS 调度**。配置了 Bearer 令牌时附带 `Authorization: Bearer <令牌>`。接收方返回 2xx 视为成功。

## 设置告警规则

1. 打开 **告警**，在「告警规则」卡片中修改阈值。
2. 点击「保存」。

| 字段 | 取值 | 默认值 | 告警种类 | 触发条件 |
| --- | --- | --- | --- | --- |
| 离线阈值（秒） | 45–3600 | 90 | 节点离线 | 网站所在集群的已启用节点超过阈值未上报，或上报数据面不健康 |
| 证书到期预警（小时） | 1–720 | 72 | 证书即将到期 | 网站当前证书在阈值内到期 |
| 最低请求数 | 1–1000000 | 100 | 服务端错误率过高 | 统计窗口内请求数达到该值 |
| 统计窗口（分钟） | 1–60 | 5 | 服务端错误率过高 | 计算 5xx 比例的时间窗口 |
| 5xx 阈值（%） | 1–100 | 20 | 服务端错误率过高 | 窗口内 5xx 比例达到该值 |

「源站不可用」没有单独阈值：某个节点在离线阈值内上报网站的每个源站都不可用时触发。一个源站在该节点上不可用，指它的被动检查或主动检查结果（任一来源）为不健康；见[被动健康检查](origins-and-cache.md#被动健康检查)与[主动健康检查](origins-and-cache.md#主动健康检查)。

「CC 防护升级」（`cc_mitigation`）没有单独阈值：节点上报网站从正常升级时触发，同一网站 15 分钟内最多一次；没有在线节点再报告该网站高于正常级别后恢复。见[挑战与 CC 防护](challenges.md#cc-防护)。

网站告警只针对已启用且至少有一个域名的网站。

### 集群与 DNS 告警

以下告警属于集群或 DNS 调度而不是网站，只投递到开启「接收所有告警」的渠道，不能订阅；「近期告警」同样列出它们。

| 告警 | 触发 | 恢复 |
| --- | --- | --- |
| 配置金丝雀发布已回滚 | 金丝雀自动回滚或被手动中止 | 该集群下一次推进 |
| 没有在线的金丝雀节点，配置已直接发布到全部节点 | 开启金丝雀的集群发布时没有在线的金丝雀节点 | 该集群下一次发布有在线的金丝雀节点 |
| DNS 大面积摘除已阻止 | [大面积摘除保护](#大面积摘除保护) 阻止了一次发布 | 下一次发布通过或强制发布 |

## 订阅告警

1. 打开 **告警**，在「告警订阅」卡片中点击「订阅告警」。
2. 在「搜索网站」中查找网站并在「网站」中选择，选择「通知渠道」，打开要发送的告警种类。
3. 点击「保存」。
4. 验证：订阅出现在「告警订阅」中；「近期告警」显示该网站的事件。

| 项目 | 行为 |
| --- | --- |
| 渠道 | 只能选择已启用的渠道；没有可用渠道时「订阅告警」不可点击 |
| 告警种类 | 节点离线、证书即将到期、源站不可用、服务端错误率过高、CC 防护升级 |
| 重复订阅 | 同一网站与渠道只有一条订阅；再次保存会替换其告警种类 |
| 取消 | 点击订阅行的「取消订阅」并确认 |

## 投递行为

| 项目 | 行为 |
| --- | --- |
| 事件 | 同一条件只在进入告警和恢复时各产生一个事件，事件 ID 固定 |
| 接收渠道 | 开启「接收所有告警」的渠道接收全部告警；其他渠道只接收订阅到它们的网站告警 |
| 重试 | 失败后按 2、4、8、16 分钟退避重试，每个渠道共尝试 5 次 |
| 重复 | 网络回执丢失时接收方可能收到重复通知；Webhook 接收方按事件 ID 去重 |
| 投递前检查 | 每次投递重新检查：渠道已启用、事件仍是该条件的当前状态、订阅仍包含该告警种类（开启「接收所有告警」的渠道除外） |
| 出站策略 | 解析并固定目标 IP；拒绝特殊用途地址；Webhook 类目标不跟随重定向；内部 Webhook 或 SMTP 需在 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` 中放行对应网段 |
| 超时与大小 | 单次投递 10 秒；请求体最大 32 KiB，响应体最大 64 KiB |
| 保留 | 告警事件保留 90 天 |
| 敏感字段 | 渠道接口和失败记录不返回密码、机器人令牌、Webhook 密钥或服务商原始错误 |

## 限制

| 项目 | 说明 |
| --- | --- |
| 后台任务 | DNS 调度同步、告警检查与投递由后台任务每分钟执行，需要至少一个 `ROLE=worker` 或 `ROLE=all` 的控制台进程，见[部署概览](../deploy/README.md) |
| 智能解析 | 不使用服务商的运营商线路或地理解析；线路即节点组 |
| 主动探测 | 不做主动可达性探测；源站状态只来自真实流量 |
| 本地模拟服务 | 「本地模拟服务」只在设置 `EDGEWEIR_DNS_TEST_ENDPOINT` 时出现，仅用于测试 |

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「CNAME 域不属于该 DNS 区域」 | CNAME 域不在服务商区域内 | 改用区域本身或其子域名 |
| 「该 DNS 名称已有非系统管理的记录」 | 目标名称上已有手工记录 | 删除手工记录后「修复记录」 |
| 「DNS 服务商仍在使用中」 | 服务商仍被选中或仍持有记录 | 关闭或改选服务商，等待清理完成后删除 |
| 「CNAME 目标」显示「无健康节点」 | 线路内没有满足条件的节点 | 检查节点心跳、数据面状态和已应用版本 |
| 渠道显示「通知发送失败」 | 目标拒绝、超时，或地址被出站策略拒绝 | 「发送测试」复现；内网目标加入 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` |
| 「通知渠道数量已达上限」 | 已有 32 个渠道 | 删除不用的渠道 |
| 「订阅告警」不可点击 | 没有已启用的渠道 | 添加或启用渠道 |

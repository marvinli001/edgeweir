# 域名、DNS 与告警

## 域名归属

租户新建的域名先保存在控制台，验证完成后才进入节点配置。到网站的「域名」页复制 `_edgeweir-verification.<可注册域>` 的 TXT 名称和值，在域名的权威 DNS 配置后点击校验。判定可注册域使用 tldts 的公共及 private 后缀表，`example.co.uk`、`alice.github.io` 分别作为独立范围，不能用简单的最后两段代替。

一个可注册域在同一平台内属于一个组织。多个组织可以提出待验证申请，待验证记录不保留全局主机名使用权；成功验证后，其他组织不能覆盖该根域、子域名或泛域名。管理员新建站点可以免 TXT；给已有站点免验证需要明确点击「免验证并发布」，会写 `domain.bypass` 审计。撤销验证会撤下该组织在此根域下的全部路由，回滚配置不能恢复未验证的域名。删除最后一个站点引用后释放根域所有权。

**升级到 M5 时，既有域名默认待验证。** 首次启动的迁移任务会撤下没有证明的旧路由；运营者需要完成 TXT 验证或在后台明确批准。原先跨组织共用一个可注册域的部署须先调整组织/命名空间；域名转移可由管理员撤销旧组织的证明后让新组织校验。已有证书本身不替代这项路由授权。

TXT 查询默认使用系统 DNS。运营者可用 `EDGEWEIR_DNS_RESOLVERS` 指定递归服务器（逗号分隔 IP 或主机名，可附端口）。API 调用者不能选择解析器。校验有查询超时、并发上限及每个证明的五秒间隔。

## 平台 DNS

在后台「平台 DNS」添加 Cloudflare、阿里云、华为云或 DNSPod 凭据；凭据仅写入并按记录绑定加密。凭据可原地轮换，区域和服务商不可借轮换改指到另一目标。给 API 凭据授予所需区域的最小 DNS 权限。

选择 CNAME 域（必须在凭据区域内），再把节点组映射为线路。默认 TTL 为 600 秒；不同服务商/套餐对最低 TTL 有不同限制。节点默认使用上报的公开 IP；NAT 或内网环境可明确填写目标地址。回环、链路本地、组播等地址不可作为目标。

每个有已验证域名的启用站点得到 `<网站 UUID>.<CNAME 域>`，指向 `all.<网站 UUID>.<CNAME 域>`。后者包含全部可用线路的地址；每条线路另有 `<线路>.<网站 UUID>.<CNAME 域>`。这些线路是明确的节点组主机名，当前不调用服务商专属的运营商/地理 DNS 功能。

只有最近有心跳、数据面健康、应用了当前集群配置的节点才进入地址集合。后台每分钟检查一次，离线/停用/配置落后的节点被摘除，恢复后加回。DNS 缓存仍受 TTL 影响，不宣称即时切流。记录被外部删除或修改后会被修复。

DNS 有独立版本，不增加节点配置 revision。回滚恢复历史 DNS **策略**，地址仍按当前站点授权与节点健康计算。服务商通常不能原子修改整组记录；系统先持久登记管理名称，再执行增删、读回确认，失败保留记录并重试。只改动登记的名称；新名称已有非系统记录时拒绝接管。关闭并清空 DNS 策略、等待清理完成后，才能删除仍持有记录的服务商。

## 统计

节点将不可变批次和单调序号保存到 0600 的本地文件，再调用 `ReportStatsV2`。回执丢失、节点重启或本地回执落盘失败会重试同一序号，控制面在一个事务内更新统计与节点游标。空 V2 请求读取游标，防止本地序号文件丢失后从头重复计数。使用新 RPC 名称是为了让旧控制面拒绝请求，避免它忽略新字段后重复累加。旧节点的未编号批次会被拒绝，需同步升级节点。

节点离线队列最多 10000 个桶、32 MiB，溢出会记录丢弃信息；Lua 未转移的计数会在两小时后过期。进程在首次完成持久化之前崩溃仍可能丢失内存计数。因此这里提供可重试的批次去重，不宣称计费级的逐请求 exactly-once。

分钟明细保留七天，小时汇总九十天，天汇总一年。后台根据持久的脏桶队列增量重算；迟到数据会让对应小时/天重算。删除明细前检查汇总是否完成，长期图表通过不重叠的视图读取已完成小时汇总和待汇总明细。UTC 边界固定，清理与入库使用协调锁。

Top URL/IP 使用节点端有界 Space-Saving 近似计数，界面标明「估算」。每个 worker 每分钟最多跟踪 128 个站点桶，每项最多 32 个候选；共享存储及上报再次限制大小。它们可能遗漏低频项，不用于精确计费。URL 不包含查询字符串或请求头；路径本身仍可能包含业务标识。

## 通知与订阅

管理员在「告警渠道」配置邮件、Webhook、钉钉、企业微信、Telegram；SMTP 在系统设置里配置。渠道默认不接收全平台告警，也不对租户开放，须明确开启。租户只能订阅自己可见网站和允许订阅的渠道。投递时重新检查组织成员关系、禁用状态、两步验证要求及渠道可见性。

默认规则：节点九十秒未报告或数据面不健康；证书七十二小时内到期；一个节点上全部已配置源站处于近期上报的不健康状态；五分钟内至少一百次请求且 5xx 比例达到 20%。阈值可调。源站状态来自被动检查，不宣称是独立的主动可达性探测。

同一条件只在进入告警或解除时产生事件；事件 ID 固定，投递失败退避重试最多五次。网络回执丢失可能导致接收方收到重复通知，Webhook 应用事件 ID 去重。事件保留九十天。外部供应商账户的真实送达需要运营者自己的配置与验收。

- Webhook：HTTP POST JSON，包含事件 ID、网站 ID、种类、状态、时间和控制台链接；可配置 Bearer token。
- SMTP：TLS 校验始终启用；关闭直接 TLS 后要求 STARTTLS。更换 SMTP 主机、端口或账户必须重新填写密码。私有 CA 可通过运营者控制的 `EDGEWEIR_SMTP_CA_FILE` 提供。
- 钉钉：文本消息，可选 timestamp/HMAC-SHA256 加签。
- 企业微信：文本群机器人 Webhook。
- Telegram：Bot API `sendMessage`，关闭链接预览，不启用付费广播。

通知会解析并固定目标 IP，拒绝特殊用途地址及重定向；公网目标要求 HTTPS。需要内部 Webhook/SMTP 时，运营者用 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` 明确放行对应网络。配置接口和失败记录不返回密码、Bot token、Webhook 密钥或原始供应商错误。

协议参考：[Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)、[钉钉机器人安全设置](https://open.dingtalk.com/document/robots/customize-robot-security-settings)、[企业微信机器人](https://developer.work.weixin.qq.com/document/path/91770)。当前本地验证包含 Webhook、受信 TLS SMTP 和供应商载荷/签名测试；不把这些结果当成真实外部账户验收。

## 本地验收

`compose.e2e.yml` 的 mock-services 是本地 TXT authority、DNS API 模拟器和 Webhook 接收器。只有显式设置 `EDGEWEIR_DNS_TEST_ENDPOINT` 才能使用测试 DNS 服务商，真实服务商不会改向这个地址。第二套环境可设置 `E2E_MOCK_PORT` 避免端口冲突。

`node scripts/e2e-m5.mjs` 验证域名未验证不路由、真实 TXT 查询、Go helper 写入 DNS、节点停止/恢复、记录漂移修复、对应租户的离线告警和真实节点统计/Top URL 上报。Playwright 覆盖后台 DNS、渠道创建、租户域名/统计/订阅及移动深色布局。

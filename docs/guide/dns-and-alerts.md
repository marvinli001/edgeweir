# 域名、DNS 与告警

域名归属校验、平台 DNS 调度记录（按集群绑定第三方 DNS 服务商）、组织区域的自动写记录，以及告警渠道、规则与订阅。

## 概念

| 术语 | 定义 |
| --- | --- |
| 可注册域 | 公共后缀表（含 private 段）之下的一级域，例如 `example.com`、`example.co.uk`、`alice.github.io`。域名归属按可注册域校验。 |
| 域名归属 | 组织对一个可注册域的路由授权。未验证的域名保存在控制台，不发布到节点。 |
| 服务商账号 | 平台 DNS 使用的一组服务商凭据及其区域。 |
| DNS 绑定 | 一个集群的平台 DNS 设置：模式、服务商账号、集群域名、TTL 与线路。 |
| 集群域名 | 一个集群的调度记录所用的父域，必须位于服务商账号的区域内。 |
| 线路 | 平台 DNS 中与一个节点组对应的一组 A/AAAA 记录。 |
| DNS 版本 | 一个集群的 DNS 绑定及其记录的快照，独立于节点配置版本（revision）。 |
| 告警渠道 | 平台管理员配置的通知目标：邮件、Webhook、钉钉、企业微信或 Telegram。 |

## 验证域名归属

1. 打开 **控制台 → 网站**，选择网站，进入「域名」页签。
2. 在「域名归属」卡片中，对状态为「待验证」的域名点击「生成校验记录」。
3. 复制「TXT 名称」和「TXT 值」，在该可注册域的权威 DNS 中添加 TXT 记录：

   ```text
   _edgeweir-verification.example.com.  TXT  "edgeweir=<token>"
   ```

4. 确认记录已生效：

   ```bash
   dig +short TXT _edgeweir-verification.example.com
   ```

   输出包含 `"edgeweir=<token>"`。
5. 点击「校验 TXT 记录」。
6. 验证：状态变为「已验证」，控制台发布新的配置版本，该可注册域下的域名进入节点配置。

### 归属规则

| 项目 | 行为 |
| --- | --- |
| 校验范围 | 一条 TXT 记录验证整个可注册域；该组织所有网站中属于此可注册域的主机名和泛域名一并生效。 |
| 唯一性 | 同一平台内，一个可注册域只属于一个组织。多个组织可同时持有待验证申请；一方验证成功后，其他组织不能再使用该根域、子域名或泛域名（`DOMAIN_IN_USE`）。 |
| 平台管理员 | 平台管理员新建网站或保存网站域名时，未验证的可注册域直接记为「管理员已确认」。已存在的待验证域名可由平台管理员点击「免验证并发布」。两种方式都写入审计 `domain.bypass`。 |
| 撤销 | 「撤销验证」停用该组织在此可注册域下全部网站的路由。配置回滚不能恢复未验证的域名。 |
| 释放 | 删除该可注册域的最后一个网站引用后，归属记录随之删除。 |
| 迁移 | 域名转移到另一组织：由平台管理员撤销原组织的验证，新组织再完成 TXT 校验。 |
| 证书 | 已上传的证书不替代域名归属。ACME 申请要求每个证书域名已验证，见 [HTTPS 与证书](https.md)。 |
| 旧部署 | 控制台首次启用域名归属时，撤下没有归属证明的既有路由；需逐个完成 TXT 校验或由平台管理员批准。 |

### TXT 查询

| 项目 | 值 |
| --- | --- |
| 递归服务器 | **后台 → 系统设置 → 所有权校验 DNS** 中保存的服务器；未保存时依次使用 `EDGEWEIR_DNS_RESOLVERS` 和系统解析器，见[平台管理](admin.md) |
| 单次查询 | 超时 2.5 秒，最多 2 次尝试 |
| 并发 | 每个控制台进程同时最多 16 个校验查询 |
| 频率 | 同一可注册域两次校验至少间隔 5 秒（`DOMAIN_VERIFY_BUSY`） |
| 选择解析器 | 租户和校验请求不能指定解析器 |

## 配置平台 DNS

平台 DNS 为每个集群写入调度记录，网站的 CNAME 目标指向所在集群的健康节点。仅平台管理员可用。Edgeweir 不运行权威 DNS，只通过服务商的 API 管理记录。

### 添加服务商账号

1. 打开 **后台 → 平台 DNS**，点击「添加服务商账号」。
2. 填写「名称」，选择「DNS 服务商」，按表单填写凭据（字段与所需权限见[服务商与凭据](#服务商与凭据)）。
3. 能列出区域的服务商：点击「列出区域」，在「区域」中选择；其他服务商直接填写「区域」。
4. 点击「测试连接」。验证：显示「连接正常：区域内有 N 条记录」。
5. 点击「创建」。

一个账号对应一组凭据和一个区域；同一组凭据管理多个区域时，分别添加账号。账号列表中的「测试连接」用已保存的凭据读取区域。「编辑」可以改名；打开「重新填写凭据」后重新填写全部字段以轮换密钥。服务商和区域创建后不可修改。凭据使用主密钥信封加密后保存，只写不读。

### 绑定集群

1. 打开 **后台 → 集群**，选择集群，切换到「DNS」页签。
2. 选择「模式」：「不管理」「手动」或「自动」。
3. 选择「服务商账号」，「区域」显示该账号的区域；填写「集群域名」和「TTL（秒）」。
4. 点击「添加线路」，填写「线路名称」并选择本集群的「节点组」。节点位于 NAT 或内网之后时，在该节点的「节点名：目标地址」字段中填写对外地址；留空则自动使用上报的公开 IP。
5. 点击「保存」。控制台提示「已生成 DNS 版本 N」。
6. 验证：「当前记录」卡片状态为「已发布」，网站「域名」页签显示「CNAME 目标」。

   ```bash
   dig +short CNAME <网站 UUID>.<集群域名>
   dig +short A all.<集群域名>
   ```

   第一条输出 `all.<集群域名>.`，第二条输出该集群健康节点的地址。
7. 在各网站域名的 DNS 中，把域名 CNAME 到「CNAME 目标」。

不同集群可以使用不同的服务商账号和集群域名。**后台 → 平台 DNS** 的「集群绑定」表列出每个集群的模式、集群域名和发布状态，「打开」进入该集群的「DNS」页签。

### 绑定字段

| 字段 | 取值 | 默认值 | 作用 |
| --- | --- | --- | --- |
| 模式 | 不管理 / 手动 / 自动 | 不管理 | 自动：控制台写入服务商；手动：列出需要创建的记录，控制台不写 DNS；不管理：网站没有 CNAME 目标，已写入的记录被清理 |
| 服务商账号 | 已添加的账号 | 无 | 自动模式必填；手动模式可以不选，此时区域按集群域名计算 |
| 区域 | 所选账号的区域 | — | 只读 |
| 集群域名 | 区域内的域名，最长 180 字符 | 无 | 本集群全部记录的父域；网站的 CNAME 目标为 `<网站 UUID>.<集群域名>` |
| TTL（秒） | 30–3600 | 600 | 全部记录的 TTL；部分服务商或套餐要求更高的最低值，见服务商表 |
| 保留站点线路别名 | 开 / 关 | 关 | 为每个网站保留 `<线路>.<网站 UUID>.<集群域名>`，见[从全局 DNS 配置升级](#从全局-dns-配置升级) |
| 线路名称 | 小写字母、数字、`-`，1–32 字符，不能为 `all` | `line-N` | 线路主机名的第一段 |
| 节点组 | 本集群的节点组，每个节点组最多一条线路 | 第一个未使用的节点组 | 线路包含的节点 |
| 目标地址 | 每个节点最多 8 个 IP，逗号分隔 | 空（使用上报的公开 IP） | 替代上报地址；可为私网地址，不能为回环、链路本地、组播等特殊用途地址 |

每个绑定最多 128 条线路、10000 条系统管理记录。同一区域内集群域名相同的两个绑定，线路名称与汇总记录名不能重复（`DNS_BINDING_CONFLICT`）。

### 生成的记录

| 名称 | 类型 | 内容 |
| --- | --- | --- |
| `all.<集群域名>` | A / AAAA | 本集群全部线路的健康节点地址 |
| `<线路名称>.<集群域名>` | A / AAAA | 该线路节点组内的健康节点地址 |
| `<网站 UUID>.<集群域名>` | CNAME | `all.<集群域名>`；每个至少有一个已验证域名的网站一条，停用或暂停的网站同样保留 |
| `<线路名称>.<网站 UUID>.<集群域名>` | CNAME | `<线路名称>.<集群域名>`；只在打开「保留站点线路别名」时 |

地址记录每个集群只写一份，记录数为「网站数 + 集群地址数」；打开「保留站点线路别名」时再加「网站数 × 线路数」。网站「域名」页签列出的线路目标在关闭线路别名时为 `<线路名称>.<集群域名>`。

线路是明确的节点组主机名，不调用服务商的运营商或地理解析功能。

### 手动模式

控制台不写入 DNS。集群「DNS」页签列出需要手动创建的记录（绝对名称）与 BIND zone 文件，「下载」保存为 `<区域>.zone`。

| 项目 | 行为 |
| --- | --- |
| 地址 | 全部启用节点的地址，不按健康状态筛选：手动记录不会随节点健康变化 |
| 网站 | 每个网站一条 CNAME；也可以用一条 `*.<集群域名> CNAME all.<集群域名>` 代替逐个网站的记录 |
| CNAME 目标 | 网站「域名」页签照常显示，状态为「手动」 |
| 切换模式 | 自动切换到手动时，已写入的记录保留，控制台不再修改；切换到「不管理」时才清理 |

### 从全局 DNS 配置升级

此前版本的平台 DNS 是一份全局配置。升级后它转换为每个集群一条绑定，租户不需要修改任何 DNS：

- 每个集群的集群域名为原来的 CNAME 域，网站的 CNAME 目标名称不变，解析结果与升级前相同。
- 原来启用时，模式为「自动」并打开「保留站点线路别名」，原来显示给租户的线路目标 `<线路>.<网站 UUID>.<CNAME 域>` 继续解析；原来关闭时，模式为「不管理」，账号、域名与线路保留在表单中。
- 多个集群共用原来的 CNAME 域时，汇总记录依次命名为 `all`、`all-2`……（有网站的集群在前），网站 CNAME 指向所在集群的汇总记录。
- 原来按网站写入的地址记录 `all.<网站 UUID>.<CNAME 域>` 由下一次对账删除，只删除控制台登记过的名称。
- 此前的 DNS 版本保留在数据库中，不再显示。

### 健康摘除与修复

| 项目 | 行为 |
| --- | --- |
| 进入地址集合 | 节点已启用、45 秒内有心跳、数据面健康，并已应用所在集群的当前配置版本 |
| 检查周期 | 后台任务每分钟重新计算全部自动绑定，最多 4 个集群并发；离线、停用或配置落后的节点被摘除，恢复后加回 |
| 故障隔离 | 每个绑定独立发布与对账；一个服务商不可用只让使用它的集群的 DNS 版本失败，其他集群照常发布 |
| 生效时间 | 受 TTL 和递归缓存影响，不是即时切流 |
| 漂移修复 | 系统管理的名称被外部删除或修改后，下一次检查恢复；「修复记录」立即对该集群执行一次 |
| 接管范围 | 只增删本集群已登记为系统管理的名称；新名称上已有非系统记录时拒绝接管（`DNS_RECORD_CONFLICT`），名称已由其他集群管理时同样拒绝（`DNS_BINDING_CONFLICT`） |
| 写入顺序 | 先登记管理名称；同一名称的记录类型变化时先删除旧类型；按记录集整体替换变化的地址记录，再替换 CNAME；然后删除不再需要的记录，最后读回确认；失败时保留登记并在下一周期重试 |
| 配置金丝雀 | 节点按自己的目标版本判断：金丝雀窗口期间，非金丝雀节点运行稳定版本，不被摘除，见 [配置金丝雀](admin.md#配置金丝雀) |

DNS 版本的失败原因显示为：服务商认证失败、服务商找不到区域、服务商不可用、服务商限流、名称上已有不受管理的记录、名称已被其他集群管理、服务器地址被出站策略拒绝等。

### 大面积摘除保护

一次发布会把某个集群原来非空的 `all.` 或线路记录集清空，或摘除的地址记录超过阈值时，保留该集群的上一版记录，不写入服务商。控制台与节点通道断开、所有节点都被判定离线时，同样按此处理。

| 项目 | 行为 |
| --- | --- |
| 阈值 | 单次摘除的地址记录占该集群上一版地址记录的比例，默认 50%，**后台 → 平台 DNS → 大面积摘除保护** 可调（5%–100%），对全部集群生效 |
| 不计入 | 不再管理的名称（网站删除、线路移除）；服务商账号、集群域名或汇总记录名变化；模式不是「自动」 |
| 阻止时 | 集群「DNS」页签顶部显示被阻止的变更（将删除的地址记录数），DNS 版本列表中状态为 **已阻止**，「集群绑定」表中该集群为「已阻止」；发出该集群的平台告警「DNS 大面积摘除已阻止」 |
| 恢复 | 之后的发布不再触发保护时自动结束阻止，告警恢复 |
| 强制发布 | 管理员在集群「DNS」页签点击 **强制发布** 并确认，按当前状态发布；写审计 `dns.force_publish` |

### DNS 版本与回滚

每个集群有自己的 DNS 版本，不增加节点配置 revision。「回滚 DNS」恢复所选版本的绑定设置（模式、账号、集群域名、TTL、线路），地址仍按当前网站授权与节点健康计算，不恢复已离线的节点。手动模式的版本在保存时即为「已发布」。

删除服务商账号前，先把使用它的集群绑定改选其他账号或切换到「不管理」，并等待清理完成（账号不再持有系统管理的记录），否则返回 `DNS_PROVIDER_IN_USE`。删除集群前同样先把该集群的 DNS 切换到「不管理」并等待清理完成（`DNS_BINDING_IN_USE`）。

### 服务商与凭据

平台 DNS 账号和组织的 DNS 凭据（证书 DNS-01 与[自动写记录](#在自己的区域自动写记录)）使用同一份服务商目录与表单。给凭据授予目标区域所需的最小权限。

各服务商的适配器只通过录制的 API 交换测试（按官方 API 文档构造的请求与响应），没有在真实账户上验收；接入前先用「测试连接」确认。

| 服务商 | 凭据字段 | 最小权限 | 列出区域 | 根域 | 说明 |
| --- | --- | --- | --- | --- | --- |
| Cloudflare | API Token；Zone Token（可选） | API Token：目标区域的 Zone → DNS → Edit，以及 Zone → Zone → Read（也可以把区域读取放在 Zone Token 中） | 支持 | CNAME 展平 | TTL 最低 60 秒；新记录不经 Cloudflare 代理 |
| 阿里云 | AccessKey ID、AccessKey Secret、区域（可选）、STS Token（可选） | RAM：`alidns:AddDomainRecord`、`alidns:UpdateDomainRecord`、`alidns:DeleteDomainRecord` 限定 `acs:alidns:*:<账号 ID>:domain/<域名>`；`alidns:DescribeDomainRecords` 与列出区域用的 `alidns:DescribeDomains` 授予 `*` | 支持 | — | 中国站与国际站使用同一接入点；免费版 TTL 最低 600（被拒时按 600 重试一次） |
| 华为云 | AccessKey ID、Secret Access Key、区域（默认 `cn-north-4`） | IAM：`dns:zone:list`、`dns:recordset:list`、`dns:recordset:create`、`dns:recordset:update`、`dns:recordset:delete` | 支持 | — | 公网区域全局可见；国际站可填 `ap-southeast-3` |

| 西部数码 | 用户名、API 密码 | API 密码作用于整个账号 | 支持 | — | API 面向西部数码代理商开放；需在西部数码允许控制台的出口 IP（错误「ip 授权失败」） |

### 自建端点与出站策略

PowerDNS、RFC 2136 与自定义 HTTP 的地址由用户填写，每个连接都经过出站地址策略：

| 项目 | 行为 |
| --- | --- |
| 地址检查 | 在连接建立时检查实际连接的地址（防 DNS 重绑定）；回环、链路本地、私网等特殊用途地址只有在 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` 放行时才允许 |
| 加密 | 公网地址必须使用 HTTPS；明文 HTTP 只允许连接放行的内网地址 |
| 重定向 | 不跟随 |
| 可用范围 | 平台 DNS 账号与组织的 DNS 凭据都可以使用 |

### 自定义 HTTP 协议

每个操作是一个请求：

```text
POST <地址>
Content-Type: application/json
User-Agent: edgeweir-certd/1
X-Edgeweir-Timestamp: <Unix 秒>
X-Edgeweir-Signature: v1=<hex>
```

`<hex>` 为以签名密钥计算的 HMAC-SHA256（小写十六进制），输入为时间戳、`.` 与原始请求体。接收方用原始请求体重新计算并以常量时间比较，签名不符或时间戳与本地时钟相差超过 300 秒时返回 401。示例：密钥 `example-secret-0123456789`、时间戳 `1700000000`、请求体 `{"action":"zones"}` 的签名为 `v1=3af007dacbb4d9b54c57bc499f275d13e48a5513e8ecf036d83c1b5a6c0f20f8`。

请求体：

```json
{"action":"set","zone":"example.com","records":[{"name":"www","type":"A","data":"192.0.2.1","ttl":600}]}
```

| 字段 | 说明 |
| --- | --- |
| `zone` | 区域名，不带末尾的点；`zones` 操作没有此字段 |
| `records` | `list` 与 `zones` 没有此字段；`name` 相对于区域（根为 `@`），`type` 大写，`data` 为地址、主机名（可带末尾的点）或不带引号的 TXT 文本，`ttl` 为秒 |

| 操作 | 行为 |
| --- | --- |
| `list` | 返回区域的全部记录 |
| `append` | 添加记录，已有记录保留 |
| `set` | 请求中每个（名称、类型）在区域中只保留请求给出的记录，其余记录集不变 |
| `delete` | 删除名称、类型与值都匹配的记录；值为空时删除整个（名称、类型）记录集 |
| `zones` | 返回接收方管理的区域 |

成功返回 2xx 与 JSON（最大 16 MiB）：`list`、`append`、`set`、`delete` 返回 `{"records":[...]}`，`zones` 返回 `{"zones":["example.com"]}`。401 或 403 表示认证失败，404 表示区域不存在，`zones` 返回 501 表示不能列出区域；429 视为限流，5xx 视为不可用。错误响应可以带 `{"error":"简短说明"}`。签名只含时间戳，300 秒内的请求可能被重放：`set` 与 `delete` 是幂等的，`append` 需要接收方去重。

## 在自己的区域自动写记录

组织可以把自己的 DNS 凭据关联到区域并开启「自动写记录」，控制台为本组织在该区域内的网站域名写入所有权 TXT 与 CNAME。

1. 打开 **控制台 → 证书**，点击「添加 DNS 凭据」（已有凭据点击「编辑」）。
2. 选择服务商、填写凭据，点击「列出区域」选择区域或直接填写，点击「测试连接」。
3. 打开「自动写记录」，点击「创建」或「保存」。
4. 在网站中添加该区域内的域名。验证：网站「域名」页签的「自动写记录」卡片中，记录状态变为「已写入」；所有权 TXT 被解析到后域名自动变为「已验证」。

| 记录 | 写入条件 |
| --- | --- |
| `_edgeweir-verification.<可注册域>` TXT `edgeweir=<token>` | 该可注册域尚未验证；验证后删除。同名的其他 TXT 值保留 |
| `<网站域名>` CNAME `<网站的 CNAME 目标>` | 网站所在集群的 DNS 模式不是「不管理」；泛域名写 `*.<域名>` |
| 区域根 | 服务商支持 CNAME 展平时写 CNAME，支持 ALIAS 时写 ALIAS；其他服务商显示「根域需手动设置」，不写入 |

| 项目 | 行为 |
| --- | --- |
| 冲突 | 名称上已有 A、AAAA 或 CNAME 记录时不覆盖，状态为「有冲突」并列出这些记录；组织成员点击「覆盖」并确认后，删除这些记录并写入 CNAME，写审计 `dns_record.overwrite` |
| 删除 | 删除网站或域名、关闭「自动写记录」时，只删除控制台写入的记录（按名称、类型与值匹配） |
| 漂移 | 写入的记录被外部删除后，下一次同步重新写入 |
| 同步 | 后台任务每分钟同步一次；卡片中的「同步」立即执行 |
| 目标变化 | 集群域名变化后，CNAME 更新为新的目标 |
| 隔离 | 只为本组织的网站写记录；其他组织的凭据即使指向同一区域也不会写入本组织的域名 |
| 审计 | `dns_record.create`、`dns_record.update`、`dns_record.delete`、`dns_record.conflict`、`dns_record.confirm`、`dns_record.overwrite`，带组织 |
| 删除凭据 | 仍有自动写入的记录时返回 `DNS_CREDENTIAL_IN_USE`：先关闭「自动写记录」，等待清理完成 |

## 配置告警渠道

仅平台管理员可用。

1. 打开 **后台 → 告警渠道**，点击「添加渠道」。
2. 填写「名称」，选择「渠道类型」，填写该类型的字段（见下表）。
3. 选择「通知语言」。
4. 按需打开「接收所有网站的告警」和「允许租户订阅」。
5. 点击「创建」。
6. 验证：点击「发送测试」，目标收到测试通知；渠道行不显示「通知发送失败」。

邮件渠道使用 **后台 → 系统设置 → SMTP** 中的服务器，见[平台管理](admin.md)。

### 渠道字段

| 渠道类型 | 字段 | 约束 |
| --- | --- | --- |
| Webhook | Webhook 地址、Bearer 令牌（可选） | HTTP POST JSON；公网目标必须 HTTPS |
| 邮件 | 收件地址 | 1–20 个地址，逗号或空格分隔 |
| 钉钉 | Webhook 地址、签名密钥（可选） | 主机必须为 `oapi.dingtalk.com`；填写签名密钥时附加 timestamp 与 HMAC-SHA256 签名 |
| 企业微信 | Webhook 地址 | 主机必须为 `qyapi.weixin.qq.com` |
| Telegram | 机器人令牌、会话 ID | 调用 Bot API `sendMessage`，关闭链接预览 |

| 开关 | 默认值 | 作用 |
| --- | --- | --- |
| 接收所有网站的告警 | 关 | 渠道接收全平台所有网站的告警，无需订阅 |
| 允许租户订阅 | 关 | 租户可在「告警」页面订阅该渠道 |

平台最多 32 个渠道。编辑渠道时，打开「更新渠道凭据」重新填写类型与字段；不打开则保留原凭据。

### Webhook 载荷

请求体为 JSON，包含 `id`（事件 ID）、`siteId`、`siteName`、`kind`、`status`（`firing` / `resolved`）、`occurredAt`、`text` 和 `url`（控制台中该网站的链接）。配置了 Bearer 令牌时附带 `Authorization: Bearer <令牌>`。接收方返回 2xx 视为成功。

## 设置告警规则

1. 打开 **后台 → 告警渠道**，在「告警规则」卡片中修改阈值。
2. 点击「保存」。

| 字段 | 取值 | 默认值 | 告警种类 | 触发条件 |
| --- | --- | --- | --- | --- |
| 离线阈值（秒） | 45–3600 | 90 | 节点离线 | 网站所在集群的已启用节点超过阈值未上报，或上报数据面不健康 |
| 证书到期预警（小时） | 1–720 | 72 | 证书即将到期 | 网站当前证书在阈值内到期 |
| 最低请求数 | 1–1000000 | 100 | 服务端错误率过高 | 统计窗口内请求数达到该值 |
| 统计窗口（分钟） | 1–60 | 5 | 服务端错误率过高 | 计算 5xx 比例的时间窗口 |
| 5xx 阈值（%） | 1–100 | 20 | 服务端错误率过高 | 窗口内 5xx 比例达到该值 |

「源站不可用」没有单独阈值：某个节点上报网站全部源站在离线阈值内均处于不健康状态时触发。源站状态来自被动健康检查，见[源站与缓存](origins-and-cache.md#被动健康检查)。

网站告警只针对已启用、未暂停且至少有一个已验证域名的网站。

### 平台告警

以下告警属于平台而不是网站，只投递到开启「接收所有网站的告警」的渠道，不能订阅；**控制台 → 告警** 的「近期告警」只对平台管理员显示。

| 告警 | 触发 | 恢复 |
| --- | --- | --- |
| 配置金丝雀发布已回滚 | 金丝雀自动回滚或管理员中止 | 该集群下一次推进 |
| 没有在线的金丝雀节点，配置已直接发布到全部节点 | 开启金丝雀的集群发布时没有在线的金丝雀节点 | 该集群下一次发布有在线的金丝雀节点 |
| DNS 大面积摘除已阻止 | [大面积摘除保护](#大面积摘除保护) 阻止了某个集群的一次发布；告警名称为集群名 | 该集群下一次发布通过或强制发布 |

## 订阅告警

1. 打开 **控制台 → 告警**，点击「订阅告警」。
2. 在「搜索网站」中查找并选择网站，选择「通知渠道」，勾选告警种类。
3. 点击「保存」。
4. 验证：订阅出现在列表中；「近期告警」显示该网站的事件。

租户只能订阅自己可见的网站和「允许租户订阅」的渠道。

## 投递行为

| 项目 | 行为 |
| --- | --- |
| 事件 | 同一条件只在进入告警和恢复时各产生一个事件，事件 ID 固定 |
| 重试 | 失败后按 2、4、8、16 分钟退避重试，每个渠道共尝试 5 次 |
| 重复 | 网络回执丢失时接收方可能收到重复通知；Webhook 接收方按事件 ID 去重 |
| 投递前检查 | 每次投递重新检查订阅者的组织成员关系、账号停用状态、组织两步验证要求和渠道可见性 |
| 出站策略 | 解析并固定目标 IP；拒绝特殊用途地址；Webhook 类目标不跟随重定向；内部 Webhook 或 SMTP 需在 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` 中放行对应网段 |
| 超时与大小 | 单次投递 10 秒；请求体最大 32 KiB，响应体最大 64 KiB |
| 保留 | 告警事件保留 90 天 |
| 敏感字段 | 渠道接口和失败记录不返回密码、机器人令牌、Webhook 密钥或服务商原始错误 |

## 限制

| 项目 | 说明 |
| --- | --- |
| 后台任务 | 平台 DNS 同步、自动写记录、告警检查与投递由后台任务每分钟执行，需要至少一个 `ROLE=worker` 或 `ROLE=all` 的控制台进程，见[部署概览](../deploy/README.md) |
| 智能解析 | 不使用服务商的运营商线路或地理解析；线路即节点组 |
| 权威 DNS | 不运行权威 DNS，只通过服务商 API 管理记录 |
| 单次操作 | 每次服务商调用最长 2 分钟 |
| 主动探测 | 不做主动可达性探测；源站状态只来自真实流量 |
| 本地模拟服务 | 「本地模拟服务」只在设置 `EDGEWEIR_DNS_TEST_ENDPOINT` 时出现，仅用于测试 |

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「尚未找到 TXT 校验记录」 | 记录未生效，或所用递归服务器缓存了旧结果 | 用 `dig` 查询确认；检查 **后台 → 系统设置 → 所有权校验 DNS** |
| 「请稍后重试校验」 | 5 秒内重复校验，或并发查询已满 | 等待后重试 |
| 「请输入可注册域名下的主机名」 | 域名不在公共后缀之下，例如直接使用公共后缀 | 使用可注册域或其子域名 |
| 「域名已被使用」 | 该可注册域已由其他组织验证 | 由平台管理员撤销原组织的验证 |
| 「CNAME 域不属于该 DNS 区域」 | 集群域名不在账号的区域内 | 改用区域本身或其子域名 |
| 「该 DNS 名称已有非系统管理的记录」 | 目标名称上已有手工记录 | 删除手工记录后「修复记录」 |
| 「该名称已被其他集群的 DNS 绑定使用」 | 两个集群在同一区域使用相同的集群域名与线路名称 | 改用不同的集群域名或线路名称 |
| 「DNS 服务商仍在使用中」 | 账号仍被集群绑定选中或仍持有记录 | 改选其他账号或切换到「不管理」，等待清理完成后删除 |
| 「先关闭该集群的 DNS，等待记录清理完成」 | 删除集群时它的 DNS 仍为「自动」或仍持有记录 | 切换到「不管理」，等待清理完成 |
| 「DNS 服务商认证失败，请检查凭据与权限」 | 凭据错误、过期或权限不足；部分服务商还要求允许控制台的出口 IP | 按[服务商与凭据](#服务商与凭据)检查权限后「测试连接」 |
| 「服务器地址是内网或特殊用途地址，或公网地址未使用 HTTPS」 | 自建端点的地址被出站策略拒绝 | 使用 HTTPS，或在 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` 放行内网地址段 |
| 自动写记录显示「有冲突」 | 名称上已有 A、AAAA 或 CNAME 记录 | 确认后点击「覆盖」，或手动处理后「同步」 |
| 「CNAME 目标」显示「无健康节点」 | 线路内没有满足条件的节点 | 检查节点心跳、数据面状态和已应用版本 |
| 渠道显示「通知发送失败」 | 目标拒绝、超时，或地址被出站策略拒绝 | 「发送测试」复现；内网目标加入 `EDGEWEIR_OUTBOUND_ALLOW_CIDRS` |
| 「通知渠道数量已达上限」 | 已有 32 个渠道 | 删除不用的渠道 |

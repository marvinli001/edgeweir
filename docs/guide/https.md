# HTTPS 与证书

证书属于组织。控制台的证书页面可上传 PEM 证书链与匹配私钥，也可申请 ACME 证书；网站的 HTTPS 页签选择证书、跳转策略、HSTS、TLS 档位、HTTP/2、HTTP/3 和压缩选项。保存会发布新的集群配置。只有节点回报已应用的版本，才表示配置已在该节点生效。

## 签发与续期

`edgeweir-certd` 使用 lego 和 libdns，由 pg-boss 启动。账户私钥、证书私钥、DNS 凭据分别使用绑定记录 ID 的信封加密。凭据只通过 stdin/stdout 传递，不放进命令行、日志或 NodeConfig。

- HTTP-01：域名先指向节点的 HTTP 端口。控制面把短期挑战发布给本组织的精确域名，等待在线节点确认应用后才请求 CA 验证。挑战路径不重定向、不缓存，过期后不再提供响应。
- DNS-01：先添加对应区域的 DNS 凭据。支持 Cloudflare、阿里云、华为云与 DNSPod；每张证书使用一个 DNS 区域。通配符必须使用 DNS-01。DNSPod 使用传统 `ID,Token` 凭据；当前发布的 libdns DNSPod 适配器与 libdns v1 不兼容，本项目提供有界的接口适配。
- ZeroSSL：选择该 CA 时必须填写 EAB key ID 和 HMAC key；它们与 ACME 账户一起加密保存。
- 续期优先使用 CA 的 ARI 窗口；没有 ARI 时，在证书寿命经过三分之二时续期，不写死天数。后台每分钟检查到期任务，失败后保留当前证书并重试。手动续期也通过同一工作队列。

DNS TXT 写入前会保存清理记录，helper 正常结束、超时或进程中断后均可按记录恢复清理，只删除本次挑战的 TXT 值。仍有清理责任时，证书和 DNS 凭据不能删除。

## 节点行为

证书材料通过 mTLS 单独获取；只有集群当前目标配置引用的 ID 和指纹获准下发。节点验证指纹、密钥匹配与域名覆盖，持久化文件为 `certificates.json`（0600）。节点本机的私钥并不加密；主机管理员仍能读取它们。

证书内容更新通过本地控制 socket 热更新，不重载 nginx。监听、TLS/压缩档位与对应的 SNI 名称属于结构性配置，需要先验证再重载；后续表推送失败时恢复原配置。只有配置持久化成功才报告应用成功，当前与上一份 last-known-good 引用的密钥都会保留。

配置回滚使用仍可用的当前证书材料。已删除、转移或释放的站点/域名不能靠历史配置重新取得授权；证书缺失、过期或不覆盖目标域名时拒绝回滚。

旧节点缺少 `required_features` 所要求的能力时拿不到该版本，后台显示需要升级。节点也会拒绝未知枚举和未知能力，继续使用 last-known-good。

## 协议范围

- 官方 OpenResty 1.31.1.1 镜像包含 HTTP/2 与 HTTP/3，已通过本地真实协议测试。HTTP/3 需要放通 HTTPS 对应的 UDP 端口。
- TLS 最低版本可选 1.2 或 1.3；密码套件采用固定的现代/兼容档位，不能注入任意 nginx 配置。
- OCSP 装订只接受经过签名、证书身份和有效期验证的响应；访问响应服务时拒绝私网/特殊地址和跳转，限制超时与响应大小，并在过期前刷新。没有 OCSP 服务的证书不会生成装订响应。
- Gzip 使用 nginx 的类型和最小响应长度控制；`text/html` 是 nginx 固定支持的类型。Brotli、Zstd 缺少模块，当前明确不可用，不能通过 API 启用。

## 验证范围

`scripts/e2e-m3.mjs` 使用本地 Pebble 验证 HTTP-01、可信证书、跳转、HSTS、HTTP/2、HTTP/3、无 reload 续期和 TLS 最低版本。HTTP/3 使用独立容器中的 Go QUIC 客户端，避免宿主机端口转发或 curl 构建缺少 QUIC 影响测试。Playwright 覆盖申请证书、选择证书、保存设置、桌面与 375px 深色界面，并断言没有页面异常。

这些测试不等于 DNS 服务商或 ZeroSSL 的真实账户验收；外部凭据、CA 限额、DNS 传播及公网防火墙需要部署者另行验证。测试用 Pebble 密钥仅用于本地环境，不得作为实际服务的信任根。

# 源站与缓存

控制台网站详情页的「源站」「缓存」Tab 和「刷新预热」页面的行为说明。界面上不放说明文字，细节以本文为准。实现见 [ADR-0014](../adr/0014-node-agent-responsibilities.md)、[ADR-0015](../adr/0015-openresty-build-and-cache.md) 的 MVP M2 更新记录。

## 源站池

每个网站有一个源站池。源站分为主源和备用源：

- **主源**按负载均衡策略分配流量；**备用源**只在所有主源都不可用时接流量，或作为主源失败后的重试。
- **负载均衡**：
  - 加权随机：按权重随机选择。
  - 轮询：平滑加权轮询（与 nginx 相同的算法），每个 worker 各自计数。
  - 一致性哈希：按请求 URI（路径 + 查询）哈希，同一 URI 固定落在同一源站，适合源站自身也有缓存的场景。某个源站不可用时只有它的 URI 会换源站。
- **重试**：一次请求最多尝试 3 个源站。连接失败、超时、502/503/504 会换下一个源站重试（POST 等非幂等请求在请求已发出后不重试）。重试不会在 HTTP 与 HTTPS 源站之间切换，下一次请求会。

### 源站地址限制

源站不能指向特殊用途地址，防止借 CDN 访问内网、云元数据接口或节点自己：

- 拒绝的 IPv4 地址段：`0.0.0.0/8`、`10.0.0.0/8`、`100.64.0.0/10`、`127.0.0.0/8`、`169.254.0.0/16`、`172.16.0.0/12`、`192.0.0.0/24`、`192.0.2.0/24`、`192.168.0.0/16`、`198.18.0.0/15`、`198.51.100.0/24`、`203.0.113.0/24`、`224.0.0.0/4`、`240.0.0.0/4`。
- 拒绝的 IPv6 地址段：`::/128`、`::1/128`、`100::/64`、`2001:db8::/32`、`fc00::/7`、`fe80::/10`、`ff00::/8`；IPv4 映射地址（`::ffff:0:0/96`）和 NAT64 地址（`64:ff9b::/96`）按其中的 IPv4 地址判断。
- `localhost` 和 `*.localhost` 总是拒绝。`127.1`、`2130706433`、`0x7f000001` 这类会被解析器当成数字的名称不是合法的源站地址。
- 控制台在保存源站时检查 IP 字面量（错误码 `ORIGIN_ADDRESS_FORBIDDEN`），节点对配置里的地址和每一次 DNS 解析结果执行同样的检查；解析到这些地址的域名源站在节点上记为回源失败（`address_forbidden`）。
- 平台管理员可以在「系统设置 → 源站地址允许清单」放行地址段（每行一个 CIDR，也可调用 `PUT /api/v1/settings/origin-allow-list`，`{"cidrs": ["10.0.0.0/8"]}`）。清单对所有组织生效，保存后给每个集群发布新版本；回滚到旧版本时沿用当前清单。

### 被动健康检查

没有探测请求，真实流量就是探测：

- 连接失败、超时、502/503/504、域名解析失败都算一次失败，其他响应清零。
- 连续失败达到「失败次数」后，源站在「恢复时间」内不再被选中；之后流量会再次尝试它，成功一次才恢复为健康，再失败一次立即重新标记为不可用。
- 所有源站都不可用时仍然会尝试（失败开放），避免健康状态误判导致全站不可用。
- 源站 Tab 显示每个源站在多少个在线节点上不可用以及最后一次错误，节点每 15 秒随心跳上报。

### 回源 Host、SNI 与证书校验

- 回源 Host 留空时使用访问者请求的 Host；S3 源站留空时使用源站地址（非默认端口时带端口）。
- SNI 留空时取回源 Host（去掉端口），再留空取源站地址。
- 回源 HTTPS 默认用节点系统 CA（`/etc/ssl/certs/ca-certificates.crt` 等，或 `--trusted-ca` 指定）校验源站证书和 SNI 对应的域名。关闭校验只影响该网站；不校验的连接不进入连接池，避免被需要校验的网站复用。

### 连接与超时

- 连接、发送、读取超时按网站设置，读取超时也是 WebSocket 的空闲超时。
- keep-alive 连接池按「源站 IP + 端口 + SNI」区分，可设置空闲时间和单连接最大请求数，也可以关闭。
- WebSocket 默认透传，不经过缓存；关闭后升级请求返回 403（`X-Edgeweir-Error: websocket-disabled`）。

### S3 兼容对象存储

源站开启「S3 签名」后，节点用 AWS Signature V4 签名回源请求：

- 填写区域、Access Key ID、Secret Key；bucket 填写后使用路径式地址（`/<bucket>/<key>`），源站地址本身已包含 bucket 时（如 `assets.s3.us-east-1.amazonaws.com`）留空。
- 只转发 GET 和 HEAD，其他方法返回 405；访问者的查询字符串不转发给对象存储。
- Secret Key 只写不读：保存后界面不再显示，留空表示沿用已保存的密钥，更换 Access Key ID 时必须重新填写。密钥用主密钥信封加密入库，只经节点通道（mTLS）下发，节点保存在状态目录（0600），用于控制台不可达时重启。

## 缓存规则

规则按列表顺序（可拖动排序）匹配，第一条适用的规则决定是否缓存和缓存多久。没有适用的规则时不缓存。

- **请求条件**：路径前缀、精确路径、后缀。同一条规则里填写的条件都要满足，留空的条件不限制。
- **响应条件**：状态码、响应大小（按 Content-Length，Range 响应按完整大小；不知道大小时不满足大小条件）。请求条件满足但响应条件不满足时，交给后面的规则判断。
- **动作**：缓存或不缓存。
- **缓存时间**：
  - 覆盖源站缓存头：使用规则的缓存时间（不填状态码时只缓存 200、203、206、300、301、308）。
  - 遵循源站缓存头：源站给了 `Cache-Control` / `Expires` 时按源站的来，没有时使用规则的缓存时间；源站的 `no-store`、`private` 生效。
  - 带 `Set-Cookie` 的响应不缓存。
- **带 `Authorization` 的请求**：默认绕过缓存，响应也不存入缓存（RFC 9111 §3.5），即使规则覆盖了源站缓存头。只有规则打开「缓存带 Authorization 头的请求」后才按该规则缓存，此时所有持有凭据的访问者共用同一份缓存，只适合与凭据无关的内容。需要 proto v0.2.1 及以上的节点，更早的节点忽略这个开关。
- **过期后**：
  - stale-while-revalidate：过期后这段时间内先返回旧内容，同时在后台刷新。
  - stale-if-error：过期后这段时间内源站出错（连接失败、超时、5xx）时返回旧内容。
  - 两者默认关闭。访问者看到的 `Cache-Control` 仍是源站原来的值。

## 缓存键

缓存键按网站设置，对所有规则生效：

- **查询参数**：全部（默认）、忽略、只保留白名单中的参数；可以对保留的参数排序，使 `?a=1&b=2` 与 `?b=2&a=1` 命中同一缓存。
- **请求头、Cookie**：列出的请求头或 Cookie 的值不同，就分别缓存。
- **设备类型**：按 User-Agent 区分移动端（含平板）与桌面端。
- **包含 Host**：关闭后网站的所有域名共用缓存。
- 修改缓存键后，按旧键缓存的对象通常不再命中，由缓存区按 `inactive` 时间回收。

## Range 与分片缓存

开启「分片缓存」后，可缓存的 GET/HEAD 请求按 1 MiB 分片回源和缓存，Range 请求只需要命中涉及的分片。源站必须支持 Range（返回 206）。不开启时，Range 请求会先回源完整对象再返回范围。

## 刷新与预热

「刷新预热」页面提交的任务下发到网站所在集群的每个启用的节点，逐节点显示结果。停用的节点不接收任务，显示为「已跳过」（`node_disabled`），不计入进度；停用节点时它尚未完成的任务同样记为已跳过。

- **URL 刷新**：刷新该 URL 的所有缓存变体（不同查询形式、设备、请求头、Cookie、分片），按网站的缓存键规则比较查询参数和 Host。
- **目录刷新**：刷新该 Host 下路径以该前缀开头的所有 URL（按字符串前缀比较，不带查询参数）。
- **全站刷新**：刷新网站的全部缓存。
- **URL 预热**：节点按正常请求取回 URL 并缓存（2xx、3xx 算成功，不跟随跳转）。HTTPS URL 的预热要等节点有 HTTPS 监听（MVP M3）。
- 刷新不删除磁盘文件：刷新后的下一次请求使用新的缓存键并回源（`X-Cache: MISS`），旧对象按缓存区的 `inactive` 时间和容量上限回收。
- URL 必须以 `http://` 或 `https://` 开头，Host 必须是自己网站的域名（含泛域名下的子域名）。一次最多 500 条。
- 节点离线时任务保持待执行，节点恢复后执行；7 天内没有执行的任务记为失败（`task_expired`）。
- 节点错过的刷新会补上：离线超过 7 天后重新连接的节点、停用后重新启用的节点，下一次拉取任务时不再执行过期的刷新，而是对这些刷新涉及的每个网站收到一次全站刷新（每个组织一个任务，来源显示为「系统（补发整站刷新）」，只发给这个节点）；原来的任务在该节点下标记「节点重新连接时已补发整站刷新」。预热错过了不补。

## 升级说明

从 MVP M1 升级到 M2 及以后版本时注意：

- **HTTPS 源站默认校验证书。** 升级后节点按「回源 Host、SNI 与证书校验」一节校验 HTTPS 源站的证书和域名。使用自签名证书、证书域名与 SNI 不符或证书链不完整的源站会回源失败（502，源站健康显示 TLS 失败），需要换成受信任的证书，或者在该网站「源站」Tab 关闭证书校验。
- **特殊用途地址的源站被拒绝。** 已保存的源站如果是内网、回环等地址（见「源站地址限制」），节点不再回源到这些地址，修改源站时控制台也会拒绝保存。确实需要回源到内网的，请平台管理员把对应地址段加入源站地址允许清单。

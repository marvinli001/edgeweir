# 扩展

节点扩展把你信任的发布者编写的 Lua 代码加入边缘请求路径：响应头、裁决、规则字段、HTML 片段、小型端点。控制台负责安装、配置并按网站开启；节点校验并加载。格式与运行时契约见[节点扩展](../reference/extensions.md)。

> 扩展以 nginx worker 的权限在节点的 worker 内运行，能看到开启它的每个网站的请求与响应。只在你愿意让某个发布者的代码跑在自己边缘上时才信任其密钥（威胁模型见 SECURITY.md）。

## 概念

| 术语 | 定义 |
| --- | --- |
| 扩展包 | `.ewx` 文件（gzip ustar：`manifest.json`、`lua/`、`assets/`）及其签名 `.ewx.sig` |
| 发布者密钥 | 你为某个发布者名称信任的 Ed25519 公钥（JWK）；kid 是密钥的 RFC 7638 指纹。默认没有 |
| 版本 | 同一扩展 id 上传过的扩展包都保留，其中一个为当前版本 |
| 能力 | 扩展包可以做的事（裁决、改请求头或响应头、读请求体、注入 HTML、改写响应体、建立连接、定时器）；安装前展示 |
| 失败模式 | `open`（默认）：出错的扩展被跳过。`closed`：出错期间开启它的网站上的请求返回 503 |
| 总开关 | 一次停止所有节点上的所有扩展；扩展包与设置保留 |

## 安装

1. 打开**系统** → **扩展**。
2. 在**受信任密钥**中添加发布者的公钥（JWK 或其 `x`），填写发布者给出的发布者名称。核对 kid 与发布者公布的是否一致。
3. 点击**安装**，选择 `.ewx` 与 `.ewx.sig` 文件。控制台校验扩展包并显示名称、版本、发布者、密钥、钩子与能力，此时不保存任何东西。
4. 再点**安装**。新扩展默认**关闭**；为已安装的扩展安装更新版本即切换到该版本。
5. 打开扩展，填写全局设置，选择失败模式并**启用**。

## 在网站上开启

1. 打开**网站** → 选择网站 → **扩展**。
2. 开启扩展并填写网站设置，**保存**。

设置、启用与总开关是热更新。安装、升级或移除网站正在使用的扩展会让该网站所在集群的节点重载 nginx。集群里有不支持 `extensions-v1` 的活动节点（旧节点，或以 `--no-extensions` 启动的节点）时，拒绝启用。

## 规则、日志与统计

| 位置 | 内容 |
| --- | --- |
| 规则 | 扩展声明的字段 `ext.<id>.<name>`，用于请求阶段（例如 `ext.hello-header.greeted eq true`）。仍被规则读取的扩展或版本不能移除 |
| 访问日志 | 拦截原因**扩展**，规则 `ext:<id>`；扩展的日志字段与裁决 |
| 统计 | 扩展的计数器与 `ext.<id>.faults`，按网站和分钟 |
| 扩展详情 | 每个节点：已加载、等待中、失败或不支持，以及故障与熔断次数 |

## 节点

| 参数 | 作用 |
| --- | --- |
| `--no-extensions` | 节点不下载、不运行扩展，也不声明 `extensions-v1` |
| `--extension-keys FILE` | 节点只接受此本地文件中的密钥签名的扩展包（每行一个 JWK，或一个 JSON 数组），不论控制台信任哪些密钥 |

## 移除

- **删除版本**移除非当前的版本。
- **卸载**移除扩展、它的各版本与网站设置；须先让规则不再使用它的字段。节点在下一次配置后删除解包的文件。
- 仍有已安装版本由某个受信任密钥签名时，不能移除该密钥。

# 挑战与 CC 防护

按规则、按网站或全局（Under Attack）或随请求量自动逐级升级（分级 CC）要求访客先通过挑战；通过后在有效期内凭通行凭证访问。

## 概念

| 术语 | 定义 |
| --- | --- |
| 挑战 | 节点代替源站返回的验证页面；通过后回到原 URL。 |
| 级别 | 挑战的强度，从低到高：Cookie 跳转（1）、JS 计算（2）、工作量证明（3）、图片验证码（4）。级别 L 的凭证满足不高于 L 的要求。 |
| 通行凭证 | 通过挑战后下发的签名 cookie，绑定网站、级别、客户端网段与 User-Agent。 |
| Under Attack | 没有有效凭证的 GET/HEAD 请求一律先挑战。按网站开启，或为所有网站开启（全局 Under Attack）。 |
| CC 防护 | 按网站配置的自动升级策略：条件持续一段时间后升一级，解除后冷却一段时间降一级。 |
| JA4 | TLS 客户端指纹，用于规则与限速，可记入访问日志。 |

## 挑战类型

| 类型 | 级别 | 通过方式 |
| --- | --- | --- |
| Cookie 跳转（`cookie302`） | 1 | 302 回到原 URL 并设置凭证；能保存 cookie 的客户端即可通过 |
| JS 计算（`js`） | 2 | 页面脚本计算一次 SHA-256 并提交 |
| 工作量证明（`pow`） | 3 | 浏览器在后台线程（Web Worker）中找到满足难度（前导零位数）的答案；默认 16 位，可调 8–24 |
| 图片验证码（`captcha`） | 4 | 输入图片中的 5 个字符；无脚本也能提交。页面提供「改用计算验证」：高难度工作量证明（默认 20 位，可调 8–26，不低于普通难度），通过后同样得到级别 4 的凭证。节点尚未取得验证码图片时直接使用高难度工作量证明 |

| 项目 | 行为 |
| --- | --- |
| 状态码 | 403；HEAD 只返回响应头 |
| 响应头 | `X-Edgeweir-Challenge: <类型>`（高难度工作量证明为 `pow`）、`Cache-Control: no-store, private`、`Content-Security-Policy`（`default-src 'none'`，脚本与样式只允许本页 nonce，表单与连接只允许本站） |
| 外部资源 | 无；图片以 `data:` 内联 |
| 语言 | 按 `Accept-Language` 显示中文或英文；无匹配时英文 |
| 动画 | 系统开启「减少动态效果」时不播放 |

| 请求 | 需要挑战但没有有效凭证时 |
| --- | --- |
| GET、HEAD | 返回挑战页（`cookie302` 为 302 跳转） |
| 其他方法（POST、PUT…） | 403 纯文本，`X-Edgeweir-Challenge: required`，不返回挑战页 |
| 节点尚未取得凭证密钥 | 503，`X-Edgeweir-Error: challenge-unavailable`（网站的错误页） |

### 保留路径

节点在确定网站之后直接处理以 `/.edgeweir/` 开头的路径，永不转发到源站：

| 路径 | 用途 |
| --- | --- |
| `POST /.edgeweir/challenge/verify` | 提交挑战答案（请求体最大 4096 字节，超出返回 413）；通过后 303 回到挑战前的 URL（只接受本站路径，不接受 `//` 开头与 `/.edgeweir/` 下的路径）；答案错误时重新显示挑战页，令牌无效、过期或已用过时 303 回到原 URL 重新挑战 |
| `GET /.edgeweir/challenge/worker.js` | 工作量证明的后台脚本 |
| 其他 | 404，`X-Edgeweir-Error: not-found` |

源站不能在该前缀下提供内容。CC 防护的单 IP 封禁同样作用于该前缀。

## 通行凭证

| 项目 | 行为 |
| --- | --- |
| Cookie | `__ew_pass`，`Path=/; Max-Age=<有效期>; HttpOnly; SameSite=Lax`，HTTPS 请求另加 `Secure` |
| 绑定 | 网站、通过的级别、客户端网段（IPv4 `/24`、IPv6 `/64`）、User-Agent 的哈希；换网段或换浏览器需要重新挑战 |
| 有效期 | 默认 1800 秒（30 分钟），网站可设 300–86400 秒 |
| 集群内通用 | 签名密钥（HMAC-SHA256）按集群分发，集群内任一节点都能验证；伪造或篡改的凭证被拒绝 |
| 密钥轮换 | 控制台每 24 小时轮换一次（每小时检查）；节点同时持有下一个、当前与上一个密钥，轮换前签发的凭证在到期前继续有效 |
| 防重放 | 每个挑战令牌只能兑换一次，令牌 5 分钟后失效 |

## 开启 Under Attack

1. 打开 **网站**，选择网站，进入「安全」页签。
2. 在「Under Attack」卡片的「挑战类型」中选择类型（默认「JS 计算」）；选择后立即保存。
3. 打开「Under Attack」开关，在「开启 Under Attack？」对话框中点击「开启」。卡片显示「已开启」，节点在配置发布后生效。
4. 验证：

   ```bash
   curl -sI -H 'Host: www.example.com' http://<节点 IP>/
   ```

   返回 403，响应头含 `X-Edgeweir-Challenge: js`。用浏览器打开网站，通过挑战后正常访问。

关闭：再点一次开关，在「关闭 Under Attack？」对话框中点击「关闭」。

攻击时自动开启、结束后自动关闭，见[自动缓解](attack-dashboard.md#自动缓解)；自动开启期间卡片显示「自动开启，至（时间）」。手动切换开关后，自动缓解不再管理本次开启。

为所有网站开启：

1. 打开 **防护设置**（`/protection`），在「防护」卡片的「挑战类型」中选择类型。
2. 打开「全局 Under Attack」，在「为所有网站开启 Under Attack？」对话框中点击「开启」。将向所有集群发布新配置。
3. 每个网站的「Under Attack」卡片随后显示「已为所有网站开启全局 Under Attack」。

全局 Under Attack 开启时修改「挑战类型」，点击「保存」后向所有集群发布。见[防护](system.md#防护)。

不离开当前页面：按 ⌘K / Ctrl+K，输入网站名或域名，选择「Under Attack：（网站）」并确认，开关切换到相反状态；「全局 Under Attack」同样切换全局开关。

以下请求不受 Under Attack 与 CC 挑战：

| 请求 | 说明 |
| --- | --- |
| ACME HTTP-01 验证（`/.well-known/acme-challenge/<令牌>`） | 控制台签发证书的令牌由节点在确定网站之前应答；其他令牌转发到源站，不缓存、不挑战 |
| 「放行」类 IP 名单中的地址 | 对所有网站生效，见 [IP 名单](rules.md#ip-名单) |
| 网站的本站放行名单中的地址 | 只对该网站生效，见[本站名单](access-control.md#本站名单) |
| 命中 `allow`（放行）规则的请求 | 在放行之前命中的 `challenge` 规则仍然生效 |
| 命中「跳过」规则且勾选「Under Attack 与 CC 挑战」的请求 | 同放行，见 [WAF 动作](rules.md#waf-动作) |
| 已验证的搜索引擎爬虫 | 网站打开「放行已验证的搜索引擎爬虫」时，见[已验证的搜索引擎爬虫](#已验证的搜索引擎爬虫) |

需要的级别取以下各项的最大值：全局 Under Attack、网站 Under Attack、网站当前的 CC 级别、该路径的 CC 级别，以及[灰名单](bans.md#灰名单)中要求挑战的条目。命中的 `challenge` 规则在规则阶段单独挑战。配置阶段的规则可按请求开关网站 Under Attack、关闭「CC 防护」或设置「CC 最高级别」，全局 Under Attack 不受影响，见[覆盖设置](rules.md#覆盖设置)。

## 挑战设置

「安全」页签的「挑战设置」卡片：

1. 在「预设」中选择宽松、标准（默认）或严格，填入下表前三项；选择「自定义」后逐项填写。保存的取值与任何预设都不同时显示为「自定义」。
2. 按需设置其余各项。
3. 点击「保存」。

| 字段 | 取值 | 默认值 |
| --- | --- | --- |
| 通行凭证有效期（秒） | 300–86400 | 1800 |
| 计算验证难度 | 8–24 | 16 |
| 高难度计算验证 | 8–26，不低于计算验证难度 | 20 |
| 访问日志记录 JA4 | 开 / 关 | 关 |
| 放行已验证的搜索引擎爬虫 | 开 / 关 | 关 |
| 挑战失败封禁 | 开 / 关；「10 分钟内失败次数」3–100；「封禁时长（秒）」60–86400 | 关；10；600 |
| 挑战页文案 | 「中文标题」「中文提示」「英文标题」「英文提示」，各 ≤ 200 个字符，纯文本 | 空（内置文案） |

| 预设 | 通行凭证有效期 | 计算验证难度 | 高难度计算验证 |
| --- | --- | --- | --- |
| 宽松 | 3600 | 14 | 18 |
| 标准 | 1800 | 16 | 20 |
| 严格 | 900 | 18 | 22 |

难度每增加 1，浏览器平均要做的计算翻倍。集群中有活动节点缺少 `challenge-v2` 时，卡片显示「集群中有节点不支持」，「放行已验证的搜索引擎爬虫」「挑战失败封禁」与「挑战页文案」不能开启或填写；已设置的值仍可修改或关闭。

## 已验证的搜索引擎爬虫

打开「放行已验证的搜索引擎爬虫」后，Under Attack（网站与全局）与 CC 要求挑战、而请求没有足够的凭证时，节点检查 User-Agent 是否声称下表的爬虫；声称时校验它的地址，通过则不挑战。`challenge` 规则、灰名单的挑战、封禁、CC 单 IP 封禁与其他检查照常。

| 名称 | User-Agent 包含（不区分大小写） | 反向解析的主机名须在 |
| --- | --- | --- |
| `googlebot` | `Googlebot`、`Storebot-Google`、`Google-InspectionTool`、`GoogleOther`、`Google-CloudVertexBot` | `googlebot.com`、`google.com`、`googleusercontent.com` |
| `bingbot` | `bingbot` | `search.msn.com` |
| `baiduspider` | `Baiduspider` | `baidu.com`、`baidu.jp` |
| `yandexbot` | `Yandex` | `yandex.ru`、`yandex.net`、`yandex.com` |
| `applebot` | `Applebot` | `applebot.apple.com` |

| 项目 | 行为 |
| --- | --- |
| 校验 | 对访客地址做反向解析（PTR，至多取 3 个名称），主机名等于或以 `.` 加上表域名结尾时，再正向解析该主机名（IPv4 访客查 A，IPv6 访客查 AAAA），结果包含访客地址才算通过。不下载第三方 IP 列表 |
| 解析器 | 节点的解析器（节点参数 `--resolver`，未设置时取 `--resolv-conf`，默认 `/etc/resolv.conf`）；单次查询超时 1 秒，至多 2 次 |
| 缓存 | 按地址与爬虫缓存在节点共享内存：通过 24 小时，未通过 1 小时，超时或解析失败 60 秒；同一地址正在查询时其他请求按未通过处理 |
| 规则字段 | `http.request.bot.verified`、`http.request.bot.name`，见[字段](rules.md#字段)；只在规则求值到它们时才查询 |
| 节点要求 | `challenge-v2` |

只做身份校验，不做评分。首次访问的爬虫地址要等待解析（至多数秒）；解析器不可用时爬虫照常被挑战。

## 挑战页文案

「挑战页文案」设置页面标题与标题下的一段提示，中文与英文各一套，按 `Accept-Language` 选用；留空的项用内置文案。纯文本，每项最多 200 个字符，不能含控制字符；节点输出前做 HTML 转义。只影响该网站的挑战页（Under Attack、CC、`challenge` 规则与灰名单）。需要节点能力 `challenge-v2`。

## 挑战失败封禁

打开「挑战失败封禁」后，同一地址（IPv4 地址，IPv6 所在 `/64`）从第一次失败算起 10 分钟内在本站提交挑战失败的次数达到「10 分钟内失败次数」时，节点在本站自动封禁它「封禁时长（秒）」（原因「挑战失败过多」），计数随即清零，见[自动封禁](bans.md#自动封禁)。

| 项目 | 行为 |
| --- | --- |
| 计为失败 | 答案错误；挑战令牌无效、过期或已用过 |
| 不计数 | 全局放行名单与本站放行名单中的地址、集群的可信代理 |
| 节点要求 | `challenge-v2` |

## 挑战规则

在网站「规则」页签或 **全局规则**（`/rules`）的「自定义 WAF」阶段选择动作「挑战」与「挑战类型」，例如只挑战登录页，或挑战指定的 JA4 指纹：

```text
http.request.uri.path eq "/login"
tls.ja4 in {"t13d1516h2_8daaf6152771_02713d6af862"}
```

请求带有级别足够的凭证时继续执行后续规则，否则按上文挑战。字段与语法见[规则](rules.md)。

## CC 防护

CC 防护按网站配置，默认关闭。「安全」页签的「CC 防护」卡片：

1. 打开「启用」。
2. 保持「跟随默认模板」使用 **防护设置 → CC 模板** 的阈值；关闭它后在「预设」中选择宽松、标准或严格，或选择「自定义」逐项填写。保存的阈值与任何预设都不同时显示为「自定义」。
3. 点击「保存」。

| 字段 | 取值 | 模板默认值 |
| --- | --- | --- |
| 最高级别 | Cookie 跳转 / JS 计算 / 工作量证明 / 图片验证码 | 图片验证码 |
| 验证码级别改用高难度计算验证 | 开 / 关 | 关 |
| 窗口（秒） | 5–60 | 10 |
| 网站 QPS | 0–1000000 | 1000 |
| 单 URL QPS | 0–1000000 | 200 |
| 单 IP QPS | 0–1000000 | 50 |
| IP 封禁时长（秒） | 60–86400 | 600 |
| 源站错误率（%） | 0–100 | 50 |
| 最小回源请求数 | 0–1000000 | 100 |
| 升级前持续（秒） | 1–3600 | 10 |
| 降级前冷却（秒） | 1–86400 | 60 |

阈值为 0 表示关闭该条件。跟随模板的网站在模板修改后自动使用新阈值（保存模板会为这些网站所在的集群发布新配置）。CC 模板在 **防护设置**（`/protection`）的「CC 模板」卡片修改，字段与上表相同，见 [CC 模板](system.md#cc-模板)。

| 预设 | 最高级别 | 网站 / 单 URL / 单 IP QPS | IP 封禁时长 | 源站错误率 / 最小回源请求数 | 升级前持续 / 降级前冷却 |
| --- | --- | --- | --- | --- | --- |
| 宽松 | 工作量证明 | 3000 / 600 / 150 | 300 | 70 / 200 | 20 / 60 |
| 标准（模板默认值） | 图片验证码 | 1000 / 200 / 50 | 600 | 50 / 100 | 10 / 60 |
| 严格 | 图片验证码 | 300 / 60 / 20 | 3600 | 30 / 50 | 5 / 300 |

三个预设的窗口都是 10 秒，验证码级别都不改用高难度计算验证。

| 条件 | 行为 |
| --- | --- |
| 网站 QPS | 网站的请求速率超过阈值：整个网站升级 |
| 单 URL QPS | 某个路径的速率超过阈值：只有该路径升级（按精确路径匹配），其他路径不受影响 |
| 单 IP QPS | 某个客户端的速率超过阈值（IPv4 按地址，IPv6 按 `/64` 计）：它在本站被自动封禁「IP 封禁时长」（原因「单 IP 请求过快」），见[自动封禁](bans.md#自动封禁) |
| 源站错误率 | 窗口内回源请求数达到「最小回源请求数」且错误（5xx 与连接失败）比例超过阈值：整个网站升级 |
| 升级 | 条件持续「升级前持续」后升一级，不超过「最高级别」 |
| 降级 | 所有条件低于阈值的 80% 并持续「降级前冷却」后降一级；介于 80% 与阈值之间时级别不变 |

> [!IMPORTANT]
> 计数与升级由每个节点在本地独立完成，阈值按单个节点计算。攻击分散到多个节点时，单个节点可能达不到阈值；按节点数折算阈值。

| 项目 | 行为 |
| --- | --- |
| 计数 | 滑动窗口（相邻两个窗口加权）；路径以有界 Top-K 统计，每个网站跟踪 64 个候选，最多 64 条升级路径。集群的可信代理（请求头未指明客户端时）不计数 |
| 最高级别为图片验证码 | 开启「验证码级别改用高难度计算验证」时，该级别改用高难度工作量证明 |
| 状态保留 | 节点重载与阈值修改后级别保留；关闭策略后再开启从「正常」开始 |
| 上报 | 级别变化、路径升降级与自动封禁每 5 秒上报一次，附当时请求最多的 IP 与路径（各最多 10 个，近似值） |

### 查看状态与事件

「安全」页签顶部「当前生效」一行显示：Under Attack（本网站或全局）、CC（预设名、「自定义」「跟随模板」或「关闭」）、CRS 的模式与预设、挑战设置的预设；在线节点的级别高于正常时还显示「节点：（最高级别）」。点击前四项跳到对应卡片，点击「节点：…」打开「攻击」页签。同一行右侧的「本站封禁」「全局规则」「防护设置」打开对应页面。

网站的「攻击」页签（见[攻击与自动缓解](attack-dashboard.md)）中与挑战和 CC 有关的区块：

| 区块 | 内容 |
| --- | --- |
| 节点当前级别 | 集群中每个活动节点上该网站的级别、在线状态与已升级的路径数（每 15 秒刷新） |
| 近期 Top IP 与路径 | 「时间范围」（1 小时、6 小时、24 小时、7 天、30 天）内事件中请求最多的地址与路径（近似值）；行右侧的「⋯」可「封禁 IP」（对话框预填本网站与该地址）或「刷新 URL」（路径展开到网站的每个非泛域名，确认后提交） |
| 挑战通过率 | 时间范围内的「已下发」「已通过」与「通过率」（不超过 100%）；Cookie 跳转只计入已下发 |
| 事件 | 级别变化、路径升降级与自动封禁的时间线：节点、触发条件（观测值 / 阈值），可按「事件类型」筛选；自动封禁的「⋯」可「在所有网站封禁」（全局范围的封禁对话框）或「解封」（解除本网站对该地址的封禁，覆盖它的网段封禁保留） |

事件默认保留 30 天，可在 **防护设置** 的「防护」卡片中把「安全事件保留天数」调为 7–365 天。网站在任一节点上从正常升级时触发告警「CC 防护升级」（`cc_mitigation`），同一网站 15 分钟内最多一次（被压下的升级在 15 分钟后仍未恢复时补发），所有节点回到正常后恢复，见[设置告警规则](alerts.md#设置告警规则)。

## JA4

JA4 是 TLS 客户端指纹（格式 `a_b_c`，例如 `t13d1516h2_8daaf6152771_02713d6af862`），在 TLS 握手时计算，同一连接上的请求共用。

| 部分 | 内容 |
| --- | --- |
| `a` | 协议（TCP 为 `t`，HTTP/3 为 `q`）、TLS 版本、是否带 SNI（`d` / `i`）、密码套件数、扩展数、ALPN 首个值的首尾字符 |
| `b` | 排序后的密码套件的 SHA-256 前 12 位 |
| `c` | 排序后的扩展（不含 SNI 与 ALPN）加上按原顺序的签名算法的 SHA-256 前 12 位 |

GREASE 值不计入。

| 用途 | 说明 |
| --- | --- |
| 规则字段 | `tls.ja4`（字符串，明文 HTTP 为空字符串），可用于各阶段规则的表达式，例如自定义 WAF、挑战与限速规则 |
| 限速键 | 限速规则的「限速键」可选 `tls.ja4`，同一指纹共享计数 |
| 访问日志 | 打开「访问日志记录 JA4」后采样日志在请求下方显示 JA4，见[访问日志](access-logs.md) |

> [!NOTE]
> TLS 版本取客户端 `supported_versions` 扩展中最高的版本；客户端没有发送该扩展时取握手协商出的版本，此时指纹的版本位是近似值。节点只统计 OpenSSL 识别的扩展，未识别的扩展（如 ALPS、ECH）不计入扩展数与哈希，指纹可能与其他 JA4 实现不同。

只实现 JA4（TLS 客户端指纹），不实现 JA4S、JA4H 等其他方法。

## 权限

| 调用方 | 读取 | 修改 |
| --- | --- | --- |
| 控制台会话（运维账号） | 是 | 是 |
| 演示账号 | 是 | 否，403 `DEMO_READ_ONLY` |
| 读写 AccessKey | 是 | 是 |
| 只读 AccessKey | 是 | 否，403 `ACCESS_KEY_READ_ONLY` |
| 服务账号 | 否，403 `SERVICE_ACCOUNT_FORBIDDEN` | 否 |

所有修改写审计：`site.protection_update`（网站的 Under Attack、挑战设置与 CC 防护）、`system.protection_update`（全局 Under Attack、事件保留天数）、`system.cc_template_update`（CC 模板）。

## 节点能力

| 功能 | 需要的能力 |
| --- | --- |
| Under Attack、CC 防护、挑战规则、配置规则开启 Under Attack | `challenge-v1` |
| 放行已验证的搜索引擎爬虫、挑战页文案、挑战失败封禁、`http.request.bot.*` | `challenge-v2` |
| `tls.ja4` 字段、JA4 限速键、JA4 日志 | `ja4-v1` |

运维账号的修改在集群有活动节点缺少所需能力时照常保存并发布；缺少能力的节点保留原配置，在 **集群与节点** 中显示「需要升级」，见[节点升级](node-upgrades.md)。服务账号与后台任务发布的配置新增需要的能力而集群节点缺少时返回 409 `NODE_CAPABILITY_REQUIRED`（「节点尚不支持：…（<节点>）」），原设置不变。不使用这些功能的集群配置不变。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「高难度计算验证的难度不能低于 N」（`PROTECTION_POW_DIFFICULTY`） | 高难度计算验证低于计算验证难度 | 调高高难度计算验证，或调低计算验证难度 |
| 节点显示「需要升级」 | 节点版本过旧，缺少 `challenge-v1`、`challenge-v2` 或 `ja4-v1` | 升级节点 |
| 「挑战设置」显示「集群中有节点不支持」 | 集群中有活动节点缺少 `challenge-v2` | 升级节点 |
| 「节点尚不支持：人机验证（<节点>）」 | 服务账号或后台任务发布的配置需要集群节点缺少的能力 | 升级节点 |
| 503，`X-Edgeweir-Error: challenge-unavailable` | 节点还没有取得凭证密钥 | 检查节点与控制台的连接 |
| 表单提交或 API 调用返回 403 与 `X-Edgeweir-Challenge: required` | 非 GET/HEAD 请求没有有效凭证 | 先用浏览器通过挑战；机器调用的接口用 `allow` 规则或「跳过」规则放行 |
| 通过挑战后又被挑战 | 凭证到期；客户端换了网段或 User-Agent；需要的级别高于凭证级别 | 调长有效期；检查代理出口是否在变化 |
| 搜索引擎爬虫仍被挑战 | 没有打开「放行已验证的搜索引擎爬虫」；该爬虫不在名单中；挑战来自 `challenge` 规则或灰名单；节点解析器查不到 PTR 或 A / AAAA 记录，或查询超时（60 秒后重试） | 打开该项；检查节点能否解析该地址的 PTR 记录 |
| 访客被 403 `ip-banned`，原因「挑战失败过多」 | 同一地址 10 分钟内挑战失败达到设置的次数 | 在 **IP 名单与封禁** 的「封禁」中解封；调高失败次数 |
| CC 防护迟迟不升级 | 流量分散到多个节点，单节点未达阈值 | 按节点数调低阈值 |

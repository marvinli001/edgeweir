# 用量保护

给自己的网站设置发送流量、请求数与带宽上限：用量达到预警阈值和上限时告警，到达上限时可以自动开启维护模式或停用网站，避免流量费用失控。用量来自节点每分钟上报的统计，控制台每分钟检查一次。

## 概念

| 术语 | 定义 |
| --- | --- |
| 周期 | 所选时区的自然日或自然月，从当地 0 点开始。夏令时切换的那天按 23 或 25 小时计。 |
| 发送流量 | 本周期内节点发给访客的字节数（含响应头），所有节点相加；与 `usage.list` 的 `bytesSent` 相同。 |
| 请求数 | 本周期内节点处理的请求数，所有节点相加。 |
| 带宽 | 网站所有节点在最近 5 个完整分钟内发送字节的平均速率，单位为十进制（1 Mbps = 10⁶ bit/s），每分钟重新计算；不按周期累计。 |
| 预警阈值 | 上限的百分比（1–99，默认 80），达到时发送「用量接近上限」告警；可以关闭。 |
| 动作 | 达到上限时：仅告警、开启维护模式、停用网站。 |
| 恢复方式 | 自动恢复或手动恢复，见[恢复](#恢复)。 |

## 设置

1. 打开 **网站** → 选择网站 →「概览」页签。
2. 在「用量保护」卡片点击「设置」（已设置时点击编辑按钮）。
3. 选择周期与时区（默认浏览器所在时区），至少填写一个上限，选择预警、达到上限时的动作与恢复方式，点击「保存」。

| 设置 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| 周期 | 每月 | 每天、每月 | |
| 时区 | 浏览器所在时区 | IANA 时区 | 周期从该时区的 0 点开始 |
| 发送流量（GB） | 不限 | > 0 | 1 GB = 10⁹ 字节 |
| 请求数 | 不限 | ≥ 1 | |
| 带宽（Mbps） | 不限 | 0.001–10000000 | |
| 预警 | 开，80% | 1–99 | |
| 达到上限时 | 开启维护模式 | 仅告警、开启维护模式、停用网站 | |
| 恢复方式 | 自动恢复 | 自动、手动 | 仅告警时不适用 |
| 带宽超限后保持（分钟） | 30 | 5–1440 | 只在自动恢复且设置了带宽上限时出现 |

保存后在下一次检查（1 分钟内）生效。卡片每分钟刷新，显示本周期各上限的用量、百分比与本周期的带宽峰值；用量达到预警阈值时进度条变为警示色，达到上限时为错误色。

## 达到上限时

| 动作 | 效果 |
| --- | --- |
| 仅告警 | 只发送告警。 |
| 开启维护模式 | 只打开网站的维护模式，沿用已保存的维护页、Retry-After、放行地址与放行路径（见[错误页与维护模式](error-pages.md)）：访客收到 503 维护页，放行的地址与路径照常访问。网站仍在节点配置中，DNS 不变。 |
| 停用网站 | 与在概览中停用网站相同：节点对网站的域名返回停用页（503 `site-disabled`），DNS 记录保留。 |

- 动作发布一个新的配置版本，原因为「网站 … 达到用量上限」，审计记录「用量保护执行动作」，操作者为系统，元数据含指标、本周期用量、上限与版本号。
- 网站已经处于该状态（你自己开启了维护模式或停用了网站）时不做任何事，恢复时也不会改动它。网站已停用时不会开启维护模式。
- 集群开启了金丝雀发布时，动作与其他配置一样先发到金丝雀节点，按发布策略推进。
- 节点不支持该动作需要的能力等原因导致发布失败时，告警照常发送，卡片显示「动作未能发布，每分钟重试」，接口的 `lastError` 为错误码（如 `NODE_CAPABILITY_REQUIRED`）。

## 恢复

| 情况 | 自动恢复 | 手动恢复 |
| --- | --- | --- |
| 新周期开始 | 解除 | 保持 |
| 调高或删除上限后不再超出 | 解除 | 保持 |
| 带宽回落 | 最后一次超出后保持「带宽超限后保持」的时间，之后解除；再次超出再次执行 | 保持 |
| 点击卡片上的「恢复」 | 解除，本周期内不再执行动作 | 同左 |
| 你在概览启用网站或关闭维护模式（包括批量启用） | 同「恢复」 | 同左 |
| 修改动作（如改为仅告警） | 先解除原动作，需要时执行新动作 | 同左 |
| 删除用量保护 | 解除 | 解除 |

- 只解除用量保护自己执行的动作。解除发布新的配置版本，原因为「解除网站 … 的用量保护动作」；自动解除的审计记录为「用量保护解除动作」（系统），点击「恢复」的为「手动恢复用量保护的动作」（你）。
- 手动恢复后卡片显示「已手动恢复，… 前不再执行动作」；告警照常。再次保存设置会取消这次暂停。

## 告警

| 告警 | 触发 | 恢复 |
| --- | --- | --- |
| 用量接近上限（`usage_warning`） | 本周期某项用量达到预警阈值 | 新周期开始，或调高上限后不再达到 |
| 用量达到上限（`usage_limit`） | 本周期某项用量达到上限；带宽为本周期出现过超出 | 同上 |

每个指标（`resourceId` 为 `bytes`、`requests` 或 `bandwidth`）每个周期每级最多告警一次，通知写明指标，如「用量达到上限：发送流量」。网站停用后告警仍然有效。在 **告警 → 告警订阅** 勾选这两个种类，或使用接收所有告警的渠道，见[DNS 调度与告警](dns-and-alerts.md#订阅告警)。

## 延迟与超出

节点每分钟上报一次统计，控制台每分钟检查一次，所以从请求到告警发出、动作在节点生效通常要 1–3 分钟（其中配置发布到达节点只需几秒，开启金丝雀时更久）。这段时间内的流量照常放行：实际用量会略高于上限，流量越大超出越多。上限应留出余量；需要立即限制请求时，配合按 IP 或键的[限速规则](rules.md)或 [CC 防护](challenges.md#cc-防护)。

节点离线期间的统计在它恢复后补报，计入当时的周期：一个周期内的用量可能在之后变大，并因此触发告警或动作。

## 接口

| 操作 | 接口 |
| --- | --- |
| 读取设置、本周期用量与状态 | `GET /api/v1/sites/{id}/usage-guard` |
| 保存 | `PUT /api/v1/sites/{id}/usage-guard` |
| 删除 | `DELETE /api/v1/sites/{id}/usage-guard` |
| 恢复 | `POST /api/v1/sites/{id}/usage-guard/restore` |

字段与错误码见 [API 参考](../reference/api.md#用量保护)。只读 AccessKey 只能读取；服务账号不能调用这些接口。复制设置与克隆不包括用量保护。

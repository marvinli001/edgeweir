# 用量保护

为网站设置发送流量、请求数与带宽上限：达到预警阈值和上限时告警，到达上限时可自动开启维护模式或停用网站。

## 概念

| 术语 | 定义 |
| --- | --- |
| 周期 | 所选时区的自然日或自然月，从当地 0 点开始。夏令时切换的那天按 23 或 25 小时计。 |
| 发送流量 | 本周期内节点发给访客的字节数（含响应头），所有节点相加；与 `usage.list` 的 `bytesSent` 相同。 |
| 请求数 | 本周期内节点处理的请求数，所有节点相加。 |
| 带宽 | 网站所有节点在最近 5 个完整分钟（不含正在统计与刚结束的这一分钟）内发送字节的平均速率，单位为十进制（1 Mbps = 10⁶ bit/s），每分钟重新计算。 |
| 带宽峰值 | 本周期内出现过的最高带宽；带宽的预警与上限按峰值判断。 |
| 预警阈值 | 上限的百分比（1–99，默认 80），达到时发送「用量接近上限」告警；可以关闭。 |
| 动作 | 达到上限时：「仅告警」「开启维护模式」「停用网站」。 |
| 恢复方式 | 「自动恢复」或「手动恢复」，见[恢复](#恢复)。 |
| 检查 | 控制台的后台任务每分钟在用量汇总之后对每个设置了用量保护的网站检查一次。 |

## 设置

页面：**网站** → 选择网站 →「概览」页签（`/sites/<网站 ID>`）→「用量保护」卡片。

1. 未设置时卡片显示「未设置用量保护」，点击「设置」；已设置时点击卡片标题右侧的编辑按钮（「编辑」）。
2. 在对话框中选择「周期」与「时区」，至少填写一个上限，设置「预警」「达到上限时」与「恢复方式」。
3. 点击「保存」，提示「已保存用量保护」。设置在下一次检查（1 分钟内）生效，不发布配置版本。

| 字段 | 取值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 周期 | 「每天」「每月」 | 「每月」 | |
| 时区 | IANA 时区名（`UTC` 与浏览器支持的全部时区），最长 64 字符 | 浏览器所在时区 | 周期从该时区的 0 点开始 |
| 发送流量（GB） | 大于 0 的数，可带小数；1 GB = 10⁹ 字节，换算后至少 1 字节 | 空（「不限」） | API 为字节数的十进制字符串（`bytesLimit`，最多 38 位） |
| 请求数 | 正整数，最多 38 位 | 空（「不限」） | API 为十进制字符串（`requestsLimit`） |
| 带宽（Mbps） | 0.001–10000000 | 空（「不限」） | API 为 bit/s 整数（`bandwidthBps`，1000–10¹³） |
| 预警 | 开 / 关 | 开 | 关闭时不发送「用量接近上限」（`warnPercent: null`） |
| 预警阈值（%） | 1–99 的整数 | 80 | 关闭「预警」时不可编辑 |
| 达到上限时 | 「仅告警」「开启维护模式」「停用网站」 | 「开启维护模式」 | 见[达到上限时](#达到上限时) |
| 恢复方式 | 「自动恢复」「手动恢复」 | 「自动恢复」 | 「仅告警」时不可选 |
| 带宽超限后保持（分钟） | 5–1440 的整数 | 30 | 只在动作不是「仅告警」、恢复方式为「自动恢复」且填写了带宽上限时显示 |

三个上限都为空时显示「至少设置一个上限」，「保存」不可用。修改写审计 `site.usage_guard_update`（「修改用量保护」，记录修改前后的设置）。

### 卡片

| 内容 | 说明 |
| --- | --- |
| 指标行 | 每个设置了上限的指标一行：「发送流量」「请求数」「带宽」的「{used} / {limit}」与百分比，下方为进度条；带宽行显示当前带宽，另起一行显示「本周期峰值 {value}」 |
| 进度条颜色 | 达到预警阈值时为警示色，达到上限时为错误色；关闭预警时只在达到上限时变色 |
| 周期 | 「本日至 {end}」或「本月至 {end}」，后接动作名称 |
| 执行中的动作 | 红色提示「{metric}达到上限，已开启维护模式」或「{metric}达到上限，网站已停用」，带「恢复」按钮 |
| 手动恢复后 | 「已手动恢复，{time} 前不再执行动作」 |
| 发布失败 | 「动作未能发布，每分钟重试」 |
| 刷新 | 卡片每分钟重新读取 |
| 删除 | 卡片标题右侧的「删除」，确认「删除用量保护？」（「正在执行的动作会一并解除」），提示「已删除用量保护」 |

用量保护执行动作期间，网站列表的状态列与「概览」页签的状态旁显示「用量超限」标记。

## 达到上限时

| 动作 | 效果 |
| --- | --- |
| 仅告警 | 只发送告警。 |
| 开启维护模式 | 只打开网站维护模式的「启用」，沿用已保存的维护页、Retry-After、放行地址与放行路径前缀（见[维护模式](error-pages.md#维护模式)）：访客收到 503 维护页，放行的地址与路径照常访问。网站仍在节点配置中，DNS 不变。 |
| 停用网站 | 与在概览中停用网站相同：节点对网站的域名返回停用页（503 `site-disabled`，见[平台错误页](error-pages.md#平台错误页)），DNS 记录保留。 |

| 项目 | 行为 |
| --- | --- |
| 判断 | 发送流量、请求数在本周期累计达到上限时执行；带宽在超出期间执行，自动恢复时在最后一次超出后保持「带宽超限后保持」的时间，手动恢复时保持到周期结束。多个指标同时达到时按发送流量、请求数、带宽的顺序记录第一个 |
| 发布 | 动作发布网站所在集群的新配置版本，原因「网站 {site} 达到用量上限」 |
| 审计 | `site.usage_guard_apply`（「用量保护执行动作」），操作者为系统，元数据含 `metric`、`period`、`usage`、`limits`、`action`、`revision` |
| 已处于该状态 | 网站已开启维护模式或已停用（由你操作）时不执行，恢复时也不改动它；网站已停用时不开启维护模式 |
| 金丝雀发布 | 集群开启了金丝雀发布时，动作与其他配置一样先发到金丝雀节点，按发布策略推进 |
| 发布失败 | 例如节点不支持维护模式需要的能力 `site-content-v1`：告警照常发送，卡片显示「动作未能发布，每分钟重试」，接口的 `lastError` 为错误码（如 `NODE_CAPABILITY_REQUIRED`），下一次检查重试 |

## 恢复

| 情况 | 自动恢复 | 手动恢复 |
| --- | --- | --- |
| 新周期开始 | 解除 | 保持 |
| 调高或删除上限后不再超出 | 解除 | 保持 |
| 带宽回落 | 最后一次超出后保持「带宽超限后保持」的时间，之后解除；再次超出再次执行 | 保持到周期结束 |
| 点击卡片上的「恢复」并确认（「恢复网站 {name}？」，「{time} 前不再执行动作，告警照常」） | 解除，本周期结束前不再执行动作 | 同左 |
| 你在概览启用网站、关闭维护模式或批量启用网站 | 同「恢复」 | 同左 |
| 修改「达到上限时」（如改为「仅告警」） | 先解除原动作，需要时执行新动作 | 同左 |
| 删除用量保护 | 解除 | 解除 |

| 项目 | 行为 |
| --- | --- |
| 范围 | 只解除用量保护自己执行的动作 |
| 发布 | 解除发布新的配置版本，原因「解除网站 {site} 的用量保护动作」 |
| 审计 | 自动解除：`site.usage_guard_release`（「用量保护解除动作」，操作者为系统）；「恢复」：`site.usage_guard_restore`（「手动恢复用量保护的动作」，操作者为你）；删除：`site.usage_guard_release`（操作者为你）与 `site.usage_guard_delete`（「删除用量保护」） |
| 暂停 | 手动恢复后到周期结束前不执行动作，告警照常；再次保存设置取消暂停 |

## 告警

| 告警 | 触发 | 恢复 |
| --- | --- | --- |
| 用量接近上限（`usage_warning`） | 本周期某项用量达到预警阈值 | 新周期开始，或调高上限后不再达到 |
| 用量达到上限（`usage_limit`） | 本周期某项用量达到上限；带宽为本周期的峰值达到上限 | 同上 |

每个指标（`resourceId` 为 `bytes`、`requests` 或 `bandwidth`）每个周期每级最多告警一次，通知写明指标，如「用量达到上限：发送流量」。网站停用后告警仍然有效。在 **告警** 页「告警订阅」卡片的订阅中打开这两个种类，或使用接收所有告警的渠道，见[告警](alerts.md#订阅告警)。

## 延迟与超出

| 项目 | 行为 |
| --- | --- |
| 延迟 | 节点每分钟上报统计，控制台每分钟检查；从请求到告警发出、动作在节点生效通常 1–3 分钟，其中配置发布到达节点为数秒，开启金丝雀时更久 |
| 超出 | 延迟期间的流量照常放行，实际用量高于上限，超出量随流量增加；上限需留出余量。需要立即限制请求时配合按 IP 或键的[限速规则](rules.md)或 [CC 防护](challenges.md#cc-防护) |
| 补报 | 节点离线期间的统计在恢复后补报，计入所属周期；周期用量可能在之后增加并触发告警或动作 |

| 数据来源 | 说明 |
| --- | --- |
| 发送流量、请求数 | 已汇总的 5 分钟用量窗口（与 `usage.list` 相同），加上尚未汇总或等待重算的分钟统计 |
| 带宽 | 分钟统计 |
| 用量记录保留 | **系统设置** →「通用」页签 →「用量」卡片的「保留天数」（35–400，默认 100），见[系统设置](system.md#用量)；最小值覆盖一个自然月 |

## 接口

| 操作 | 过程 | 方法与路径（`/api/v1`） |
| --- | --- | --- |
| 读取设置、本周期用量与状态 | `usageGuard.get` | `GET /sites/{id}/usage-guard` |
| 新建或替换设置 | `usageGuard.update` | `PUT /sites/{id}/usage-guard` |
| 删除 | `usageGuard.delete` | `DELETE /sites/{id}/usage-guard` |
| 恢复 | `usageGuard.restore` | `POST /sites/{id}/usage-guard/restore` |

| 请求 / 响应 | 字段 |
| --- | --- |
| `PUT` 请求 | `period`（`day` / `month`，默认 `month`）、`timeZone`（必填）、`bytesLimit`、`requestsLimit`（十进制字符串或 `null`）、`bandwidthBps`（整数或 `null`）、`warnPercent`（1–99 或 `null`，默认 80）、`action`（`alert` / `maintenance` / `disable`，默认 `maintenance`）、`recovery`（`auto` / `manual`，默认 `auto`）、`bandwidthHoldMinutes`（5–1440，默认 30）、可选 `expectedUpdatedAt` |
| 响应 | `settings`（未设置时为 `null`）、`updatedAt`、`period { start, end }`、`usage { bytes, requests, bandwidthBps, bandwidthPeakBps }`、`held { action, metric, since }`、`pausedUntil`、`lastError` |

只读 AccessKey 只能调用 `GET`；服务账号不能调用这些接口（403 `SERVICE_ACCOUNT_FORBIDDEN`）。复制设置与克隆不包括用量保护。字段说明见 [API 参考](../reference/api/sites.md#用量保护)。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「保存」不可用，提示「至少设置一个上限」 | 三个上限都为空 | 至少填写一个上限 |
| 输入框标红，「保存」不可用 | 发送流量不是正数、请求数不是正整数、带宽不在 0.001–10000000、预警阈值不在 1–99 或保持时间不在 5–1440 | 修正取值 |
| 「输入有误」（`BAD_REQUEST`，400） | API 请求三个上限都为 `null`、时区未知或字段超出范围 | 按[接口](#接口)修正请求 |
| 「内容已被修改，请刷新后重试」（`UPDATED_AT_MISMATCH`，409） | 读取之后设置被其他会话修改 | 刷新后重新编辑 |
| 「用量保护没有正在执行的动作」（`USAGE_GUARD_NOT_HELD`，409） | 调用「恢复」时没有正在执行的动作 | 无需恢复 |
| 卡片显示「动作未能发布，每分钟重试」 | 发布失败，`lastError` 记录错误码，例如 `NODE_CAPABILITY_REQUIRED`（集群有活动节点缺少维护模式需要的 `site-content-v1`） | 升级节点，见[节点升级](node-upgrades.md)；或把动作改为「停用网站」 |
| 达到上限但没有执行动作 | 动作为「仅告警」；本周期已手动恢复（卡片显示「已手动恢复，…」）；网站已停用或已开启维护模式 | 检查设置与卡片提示 |
| 用量超过上限较多 | 统计与检查有 1–3 分钟延迟，期间流量照常放行 | 调低上限留出余量，配合限速规则 |
| 带宽回落后网站仍在维护 | 自动恢复的保持时间未到，或恢复方式为手动 | 等待保持时间，或点击「恢复」 |
| 没有收到告警通知 | 告警订阅未打开 `usage_warning` / `usage_limit` | 在 **告警** 页「告警订阅」卡片的订阅中打开这两个种类 |

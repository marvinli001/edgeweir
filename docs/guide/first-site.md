# 快速上手

5 分钟跑通首个站点：从初始化控制台、接入首台边缘节点，到完成域名解析与 HTTPS 流量命中。

## 部署流程全景

搭建完整的边缘加速服务通常只需以下 6 步：

1. **完成初始化向导**：生成平台管理员账号与默认组织。
2. **接入首台边缘节点**：在节点服务器执行一行注册脚本，通过 mTLS 建立可信连接。
3. **添加网站与源站**：配置你的加速域名、源站回源策略与基础缓存规则。
4. **配置 DNS 解析**：将域名权威解析指向边缘节点公网 IP 或 CNAME 调度域。
5. **申请并绑定证书**：一键签发 ACME 免费证书，开启全站 HTTPS。
6. **回源与缓存验收**：通过 curl 验证请求是否正确命中边缘节点缓存。

## 前提

| 项目 | 要求 |
| --- | --- |
| 控制台 | 已部署，浏览器可访问 `EDGEWEIR_PUBLIC_URL`，见 [部署概览](../deploy/README.md) |
| 节点主机 | Linux（systemd），amd64 / arm64；可访问 `EDGEWEIR_PUBLIC_URL` 与节点通道（默认 TCP 8443）；有 sudo 权限的账户 |
| 节点入站端口 | TCP 80；启用 HTTPS 后另需 TCP 443 |
| 域名 | 可修改其权威 DNS 记录 |
| 源站 | 节点可访问；地址不在特殊用途地址段（内网、回环等），或已加入 [源站地址允许清单](admin.md#源站地址允许清单) |

## 1. 完成初始化向导

1. 从控制台日志读取 setup token。Docker Compose 部署：

   ```bash title="控制台主机"
   docker compose logs console | grep setupToken
   ```

   日志行为 JSON，`setupToken` 字段为 token（`ews_` 开头），`url` 字段为初始化页地址。未初始化的控制台每次启动打印同一个 token。其他部署方式的日志位置见 [Docker Compose](../deploy/docker.md) 与 [宝塔面板 / aaPanel](../deploy/baota.md)。

2. 浏览器打开 `EDGEWEIR_PUBLIC_URL`。未初始化的控制台跳转到 `/setup`（**创建管理员**）。

3. 填写表单，点击 **完成**。

   | 字段 | 说明 |
   | --- | --- |
   | **Setup token** | 第 1 步读取的 token |
   | **姓名** | 平台管理员姓名，最多 100 字符 |
   | **邮箱** | 登录邮箱 |
   | **密码** | 12–128 字符 |
   | **组织名称** | 第一个组织的名称，默认 `Default` |

4. 验证：控制台自动登录并进入 **概览**；**后台 → 系统设置 → 系统信息** 的 **Setup token** 显示 **已于 {时间} 使用**。

初始化创建的对象：

| 对象 | 值 |
| --- | --- |
| 平台管理员 | 表单中的账户；同时为第一个组织的所有者 |
| 组织 | 表单中的组织名称；标识由名称生成 |
| 集群 | `default`，含默认节点组 `default`，发布配置版本 #1 |
| setup token | 作废；此后 `/setup` 跳转到登录页 |

## 2. 接入节点

1. 打开 **后台 → 集群与节点**，选择集群 `default`，点击 **添加节点**。

2. 填写表单，点击 **生成安装命令**。

   | 字段 | 说明 |
   | --- | --- |
   | **节点名称** | 可选，最多 64 字符 |
   | **节点组** | 默认为集群的默认节点组 |
   | **有效期** | 15 分钟、1 小时（默认）或 24 小时 |

3. 复制 **安装命令**（仅显示一次），在节点主机上执行。命令格式：

   ```bash title="节点主机"
   export EDGEWEIR_TOKEN='ewt_…'
   curl -fsSL https://console.example.com/install.sh | sudo --preserve-env=EDGEWEIR_TOKEN bash -s -- --server https://console.example.com:8443 --ca-sha256 <CA 指纹>
   ```

4. 验证：**后台 → 集群与节点** 的节点表出现该节点，**状态** 为 **在线**，**已应用版本** 旁显示 **已同步**。

token 单次有效。安装脚本的校验步骤、下载镜像与失败处理见 [接入节点](../deploy/nodes.md)。

## 3. 新建网站

1. 打开 **网站**，点击 **新建网站**。

2. 填写表单。

   | 字段 | 默认值 | 说明 |
   | --- | --- | --- |
   | **名称** | 无 | 最多 100 字符 |
   | **域名** | 无 | 每行一个或以逗号分隔；泛域名写作 `*.example.com`；1–50 个 |
   | **源站地址** | 无 | IP 或主机名 |
   | **端口** | 80（HTTP）/ 443（HTTPS） | 源站端口 |
   | **回源协议** | HTTP | HTTP 或 HTTPS |
   | **回源 Host** | 跟随请求 | 发往源站的 `Host` |
   | **缓存** | 开启 | 开启时生成一条缓存规则：**路径前缀** `/`，**缓存时间（秒）** 3600，**遵循源站 Cache-Control** 关闭 |

3. 点击 **创建**。提示 **已创建，版本 #N**，网站所在集群发布新的配置版本，页面进入网站详情。

| 规则 | 说明 |
| --- | --- |
| 所在集群 | 组织的默认集群；未设置时为最早创建的集群 |
| 域名归属 | 平台管理员创建的网站，域名状态为 **管理员已确认**。组织成员创建的网站须在 **域名** 页完成 TXT 校验；未验证的域名不发布到节点，见 [验证域名归属](dns-and-alerts.md#验证域名归属) |
| 源站地址 | 特殊用途地址段内的源站被拒绝，平台管理员放行的地址段除外 |

源站池、缓存规则与缓存键见 [源站与缓存](origins-and-cache.md)。

## 4. 配置 DNS

在域名的权威 DNS 中为每个网站域名添加记录。

| 平台 DNS | 记录 |
| --- | --- |
| 未配置 | `A` / `AAAA` 记录指向节点的公网地址。**后台 → 集群与节点** 节点表的 **IP** 列列出节点上报的地址。多个节点各添加一条 |
| 已配置（**后台 → 平台 DNS**） | `CNAME` 记录指向网站 **域名** 页 **CNAME 目标** 卡片中的地址（`<网站 ID>.<集群域名>`）。卡片状态为 **已发布** 时记录已写入服务商 |

平台 DNS 的线路、健康摘除与 TTL 见 [配置平台 DNS](dns-and-alerts.md#配置平台-dns)。

## 5. 启用 HTTPS

1. 打开 **证书**，点击 **申请证书**（ACME）或 **上传证书**。HTTP-01 验证要求第 4 步的记录已生效。
2. 打开网站的 **HTTPS** 页签，在 **证书** 中选择该证书，按需开启 **强制 HTTPS**，点击 **保存**。
3. 集群发布新版本。集群内有网站引用证书时，节点监听 TCP 443。

签发方式、续期、TLS 与 HTTP/3 见 [HTTPS 与证书](https.md)。

## 6. 验证

1. 确认配置已应用：**后台 → 集群与节点** 中节点的 **已应用版本** 等于集群的 **最新版本**，并显示 **已同步**。

2. 绕过 DNS，直接向节点发送 HTTP 请求（`203.0.113.10` 替换为节点地址）：

   ```bash
   curl -sI --resolve www.example.com:80:203.0.113.10 http://www.example.com/
   ```

   预期：状态码与源站一致；响应带 `X-Cache` 头，缓存规则覆盖的路径首次为 `MISS`。

3. 重复第 2 步。源站响应可缓存时返回 `X-Cache: HIT`。

4. 启用 HTTPS 后：

   ```bash
   curl -sI --resolve www.example.com:443:203.0.113.10 https://www.example.com/
   ```

   HTTPS 请求用 `--resolve`，不用 `-H 'Host: …'`：节点要求 SNI 与 `Host` 一致。

5. DNS 生效后：

   ```bash
   dig +short www.example.com
   curl -sI http://www.example.com/
   ```

   预期：`dig` 返回节点地址（经平台 DNS 时先返回 CNAME 目标）；`curl` 结果与第 2 步相同。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 初始化提示 **Setup token 无效** | token 错误或已使用 | 从日志重新读取；初始化完成后使用登录页 |
| 初始化提示 **初始化正在进行，请稍后重试** | 另一个初始化请求正在执行 | 稍后重试 |
| 节点未出现或 **离线** | 注册失败，或节点无法访问节点通道 | 见 [接入节点](../deploy/nodes.md) 与 [端口、反向代理与可信代理](../deploy/networking.md) |
| **已应用版本** 显示 **应用失败** | 节点校验或应用配置失败 | 鼠标悬停该标记查看原因 |
| **已应用版本** 显示 **需要升级** | 节点缺少配置所需能力 | 升级节点，见 [节点升级](node-upgrades.md) |
| 404，`X-Edgeweir-Error: unknown-host` | 节点配置中没有该域名：版本未应用，或域名未通过归属验证 | 检查 **已应用版本** 与 **域名** 页的归属状态 |
| 421，`X-Edgeweir-Error: sni-host-mismatch` | HTTPS 请求的 SNI 与 `Host` 不一致 | 使用 `--resolve` |
| 502，`X-Edgeweir-Error: no-origin` | 没有可用源站 | 检查源站地址、端口、协议与健康状态，见 [源站与缓存](origins-and-cache.md) |
| 508，`X-Edgeweir-Error: loop-detected` | 源站指回节点 | 源站地址改为真实源站 |
| 新建网站提示 **源站地址 … 属于特殊用途地址段 …，平台未放行** | 源站为内网、回环等地址 | 平台管理员将地址段加入 [源站地址允许清单](admin.md#源站地址允许清单) |
| 新建网站提示 **域名已被使用：…** | 域名已属于其他网站或其他组织 | 更换域名，或先从原网站移除 |

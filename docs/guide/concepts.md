# 核心概念

控制面的对象定义、对象之间的从属关系、配置下发流程与访问身份。

## 对象

| 概念 | 定义 | 详见 |
| --- | --- | --- |
| 网站 | 一组域名，以及它们共用的源站、缓存、HTTPS、规则与防护设置。属于一个集群，创建后不能更换集群 | [新建网站](first-site.md#3-新建网站)、[网站管理](site-management.md) |
| 域名 | 网站匹配的请求 Host，写法为精确、泛（`*.a.com`）、后缀（`.a.com`）或正则（`~`）。同一写法的域名只属于一个网站 | [域名](domains.md) |
| 源站 | 网站回源的地址、端口与协议（HTTP、HTTPS 或 S3 兼容对象存储） | [源站与缓存](origins-and-cache.md#配置源站) |
| 源站池 | 一个网站的全部源站，以及负载均衡、健康检查、超时与长连接设置；每个网站一个 | [源站池设置](origins-and-cache.md#源站池设置) |
| 源站组 | 源站上的分组标签，空为默认组；规则可把请求发往其他组 | [源站组](origins-and-cache.md#源站组) |
| L4 应用 | 在集群每个节点的一个端口上把 TCP 连接或 UDP 会话转发给源站 | [L4 转发](l4.md) |
| 证书 | 上传或经 ACME 申请的 TLS 证书，由网站的 HTTPS 设置引用 | [HTTPS 与证书](https.md) |
| 集群 | 一组节点，以及分配给这些节点的网站与 L4 应用。监听端口、配置版本序列、DNS 绑定与调度规则按集群独立 | [集群](clusters.md#集群) |
| 节点组 | 集群内节点的分组，可带一个区域。DNS 线路、备用节点组、配置金丝雀与节点升级以节点组为单位；每个集群有一个默认节点组 `default` | [节点组](clusters.md#节点组) |
| 节点 | 运行 edgeweir-node（agent 与 OpenResty）的主机，以一次性安装命令注册，之后以客户端证书经 mTLS 连接节点通道。45 秒内有心跳为在线 | [节点](clusters.md#节点)、[接入节点](../deploy/nodes.md) |
| 区域 | 全平台共用的地域标签（名称与代码），由节点组与区域探针引用 | [区域](clusters.md#区域) |
| 区域探针 | 在某个区域运行的探测进程，从该区域探测各节点的调度地址；也可由节点兼任 | [区域探针](scheduling.md#区域探针) |
| 配置版本 | 一个集群的完整节点配置（NodeConfig），带集群内递增的版本号（revision）与内容哈希。改变节点配置的变更在同一事务内发布新版本；内容与上一版相同时不发布 | [配置版本](clusters.md#配置版本) |
| 快照与差量 | 节点以已应用的版本号请求配置，节点通道返回完整快照或相对该版本的差量。节点校验哈希后保存为 last-known-good 再应用 | [配置下发](#配置下发) |
| 配置金丝雀 | 按集群开启的发布策略：新版本先下发到金丝雀节点组，观察窗口通过后推进到全部节点，否则回滚 | [配置金丝雀](clusters.md#配置金丝雀) |
| 节点任务 | 刷新（URL、目录、Host、Cache-Tag、整站）与预热（URL、站点地图）：不产生配置版本，以任务下发到集群的已启用节点 | [源站与缓存](origins-and-cache.md) |
| DNS 绑定 | 一个集群的 DNS 调度设置：模式、服务商账号、集群域名、TTL 与线路 | [DNS 调度](dns.md) |
| DNS 版本 | 一个集群的 DNS 绑定及其记录的快照，独立于配置版本 | [DNS 版本与回滚](dns.md#dns-版本与回滚) |
| 调度规则 | 按节点指标或探测结果改变集群 DNS 记录的规则 | [智能调度规则](scheduling.md#智能调度规则) |
| 账户 | 控制台唯一的运营者账户，由初始化向导创建 | [账户与登录](account.md) |
| AccessKey | 以账户身份调用 `/api/v1` 的密钥，`ewk_` 开头；权限范围为只读或读写 | [个人设置](account.md#个人设置) |
| 服务账号 | 供集成调用 `/api/v1` 的独立身份，不能登录控制台；key 以 `ews_` 开头，只能调用其 scope 允许的过程 | [服务账号](system.md#服务账号) |
| 审计日志 | 管理操作的记录：操作者、操作、对象、来源与元数据；控制台自身的变更与审计条目在同一事务中提交 | [审计日志](system.md#审计日志) |

## 关系

| 对象 | 属于 | 数量与约束 |
| --- | --- | --- |
| 节点组 | 集群 | 每个集群至少一个（默认节点组），名称在集群内唯一 |
| 节点 | 节点组 | 一个节点属于一个节点组；只能在同一集群的节点组之间移动 |
| 节点组 → 区域 | 区域 | 0 或 1 个区域；删除区域时节点组的区域置空 |
| 区域探针 | 区域 | 1 个区域；区域下有探针时不能删除区域 |
| 网站 | 集群 | 每个集群最多发布 512 个已启用的网站 |
| L4 应用 | 集群 | 每个集群最多 256 个；端口取自集群的端口池 |
| 域名 | 网站 | 每个网站零个或多个 |
| 源站池 | 网站 | 每个网站一个 |
| 源站 | 源站池 | 每个源站可带一个源站组标签 |
| 证书 | 平台 | 一张证书可被多个网站引用；被引用的证书不能删除 |
| 配置版本 | 集群 | 每个集群保留最近 200 个 |
| DNS 绑定 | 集群 | 每个集群一条；模式为「不管理」时不写入 DNS |
| DNS 版本 | 集群 | 每个集群保留最近 200 个 |
| 调度规则 | 集群 | 作用于集群 DNS 绑定的全部线路或其中一条 |
| AccessKey | 账户 | 只能在已登录的控制台中创建 |
| 服务账号 key | 服务账号 | 每个服务账号零个或多个；删除服务账号时全部失效 |

## 配置下发

1. 控制台在一个事务中写入业务表，编译集群的 NodeConfig，计算内容哈希；与上一版不同时写入新的配置版本并通知各控制台实例。
2. 控制台经 `WatchConfig` 流通知该集群的节点。
3. 节点调用 `GetConfig` 并带上已应用的版本号，取得快照或差量，校验哈希，保存为 last-known-good，应用到 OpenResty。
4. 节点以 `ReportStatus` 回报已应用的版本与心跳；控制台据此显示 **已应用版本**、网站的生效状态与 DNS 的地址集合。

| 项目 | 行为 |
| --- | --- |
| 目标版本 | 没有金丝雀时为集群最新版本；金丝雀进行中时金丝雀节点为候选版本，其他节点为稳定版本 |
| 节点能力 | 配置需要节点尚不支持的能力时，缺少能力的节点显示 **需要升级** 并继续使用原配置，见 [配置版本](clusters.md#配置版本) |
| 断开控制台 | 节点按最后一次成功应用的配置继续服务 |
| 回滚 | 以所选版本的内容发布一个新版本，不删除历史，见 [配置版本](clusters.md#配置版本) |

节点通道的协议与认证见 [架构](../../ARCHITECTURE.md)。

## 访问身份

| 身份 | 凭据 | 入口 | 权限 |
| --- | --- | --- | --- |
| 账户（会话） | 会话 cookie 与 CSRF 头 | Web 界面、`/rpc` | 全部操作 |
| AccessKey | `x-api-key: ewk_…` | `/api/v1` | 读写：与会话相同，但不能创建或修改密钥；只读：GET 过程与 `rules.validate` |
| 服务账号 | `x-api-key: ews_…` | `/api/v1` | 服务账号过程中 scope 允许的部分 |
| 节点 | 安装令牌 `ewt_…`（单次），之后为客户端证书 | 节点通道（默认 `:8443`） | 节点 RPC |
| 区域探针 | 注册令牌 `ewp_…`（单次），之后为客户端证书 | 节点通道 | 仅探针 RPC |

令牌只以 SHA-256 保存。审计日志的操作者类型为 **用户**、**AccessKey**、**服务账号**、**节点**、**探针** 与 **系统**。端点与请求格式见 [API 与端点](../reference/api.md)。

# 节点签名升级

在后台「集群与节点」选择目标版本和先升级的节点组。控制台读取发布清单，为当前集群的启用节点建立任务快照；目标节点必须全部在线、配置同步、数据面健康，并宣告 `self-upgrade-v1` 能力。目标版本不带 `v` 前缀，例如 `0.1.0`。

第一组执行成功后，控制台观察至少 30 秒的健康回执。回执中版本、配置 revision 和内容哈希都必须匹配；负面回执或过长的心跳间隔重新开始观察。管理员再点击「推进剩余节点」，其余节点才收到任务。界面显示每个节点的等待、运行、成功、拒绝或回滚结果。

升级会重启 agent 和 OpenResty，不承诺无中断。应选能由其他节点承接流量的试运行组。取消操作只取消尚未执行的任务；已完成的节点保留当前版本。运行中的任务需等待成功或回滚。30 分钟内未完成的任务会过期。

## 节点侧验证

节点只接受本机配置的发布目录。默认目录是本项目 GitHub Releases；控制台传来的地址必须精确匹配目标版本、当前 Linux 架构和预期文件名。

1. 下载 `checksums.txt`、Sigstore bundle 和归档，均有大小及超时上限。
2. 用 cosign 验证清单，默认固定 `marvinli001/edgeweir-node` 的 `release.yml`、目标 `v<version>` tag 和 GitHub Actions OIDC issuer。
3. 检查任务 SHA-256 与已签名清单相同，再校验归档 SHA-256。
4. 拒绝路径穿越、链接、特殊文件、重复条目及超大归档，检查可执行文件报告的版本。
5. 把二进制和 Lua 放进同一个私有版本目录，持久化状态后切换。

控制台不能下发 shell 命令、改用另一把公钥或绕过签名。明文 HTTP 的本地测试镜像也仍须验签。

## 监督进程与恢复

新镜像及 systemd 单元使用 `edgeweir-node supervise --manage-nginx`。监督进程持有独占状态锁，避免第二个进程把正在运行的试验误判为中断。私有 Unix socket 权限为 0600；候选程序必须完成 mTLS 通信、应用期望配置并提供持续的健康回执，才会确认成功。90 秒内无法完成启动验证，或试运行期间进程退出、监督进程重启，都会恢复前一程序、Lua 和配置快照。

升级结果在收到控制台确认前保留在磁盘。确认写入失败不会丢弃结果；下载、验签或持久化失败不被报告为成功。身份密钥、证书、凭据和统计游标不会随代码回滚而倒退。节点只保留当前、前一及正在准备的版本目录，避免历史归档无限占用磁盘。

自升级更新的是运行中的 agent 和 Lua。固定的监督进程、cosign 和 OpenResty 由镜像或 deb/rpm 的维护流程更新；程序与 Lua 的基础安装指纹变化时优先采用新安装，不会被状态卷中的旧自升级版本遮蔽；涉及这些组件的安全修复应更新完整镜像或系统包。控制台显示的是活动 agent 版本；直接运行系统路径中的 `edgeweir-node version` 显示的是该固定二进制的版本。

已有节点需要先安装支持监督模式的镜像/软件包。没有监督进程或 cosign 的节点不会宣告升级能力；以 `--allow-unsigned` 进行的开发安装不自动获得远程升级能力。

## 私有镜像与自有发行

控制台的 `EDGEWEIR_NODE_RELEASE_BASE_URL` 和节点本机的 `EDGEWEIR_UPGRADE_SOURCE` 应指向同一个按 `v<version>/` 分目录的发布源。镜像应直接提供文件；除官方 GitHub 下载跳转外，节点拒绝跨来源重定向。

自有发行可以在节点配置 `EDGEWEIR_UPGRADE_PUBLIC_KEY`，指向由运维部署的本机公钥。此模式验证固定公钥签名，不使用公共透明日志；只更改控制台数据库无法切换节点信任的公钥。`EDGEWEIR_UPGRADE_ALLOW_HTTP=true` 仅用于明确选择的本地测试或隔离镜像，默认关闭。签名生成与验证方法见 [Sigstore 文档](https://docs.sigstore.dev/cosign/signing/signing_with_blobs/)。

仓库尚未发布正式二进制版本。当前验收使用本地生成的临时发行密钥：真实 cosign 验签、两台 Linux 节点从 A 升级到 B、错误密钥签名拒绝、已签名坏程序启动失败后回滚，以及浏览器发起和推进。正式 GitHub OIDC 发布物仍需在发布后独立验证。

复现入口：`scripts/e2e-upgrade-fixtures.mjs`、`scripts/e2e-m6-upgrades.mjs`、`apps/console/e2e/m6-upgrades.spec.ts`；监督进程的崩溃恢复、确认持久化失败、重复进程和归档边界有 Go race 测试。

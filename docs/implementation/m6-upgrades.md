# M6 节点升级实施记录

状态：实施中，尚未完成验收。日志、AccessKey、ClickHouse、恢复和性能基线已单独验证；本文件不代表升级功能已经可用。

## 边界

- 管理员选择版本与一个节点组先试运行；仅在该组全部成功、心跳新鲜、数据面健康、版本与配置回执符合要求后，才可明确推进到本集群剩余节点。
- 使用类型化 UpgradeTask，不添加 SSH 或任意命令执行接口。任务只包含版本、固定发布目录中的归档/校验和/签名地址和 SHA-256。
- 节点信任锚由本机运维配置：默认固定本仓库 release.yml 的 GitHub OIDC 签名身份；私有发行可配置本机公钥。控制台不能传入新的公钥或替换签名身份。默认只允许固定 HTTPS 发布地址；测试/镜像地址由本机配置。
- 复用发布流程已经签名的 checksums.txt 和 checksums.txt.sigstore.json，验签之后再验证归档哈希和目标文件名。拒绝目录穿越、符号链接、超大归档、错误架构或版本。二进制与 Lua 作为同一版本目录安装。

## 状态与回滚

系统目录保持只读。稳定的 `supervise` 进程启动当前 agent；升级目录、事务日志和结果位于私有 StateDir。agent 通过本机 0600 Unix socket 提交任务。候选包验证完成后持久化 pending 状态，再停旧子进程、保存 LKG 配置副本、启动新版本。

新版本需要成功与控制台通信、应用配置并报告数据面健康，经过观察窗口后监督进程才提交 active 状态与成功结果。候选进程退出、健康超时或监督进程在试运行阶段重启，都会恢复前一版本和 LKG 配置。升级结果持久化到收到控制台确认，不依赖原进程的内存。

控制台维护独立升级任务和逐节点结果，避免刷新任务的超时/重试逻辑误处理升级。未启用监督进程或缺少验签工具的节点不宣告升级能力。
